# Phase 284 修复总结：原版图片显示方向适配

日期：2026-08-23（Asia/Shanghai）  
状态：已完成静态适配与验证；设备样本与 crop 全矩阵仍开放。

## 目标

Phase 281 只规范化超过 3000px 的原图，小尺寸 EXIF 图片仍保留 encoded pixels。Phase 283 后这些图片可进入
生产渲染路径，因此补齐原版显示层的 orientation/mirror 行为，避免小图方向错误。

## 原版证据

- 插入路径 `vuh.java` 对超 3000px 图片显式旋转并重写 WebP。
- 显示路径 `g3.java` case 6 对 JPEG/WebP/HEIC/HEIF 读取 `w34` orientation：
  - orientation `2/4/5/7` 触发水平镜像；
  - `w34.l()` 提供 rotation degrees；
  - 变换以 bitmap 中点为中心；
  - 90/270 创建交换物理宽高的新 Bitmap。
完整记录见 ADR-0262 与 evidence 文件。

## Harmony 实现

- `OriginalImageNormalizer.ets` 导出既有 `originalRotationDegrees()`；
- `ImageAssetLoader.ets` 读取 `image.PropertyKey.ORIENTATION`（默认 `'1'`），校验 oriented dimensions，
  并在 `LoadedImageAsset` 增加 `orientationDegrees` 和 `mirroredHorizontally`；
- `ImageCanvasRenderer.imageRenderGeometry()` 只接受 `0/90/180/270`；90/270 使用交换后的 oriented 尺寸；
- renderer 在 oriented bitmap 中心执行 rotate，必要时水平镜像；
- `NoteCanvasView` 把 loader 的两项元数据传入 image rendering。

持久化 intrinsic dimensions、AssetHash、CREATE_BLOCK 和资产文件保持不变；该修复只作用于显示 decode/render
层，不重复改写已入库资产。
