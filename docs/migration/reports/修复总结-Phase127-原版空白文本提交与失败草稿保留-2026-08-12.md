# Phase 127 修复总结：原版空白文本提交与失败草稿保留

## 原版证据与问题

- 原版 `f46.a()` 只在字符串 `length() == 0` 时拒绝 INSERT_STRING；`s5j.i()` 对单个空白
  Unicode scalar 走单字符 INSERT，对多个空白原样交给 `kci.b()`，不存在 trim。
- 当前 `onTextCommit()` 使用 `text.trim().length === 0`，会把空格、换行、NBSP、全角空格等合法
  RichText 当成空编辑取消。新 Text 无法只输入空白，既有 Text 也无法改成空白内容。
- 边修边审发现覆盖层 Done 在异步提交 settle 前就清空自己的 `draftText`。CRDT 预览失败、切页竞态
  或持久化拒绝时，画布数据虽未被替换，用户眼前的草稿却可能消失。

## 已完成修复

- Text 提交门禁改为只判断 `text.length === 0`，所有非空字符串 byte-for-byte 进入既有原版
  CREATE/INSERT/REMOVE/REVIVE 路径；不再破坏有意义的空白字符。
- `TextBlockOverlay.onCommit` 改为 `Promise<boolean>`，Done 只有在返回 `true` 后才清空局部草稿。
- `NoteCanvasView` 返回真实异步提交结果；异常记录后返回 `false`。预览拒绝或生命周期竞态下，编辑器
  保持内容，用户仍可修改、重试或显式取消。
- 真正空字符串仍沿当前取消逻辑。本阶段没有证据证明既有空 Text 应删除 Block 或保留空容器，故不猜。
