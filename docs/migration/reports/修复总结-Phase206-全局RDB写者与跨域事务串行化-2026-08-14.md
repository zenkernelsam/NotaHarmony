# Phase 206 修复总结：全局 RDB 写者与跨域事务串行化

## 发现

Phase 205 统一了笔记/文件夹元数据写者，但继续沿调用链审计后确认，同一个 `DatabaseManager` 单例和同一个 `RdbStore` 仍被多把互不相识的锁写入：

1. 页面仓储、元素快照、持久历史和同步 inbox 使用 `editorPersistenceMutex`；笔记/文件夹使用 `libraryMetadataMutationMutex`；资产使用 `assetMutationMutex`；工具状态另有私有 `writeMutex`。
2. 这些锁保护的是业务域，不是 store。页面保存与文件夹移动、同步 reducer 与标题保存、资产到达与笔记删除仍可能从不同锁同时调用 `beginTransaction()`。
3. `saveViewState()`、单个工具状态和工具箱状态虽是单语句写入，也没有加入任何 store 级写者；它们可能在其他子系统持有事务时进入同一个 RdbStore。
4. 简单把所有领域锁指向同一对象会让现有 `asset -> editor`、`asset -> library` 嵌套自锁，因此必须保留资产领域锁，并只统一数据库写者。

边修边审还发现 `d02-recording-state.mjs` 把 `DB_VERSION` 硬编码为 61；Phase 193 已将数据库升到 62，这个 stale replay 会把无关版本升级误报为录音回归。

## 修复

- 新增 `DatabaseWriteMutex.ets`，建立单例 `RdbStore` 的进程内 FIFO 写者。
- `editorPersistenceMutex` 和 `libraryMetadataMutationMutex` 改为 `databaseWriteMutex` 的兼容别名；现有页面、Stroke、OpStore、同步 inbox、录音、笔记和文件夹事务无需复制第二套锁逻辑即可共享一个写队列。
- 保留 `assetMutationMutex`，锁序统一为 `assetMutationMutex -> databaseWriteMutex`。
- `AssetRepositoryImpl.saveAsset()`、`deleteAsset()` 在资产锁内取得数据库写者；删除事务返回提交时读取的本地路径，释放数据库写者后再清理文件。
- `ImageAssetPackageStore` 在资产锁内取得数据库写者，并把既有文件/数据库补偿事务提取为明确的 locked helper。
- `ToolRepositoryImpl` 删除私有写锁，批量事务和三个单语句写入口全部进入数据库写者。
- `NoteRepositoryImpl.saveViewState()` 进入数据库写者，避免视口 replace 与其他在途事务交叠。
- `DatabaseManager` 初始化保持例外：`initPromise` 串行且 store 在全部迁移完成前不发布。
- 新增 `d02-global-rdb-writer.mjs`，自动扫描所有含 `beginTransaction()` 的运行期 data 文件，并校验别名、资产锁序、工具/视口单语句写入及初始化发布边界。
- 更新 Phase 205 replay 以识别共享元数据锁升级为全局写者别名。
- 修复 `d02-recording-state.mjs` 的版本脆弱断言，改为验证当前版本不早于 v55 录音状态迁移。

## 原版对照

- `decompiled_1.0.3/sources/defpackage/x5c.java`：RoomDatabase 持有 `internalTransactionExecutor`。
- `decompiled_1.0.3/sources/defpackage/t5c.java:295-310`：事务执行器由 `new cyc(..., 1)` 构造并绑定到事务 coroutine context。
- `decompiled_1.0.3/sources/defpackage/cyc.java`：`ArrayDeque` 排队 Runnable，当前任务完成后才启动下一项。

原版是“每个 RoomDatabase 有数据库级串行事务执行器”；Harmony 把多个原版表域合并进一个 `nota.db`，因此在合并后的 store 边界使用一个写者，才是接近原版执行语义的适配。它不是凭感觉增加粗锁，也不声称原版所有数据库共享同一线程。

## 未闭环

- 本阶段是进程内写者，不覆盖跨进程 RdbStore 使用、系统杀进程时的外部文件补偿和真实 SQLite 锁等待行为。
- 只读查询没有全局串行化；仍需在设备上验证长同步事务期间资料库、录音列表和缩略图读取的可见性与延迟。
- 图片资产到达仍在数据库事务内执行原子文件落位；后续可继续审计是否能缩短写锁时间而不破坏补偿语义。
- 设备并发回归应覆盖：快速翻页同时移动/改标题、后台同步同时保存工具/视口、图片或录音到达同时删除笔记，以及任意事务失败后下一写者能正常继续。
