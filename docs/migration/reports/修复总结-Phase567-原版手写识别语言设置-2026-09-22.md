# Phase 567：原版手写识别语言设置（language 行）

日期：2026-09-22

## 原版现场

- `x22.java` case 5：Handwriting & Drawing 子区最后一项
  `feature_settings__language`（在 straight_lines / shapes_detection /
  palm_detection / auto_deselect_eraser / ruler_units 之后）。
- `pb5.java` case 0：行尾以 dc5→显示名映射渲染当前识别语言。
- `dc5.java`：23 项语言枚举 `(localeCode, languageTag)`，默认 en_US 系
  （`ub5` 默认 `dc5.L`）。
- `vmc.java`：语言选择器 ViewModel；选择写全局偏好 `dc5.I`（localeCode），
  识别管线 `jc5.e` 按 note → 全局 → 系统 locale → en_US 解析。
- caption 原文："Handwriting language is used to improve recognition and
  search of your handwritten notes."

## Harmony 落地

- policy 补 `displayName`（MyScript 语言包原生名，dc5 顺序），导出
  `originalHandwritingRecognitionLanguageOptions()` 与
  `originalHandwritingLanguageDisplayName()`。
- SettingsPage 手写块尾部新增 Language 行：标签 + caption + 当前语言
  显示名，点击打开 `HandwritingLanguageDialog`（23 项、当前项打勾）。
- `setRecognitionLanguage` 复用既有守护模式（乐观更新 + saveBusy +
  lifecycleGeneration/处置守卫 + 失败回滚 + 统一 toast），写入
  `saveRecognitionLanguageId(localeCode)`。
- 加载侧：未设置偏好时按 `resolveOriginalHandwritingLanguage(null,
  stored, systemLocale)` 显示有效语言，与原版 `ub5.f` 语义一致。
- 顺带修复 `OriginalHandwritingLanguagePreferenceStore.getStore` 的
  `throw error`（arkts-limited-throw：catch 参数非 Error 类型）。

## 差异登记

- 原版选择器含语言包下载/可用性状态；Harmony 无分发管线，23 项全可选
  （fail-closed，ADR-0538）。
- `ruler_units` 因无尺具不移植。
- 设置页维持扁平 note_editor 结构，未引入原版子区分节。
