# Phase 418 修复总结：选区退出寄存器统一重置

## 问题

Phase 416 只在翻页成功时重置选区寄存器。补审发现同一页还有 11 类权威退出会调用 `deselect()` 或
`deleteSelected()` 后隐藏选区，但 NotePage 的颜色、宽度和样式继续保留：加载失败、选择中取消交互、局部橡皮完成、
四个持久化历史分支、通用历史应用、DELETE/CUT、显式 DESELECT 和数学插入。这些值既驱动工具栏回显，也可能成为下一次
signal 的批量命令来源。

## 修复

- 新增 `clearSelectionWithRegisterReset()`，一次完成 SelectionTool 清空、浮层隐藏和 nullable 寄存器 reset
  （color/width/style 为 null，宽度范围回到 0.5–30，Taper 可用）。
- 全部 11 处权威退出改用该助手；不再在每个分支手工重复发布。
- 绘制开始只是暂时隐藏旧浮层，图片裁剪与数学编辑保持概念选区，因此不纳入重置范围。

## 原版对照

1.0.3 的 `xsc.m()/s()/t()` 将 selection state 原子重置为空态。Harmony 的选区身份与命令寄存器也必须在权威退出时
一起失效，不能只清空可见选区。

## 验证

- 选区样式专项 Replay 增加全部退出路径的助手顺序断言，并模拟寄存器四项默认化，结果通过。
- ArkTS 检查 Canvas/Page/Toolbar 无错误；全量 Desktop Replay 371/371 通过。
- clean 与双静态 HAP 构建成功（clean 28.804 秒、ohosTest 32.356 秒、default 3.821 秒）。未启动模拟器、虚拟机、真机或 Hypium。
