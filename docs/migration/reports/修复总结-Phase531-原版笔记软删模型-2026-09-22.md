# Phase 531：原版笔记软删（Recently Deleted）模型落地

日期：2026-09-22

## 选题

Phase 530（原版 Room schema 逐表比对）登记的 SCHEMA-D1 为最高优先级功能差异：
原版删除笔记为软删（`ClientNoteUpdate` DELETE 行），Recently Deleted 提供恢复与
永久删除，30 天自动清除，`PermanentlyDeletedNote` 墓碑防复活；Harmony 此前
直接硬删，无恢复路径。

## 原版现场重放（decompiled_1.0.3）

- `leb.java`：移入回收站＝先清该笔记的 UNDELETE 队列行，再 `sp1(noteId, rp1.J=DELETE,
  deletedAt=now)` upsert（`ClientNoteUpdate` 复合主键 `(id,type)`，`vp1.java:17`）。
- `tp1.java`：恢复＝`DELETE FROM ClientNoteUpdate WHERE id=? AND type!='PERMANENTLY_DELETE'`——
  删掉 DELETE 队列行即恢复，本地不另写 UNDELETE 行。
- `x17.java:143` ClientPivot：`deletedAt = client[DELETE].deletedAt ?:
  (hasUndelete ? null : synced.deletedAt)`；`AllNotes` 排除 `PermanentlyDeletedNote`
  与 `hasPermanentlyDelete` 行。
- `wp1.java:544`/`e47.java`：`INSERT INTO PermanentlyDeletedNote(noteId)` 墓碑。
- `strings.xml`：设置页 "Recently Deleted"；"Unless recovered, notes in this list
  will be permanently deleted after 30 days"；"Recover notes"。

## Harmony 修改（行为等价模型，ADR-0503）

- `DatabaseHelper.ets`：`DB_VERSION=67`；`note_meta.deleted_at`；
  `DDL_PERMANENTLY_DELETED_NOTE`；`MIGRATIONS[67]`（ALTER+CREATE）；
  `idx_note_meta_deleted_at`。
- `NoteTypes.ets`：`NoteMeta.deletedAt`。
- `NoteRepositoryImpl.ets`：库投影（全部/文件夹/搜索）排除 `deleted_at IS NOT NULL`；
  新增 `getTrashedNotes/trashNote/restoreNote/purgeExpiredTrash`；`deleteNote` 写墓碑、
  清理 `search_item`（顺带修复索引孤儿）、支持 `recordTombstone=false`（导入回滚）。
- `NoteImporter.ets`：回滚不写墓碑；`noteIdExists` 覆盖墓碑表——永久删除的 id
  重导入时换新 id，绝不复活（对齐 AllNotes 墓碑排除）。
- `LibraryViewModel.ets`：删除 → `trashNote`；加载 → 先 `purgeExpiredTrash`。
- 新 `ui/settings/RecentlyDeletedPage.ets`：回收站列表（删除日期+剩余天数）、
  Recover、Delete Permanently（确认框）、原版空态文案、打开即结算过期。
- `SettingsPage.ets` + `main_pages.json` + `main_pages` 路由注册。
- 文案：`delete_note_message` 改为回收站措辞（中/英），新增 10 条字符串（中/英）。
