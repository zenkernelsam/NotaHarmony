# Phase 536：原版页书签（bookmark）奇偶落地

日期：2026-09-22

## 选题

原版功能级差距清查：页书签是原版内容管理器的一等功能
（`nd2` 过滤枚举 ALL/BOOKMARKS/NOTES、`md.java` 缩略图
`bookmark_tall_fill/outline` 叠加、`de2.m` 多选开关动作），
且在线格式上是每页 LWW 寄存器（CreatePage/ModifyPage 字段 3）。
Harmony 此前对携带 `bookmarked` 的 CreatePage 与 ModifyPage/bundle
一律 `BOOKMARK_UNSUPPORTED` 延迟且不解析字段——判定为 P1 数据
保真缺陷（导入的书签状态静默丢失）。

## Harmony 修改（ADR-0508）

- Schema v70：三张物化表加 `bookmarked`（`INTEGER NOT NULL
  DEFAULT 0`）+ 新建 `original_page_bookmark_winner` 胜者表
  （页序列身份主键、胜者身份、`CHECK (0|1)`、CASCADE）；迁移自
  `original_page_identity` 播种既有页胜者。
- `OriginalCreatePageOperation`：字段 3 解码（仅字节 1 → true），
  移除书签延迟，按操作身份播种胜者并物化 `page_info`。
- `OriginalModifyPageOperation`：`hasBookmarked`/`bookmarked` 解码 +
  `applyBookmark`（胜者读 → LWW → 胜者写 + 活动/归档页物化）。
- `OriginalModifyPagePayloadEncoder`：`encodeOriginalModifyPageBookmark`
  （字段 3 vtable 字节、页向量 4 对齐、缺省字段 vtable=0）。
- `OriginalNoteBundlePageIdentity`：bootstrap 状态携带书签与胜者；
  fresh 插胜者行；`applyBootstrapBookmarks` 双路径物化；
  `existingMappingMatches`/`hasExistingMapping` 校验胜者表。
- 运行时：`PageInfo.bookmarked` 全链（克隆/读写/检查点/归档恢复/
  导入导出/备份签名）；`PageRepository.setPageBookmarked` 双路径
  （原版页 → `persistOriginalPageBookmark` 操作流；本地页 → 列更新）。
- UI：`PageManagerBar` 当前页 `🔖` 指示 + 开关按钮 + 紧凑菜单项；
  `NotePage.toggleCurrentPageBookmark` 经 `runPageOperation`；
  `bookmark_page`/`remove_bookmark` 双语资源。

## 刻意排除

`bookmarked` 是可变寄存器，不进入 `PageStructureOpCodec`/
`samePage`/`samePageInfo`/`changedPages`——否则删除推送与重做之间
的书签翻转会导致检查点校验失败。检查点/归档列仍携带书签保真恢复。
