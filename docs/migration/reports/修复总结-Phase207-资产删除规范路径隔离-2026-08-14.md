# Phase 207 修复总结：资产删除规范路径隔离

## 发现

Phase 206 建立全局 RDB 写者后继续复核资产锁图，发现 Phase 201/206 的“事务提交后释放数据库写者、继续持有资产锁再删除文件”并不足以保护内容寻址文件：

1. `OriginalAssetReferenceStore.mergeOriginalAssetReference()` 会在页面背景、录音、NOTE_BUNDLE 等 operation reducer 的既有事务里直接插入或更新 `note_asset`。
2. `OriginalCreateBlockOperation` 也会为 IMAGE block 直接合并 canonical/legacy 资产行。
3. 这些路径共享 `databaseWriteMutex`，但并不全部取得 `assetMutationMutex`；因此资产锁不能阻止它们在删除事务提交后复用同一 hash。
4. 旧顺序下，删除方释放数据库写者后，新的编辑器/同步事务可以先发布同 hash 引用；删除方随后对旧 `local_path` 执行 unlink，会把新引用正在使用的规范文件删除。
5. canonical/legacy hash 迁移期间，两个 `note_asset` 行还可能共享同一 `local_path`；删除其中一行并不等于取得该文件的独占所有权。

这不是两个数据库事务重叠的问题，而是数据库提交与提交后文件副作用之间的所有权缺口。简单把慢速 unlink 放回全局写者虽能保正确，却会阻塞页面保存、同步、工具状态和资料库写入。

## 修复

- 新增共享 `detachAssetFileForDeletion()`：只接受应用 `filesDir` 内路径，在 `<filesDir>/assets/trash` 分配唯一隔离名，并用同文件系统 `renameSync` 原子移走规范文件。
- `AssetRepositoryImpl.deleteAsset()` 在删除事务提交后、仍持有 `databaseWriteMutex` 时 detach；释放数据库写者后、仍在 `assetMutationMutex` 内 unlink 隔离文件。
- `NoteRepositoryImpl.deleteNote()` 对最后引用消失的全部资产采用同一两阶段顺序；数据库提交和所有规范路径 detach 完成后才释放数据库写者，随后删除隔离文件并忘记资产 availability generation。
- 两条删除入口都在目标资产行删除后、提交前按 `local_path` 查询剩余所有者；仍由 canonical/legacy 别名行或其他资产行引用的文件不会进入 detach 集合。笔记删除同时去重候选路径，避免同一文件被重复处理。
- detach 失败、路径越界或源文件缺失时不安排稍后的规范路径 unlink。该路径宁可留下可复用孤儿文件，也不会误删后来发布的同 hash 文件。
- 更新资产引用门禁、路径隔离、WebDAV 批次补偿和全局 RDB 写者 replay；新增 `d02-asset-delete-detach-boundary.mjs`，同时覆盖旧竞态模型与新顺序源码门。
- ADR-0178/0183 更正“仅持有资产锁即可覆盖所有引用写者”的旧边界，新增 ADR-0184 记录规范路径隔离协议。

## 原版对照

- `decompiled_1.0.3/sources/defpackage/zq6.java`：原版在私有 `assets/final` 中以完整 `AssetHash` 派生规范文件名。
- `defpackage/p29.java`：原版资产管理器持有专用 `em8` mutex。
- `defpackage/em8.java`：该对象是 coroutine mutex，负责串行取得/释放。
- `defpackage/mr1.java`、`defpackage/vs8.java`：资产到达在该 mutex 内核对 hash，并替换 `zq6.h(...)` 的规范文件。

原版不允许较早的异步清理在较新的同 hash 发布之后删除规范文件。Harmony 的 operation reducer 与资产文件路径分属不同适配层，因此使用“数据库写者内快速 detach、写者外慢速 unlink”恢复这一生命周期不变量；不声称原版逐行采用相同 trash 目录实现。

## 未闭环

- 进程在 detach 后、unlink 前退出会留下 `assets/trash` 孤儿；其不会占用规范 hash 路径，但后续仍可增加安全的启动期垃圾回收。
- 进程在数据库提交后、detach 前退出会留下无数据库行的规范孤儿文件；同 hash 到达会逐字节核对并复用，但仍需设备故障注入确认。
- rename 权限失败、磁盘满、符号链接解析、跨进程访问及真实同 hash“删除/同步到达/图片恢复”并发仍需设备验证。
- 当前共享路径门禁按数据库中持久化的 `local_path` 精确比较；路径别名、大小写或符号链接指向同一实体的异常脏数据仍需设备与迁移故障注入验证。
