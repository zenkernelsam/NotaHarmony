# Phase 299 修复总结：图片粘贴执行前可用性复查

## 缺陷

Phase 295～298 收口了菜单显示与异步刷新，但点击执行入口仍只检查编辑器和忙碌状态。若长按后系统剪贴板被替换
成文本或清空，旧菜单项仍可能进入 READ_PASTEBOARD 请求和 Pasteboard 数据读取，最后以错误反馈收场。

## 决策与实现

`startOriginalClipboardImagePaste()` 改为先走统一 `canUseOriginalClipboardImage()` 门禁，再做一次当前 MIME
availability probe。probe 不可用时同步清除缓存并静默返回；只有复查通过才请求 `READ_PASTEBOARD`，随后读取
PixelMap 并复用原版缩放/WebP lossy 85 规范化。显示状态与执行状态现在使用同一语义边界。

## 验证

- 剪贴板专项 Replay 从 22/22 扩展至 23/23，新增“复查先于权限”断言；
- 双 HAP 与全量 Replay 结果见总进展验证补录；
- 未启动模拟器、虚拟机、真机或 Hypium。

## 开放项

真实点击竞态、跨应用复制时序和厂商 MIME 兼容矩阵仍需设备验收；`T-042` 继续严格留到 Goal 最后一项。
