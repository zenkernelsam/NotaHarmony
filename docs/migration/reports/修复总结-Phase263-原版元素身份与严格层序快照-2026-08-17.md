## 修复前真实缺陷

### `(kind,id)` 仍可制造双重实体

早期 M2-R-09 已有统一 `PageElementRef`，但 normalization、成员比较和若干 codec 仍把 kind 与 ID 一起作为 key。
数据库主键为 `(note_id,page_id,element_id,kind)`，因此同一 ID 可以作为 Stroke/Text 同页共存，或跨页面重复。

### 损坏显式 order 被自动“修好”

非空 order 即使缺成员、重复、zIndex 错误或 kind 不匹配，也可能被 normalization 删除坏引用、补回遗漏成员并
重排。调用方随后无法知道 durable snapshot 已经损坏，Undo/Redo 与导出可能继续传播伪造顺序。

### row 与 payload identity 可撕裂

持久化加载以前可以只信 row kind/ID，随后把 payload JSON 解码为另一 kind 或另一 ID；部分路径会逐条跳过坏元素，
最终把内容丢失伪装成可加载页面。

## 实际修改

### note-wide、ID-only identity

- 新增 `PageElementIdentity.ets`，为整包导入提供原子 note-wide ID reservation，并为事务写入提供其他 live 页面
  占用检查。
- `strictPageElementOrder()` 先按 ID 注册 Stroke/Text/Shape/Image/Math；任何跨 kind 重用立即失败。
- 空 order 仅作为 legacy 确定性迁移入口。任何非空 order 必须数量完整、zIndex 从 0 连续、kind 匹配且每个 ID
  恰好一次；不再自动补成员或重排后继续保存。
- append/remove/member/order、Undo/Redo、page mutation/snapshot、persistent history、Group mutation、partial
  erase 与 clipboard 全部使用 ID-only key；kind 只参与 discriminator 验证。

### row/payload 强绑定和整页 fail closed

- `decodeStoredPageElement(elementId,kind,payload)` 验证 kind 1..5、非空 payload、JSON discriminator 与内嵌 ID。
- 当前页/整篇 note 加载、history、DELETE_PAGE checkpoint 与 repository restore 统一走严格 decoder。
- 任一 row identity、payload 或 order 损坏会使整次操作失败，不再逐条跳过后返回假成功。

### 导入、保存、history 与页面恢复

- 自有 `.note` 和 Notability 导入都在创建 note 前扫描所有页面，跨页 ID 冲突直接计为包损坏，不留下半成品。
- 普通 snapshot 保存、同页 history group 和删除页恢复在同一 SQLite transaction 内检查其他 live 页面。
- 快速切页、删除页 checkpoint、Undo/Redo、partial erase 与 clipboard future snapshot 都携带并严格验证同一
  element order。

### DB v64 与旧损坏库兼容

- 数据库升至 v64，新增非唯一
  `idx_page_snapshot_identity ON page_element_snapshot(note_id,element_id)`。
- v64 migration 和 latest-schema 初始化都先创建该索引，再安装 INSERT 与 identity-field UPDATE trigger。
- 不创建 `UNIQUE(note_id,element_id)`：旧库已有重复行时仍可启动和诊断；trigger 禁止任何未来跨页/跨 kind 重用。
- 专项内存 SQLite 在已有重复行后成功创建索引，并用 `EXPLAIN QUERY PLAN` 证明 trigger 的 `EXISTS` 查询形状命中
  identity index，避免批量插入近似 O(n²) 扫描。

### Group、hidden/archived 与 operation identity

- active Group ID 与 live 叶实体 ID 冲突时，Group selection/layering 直接 fail closed。
- 入站 operation 由 `(note_id,op_timestamp,editor_site_id)` 主键持久化；相同 identity 只有 bytes/metadata 完全
  相同才视为幂等，payload 冲突会拒绝。
- 本地 identity 通过 `max_op_timestamp` 分配并 compare-and-set；并发分配只有一个成功，已有 operation/sync 状态后
  editor site 不可替换。因此 hidden/archived 原版实体不会因为暂时离开 live page snapshot 而重新释放 ID。
- 没有增加跨全部原版 CRDT/archive 表的保存期扫描 trigger，避免把 operation identity 已保证的边界重复实现。

## 边修边审发现并修复

- v64 trigger 的查询条件正是 `(note_id,element_id)`，但旧索引只有 note/revision 和 note/page/order；批量保存会
  反复扫描同 note。新增非唯一 identity index，并保证 migration 在 trigger 前创建。
- `NoteCanvasView.ets` 仍保留已无调用的 `normalizePageElementOrder` import，现已清理。
- Clipboard 的内部 state 虽来自严格 Copy admission，专项仍补充锁定“非空损坏 order 不得替换已发布 clipboard”。
- replay 增加 row/payload discriminator、Group/leaf shared identity、hidden/archived operation identity 与索引
  query-plan 证据，避免未来以性能或兼容为由回退为 `(kind,id)`。
