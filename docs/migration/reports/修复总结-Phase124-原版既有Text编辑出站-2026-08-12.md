# Phase 124 修复总结：原版既有 Text 编辑出站与身份保持 Undo/Redo

## 原版证据与设计纠错

- 直读原版 `s5j/u5j/kci/f46/tej/pub/vej/qub/f2c`：一个 Unicode code point 使用 type 7，
  多个使用 type 8；删除一个字符使用 type 9、多个使用 type 10，复活使用 type 11。
- 原版删除是字符身份上的 LWW tombstone，Undo 不应重新插入同值字符。Harmony 目前编辑器只给
  before/after 字符串，因此按 Unicode scalar 公共前后缀还原一次连续替换，并优先匹配 hidden
  identity 做 REVIVE。
- Text 自动尺寸属于 type-19 field 6。审查时补上 float32 可重放门禁，避免编辑器 double 值经
  原版 payload 截断后与目标快照不一致，导致事务在 reducer-state 校验阶段失败。

## 已完成修复

- 新增严格 type-7/8 与 type-9/10/11 writer，覆盖 root/显式锚点、Block identity、Unicode、
  空输入、重复身份、数量和字节预算校验；新增 type-19 size writer。
- 新增 `OriginalLocalTextMutation`：验证 CRDT 可见文本等于 before，计划 remove/revive/insert，
  并通过完整字符树物化证明复活候选精确生成 after。
- visibility reducer 新增 batch 入口并导出规范字符顺序物化。REMOVE、REVIVE/INSERT 与可选
  MODIFY_BLOCK 经生产 reducer、upload-immediate journal 和同一个 `OriginalPageMutationBatch`，
  一次 UI 编辑只推进 `N→N+1`。
- 严格 classifier 只接受一个既有 Text、稳定 ID/顺序、live canonical 原版 Block、已有字符状态、
  无字符/段落样式，且只允许正文、尺寸与派生 bounds 改变。额外补齐 snapshot row ID 与 payload
  ID 一致性，损坏状态不再误入原版 writer。
- 新增 `ORIGINAL_TEXT_VISIBILITY=73` 透明 history companion。普通提交与多步持久 Undo/Redo
  都复用同一事务路径；替换 Undo/Redo 在 B/X 身份之间 remove/revive，不制造重复字符 identity。
- 边修边审收紧 history-group 分类链：Text 已命中时不再继续误分类 Image flip/crop/position。
