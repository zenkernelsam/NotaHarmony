# Phase 296 修复总结：剪贴板图片实时可用性更新

## 缺陷

Phase 295 的 MIME 探测只在页面加载和切换时执行。若用户保持笔记打开，再从其他应用复制系统图片，
Canvas 仍缓存旧的不可用状态；这与 Android 原版每次构造菜单状态都读取当前 ClipDescription 的行为不一致。

## 决策与实现

新增可注入的 Pasteboard update 订阅边界。`NoteCanvasView` 在 `aboutToAppear()` 调用
`SystemPasteboard.on('update')`，在 `aboutToDisappear()` 用同一 callback 调用 `off('update')`。事件回调只触发
Phase 295 的 MIME probe；生命周期结束时清空 `systemClipboardImageAvailable`。订阅与退订异常记录日志并保持
listener 状态一致，不会重复订阅或泄漏。

实际粘贴链路不变：仍先通过 READ_PASTEBOARD gateway，再读取 PixelMap 并做原版缩放/WebP 规范化。

## 验证

- ArkTS fixture 增加“订阅与退订同一 listener”用例；
- 剪贴板专项 Replay 从 20/20 扩展至 21/21，覆盖 update 事件接线、生命周期退订和菜单门禁；
- 双 HAP 与全量 Replay 结果见总进展验证补录；
- 未启动模拟器、虚拟机、真机或 Hypium。

## 开放项

真实系统剪贴板事件频率、跨应用复制时序、厂商兼容行为和大图粘贴体验仍需设备验收；`T-042` 继续严格留到
Goal 最后一项。
