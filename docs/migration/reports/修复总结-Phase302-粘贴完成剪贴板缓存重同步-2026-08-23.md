# Phase 302 修复总结：粘贴完成后的剪贴板缓存重同步

## 缺陷

粘贴期间的外部 update 可能因事件合并、generation 过滤而未能更新缓存；部分插入失败时，旧缓存也不应继续
表示当前可用性。缺少完成后的统一重同步点会让 Paste 菜单短暂偏离真实 MIME 状态。

## 决策与实现

捕获 `insertOriginalPhotos()` 返回的 `PhotoInsertOutcome`，在数据流程完成后重新调用无权限的 MIME probe，
并将缓存设置为 `probe && outcome.insertedCount > 0`。probe 异常继续 fail closed；重同步不读取 PasteData、
不解码 PixelMap，也不触发权限。显示、执行前复查和完成重同步现在形成闭环。

## 验证

- 剪贴板专项 Replay 从 24/24 扩展至 25/25，新增完成重同步断言；
- 双 HAP 与全量 Replay 结果见总进展验证补录；
- 未启动模拟器、虚拟机、真机或 Hypium。
