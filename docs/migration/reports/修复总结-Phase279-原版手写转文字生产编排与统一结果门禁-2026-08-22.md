## 2. 原版 1.0.3 证据

本阶段直读 `dhb.java`、`hc5.java`、`tsc.java`、`bt1.java`、`lvd.java`、`cq.java`、`re0.java`：

1. `dhb` 从当前页筛出存在且 `wqh.e()` 允许的 Ink，并建立 eligible ID 快照；后续单页检查、识别与转换使用同一候选集合。
2. `hc5` 对空 eligible 列表直接返回空字符串，不调用识别 provider；非空才进入异步 `pm8.c`。
3. `tsc` 以 `lvd.E0` 判断结果是否全为空白；`cq.f0` 等价于 `Character.isWhitespace || Character.isSpaceChar`。全空白不提交，合法文本的前后空白不应被 trim。
4. `bt1` 在一个 `xq9` transaction 内严格执行 `DELETE_ENTITIES → CREATE_BLOCK(TEXT) → INSERT_STRING`。
5. `re0` 只在转换完成后记录 `Convert Handwriting`，失败或迟到结果不应产生成功历史。

## 3. 实现内容

### 3.1 统一 UTF-8/Unicode/空白门禁

新增 `OriginalHandwritingConversionTextPolicy.ets`，并让 planner、persistence 与
`OriginalInsertTextPayloadEncoder.ets` 共用同一检查路径：

- 空字符串拒绝；
- 原版全空白（含普通空格、不换行空格、全角空格、换行等）拒绝；
- `TextEncoder` 编码必须经 UTF-8 `TextDecoder` 严格往返，孤立 surrogate 拒绝；
- wire payload 最大值是 1 MiB **字节**，不是 UTF-16 code-unit 数；
- 合法文本保持原样，`  hello  ` 不被 trim。

分类顺序保留原版调用链：非空后先执行 `tsc/lvd` 全空白判断，再应用 Harmony wire 的 Unicode/byte
门禁，因此超大纯空白仍是 `RESULT_WHITESPACE_ONLY`，不会被误报为 `RESULT_TOO_LARGE`。

修复前 planner 的 `result.text.length > 1048576` 会让多字节文本错误通过，直到持久层才失败；现在 planner
与 transaction 前置校验共享真实 encoder 预算。

### 3.2 Convert-to-Text coordinator

新增 `OriginalHandwritingConversionCoordinator.ets`，依赖注入：

```text
immutable page snapshot
  → adaptOriginalHandwritingSelection
  → planOriginalHandwritingConversion
  → context reader
  → async stroke-native provider
  → freshness reader（page/generation/fingerprint）
  → commitOriginalHandwritingConversion
```

安全不变量：

1. planner、OCR 和 persistence 共用同一 `acceptedStrokeIds` 序列；不重新猜测 UI 顺序。
2. OCR 前通过 persisted-element codec 冻结 exact `StrokeElementData` 快照；调用方修改原对象不影响提交。
3. 原子 type-25 写回要求 canonical `op:*` entity identity；coordinator 在读取 context、调用 provider 前即拒绝
   `nb-*` 等导入 ID，避免耗费 OCR 后才以泛化 persistence failure 结束。selection adapter 仍可独立服务
   imported stroke 的 provider 顺序，不伪造 operation clock。
4. provider 返回后重新读取 freshness 三元组；页切换、generation 变化或 source fingerprint 变化均丢弃迟到结果。
5. coordinator 不分配 operation identity，不修改 selection、画布或 Undo/Redo；DELETE/CREATE/INSERT identity
   及 HWC1 history 仍由 `commitOriginalHandwritingConversion()` 独占。
6. 所有失败结构化返回，只有 `SUCCESS` 才允许未来 caller 刷新 UI/history。

结果枚举明确区分：`INVALID_REQUEST`、`PLAN_REJECTED`、`PROVIDER_UNAVAILABLE`、`CONTEXT_FAILURE`、
`PROVIDER_FAILURE`、`PROVIDER_NO_RESULT`、`RESULT_REJECTED`、`STALE_RESULT`、`FRESHNESS_FAILURE`、
`PERSISTENCE_FAILURE`、`SOURCE_IDENTITY_UNSUPPORTED`、`SUCCESS`。

### 3.3 边修边补审修正

- 把全空白判定从“空字符串/长度”中分离出来，避免识别出一串空格时创建空 Text。
- 把 planner 的长度门禁改为真实 UTF-8 byte/round-trip 检查，覆盖 ASCII 恰好 1 MiB、超限多字节和孤立
  surrogate。
- 补审并固定原版空白判定优先级，以及非 original source identity 的 provider 前 fail-fast，避免结果分类漂移
  和无意义的异步 OCR 调用。
- 增加 `recognizeAvailableOriginalHandwritingText()`，让 coordinator 在捕获 `isAvailable()` 异常后不重复
  探测 provider；既有公共识别入口行为保持不变。
- 持久层继续作为最终防线，coordinator 不绕过 source payload byte compare、original identity 分配或事务回滚。
