# T-041 完成报告：存储层页维度修复

## 结论

T-041 的目标已由后续持久化重构实现：存储层以 `noteId + pageId` 为权威读写维度，`page_info` 另有
`page_index` 唯一约束和纸张尺寸列。我方 ZIP、原版 Notability Session、导出器、编辑器翻页和缩略图都按页隔离，
不再存在“先删除整笔记再全量重写”或“多页纵向平铺”的路径。

## 当前实现证据

- `DatabaseHelper.ets`：`page_info` 包含 `page_id/note_id/page_index/width_mm/height_mm`，
  并有 `UNIQUE(note_id,page_index)` 与 `UNIQUE(note_id,page_id)`。
- `NoteImporter.importOurFormat()`：逐页解析并校验 `pageIndex`、唯一 `pageId` 和跨页元素身份；
  每页调用 `addImportedPage()` 后按该页 `pageInfo.pageId` 调用 `saveElements()`。
- `NoteImporter.importNotability()`：Session 解析为真实页列表，逐页分配新 `pageId`、写入元素顺序，
  没有 flattenPages。
- `StrokePersistence.saveElements()/loadElements()`：参数均为 `noteId + pageId`；队列键也按同一页身份隔离。
- `NoteExporter`、`NoteCanvasView`、`ThumbnailRenderer`：分别用 `p.pageId`、`targetPageId`、`page.pageId`
  加载对应页内容。

## 验收映射

- 多页恢复：导入前拒绝重复页/错序页/跨页重复元素；导出按页生成 `pages/page_N.json`，导入重建独立页。
- OP-AMP 类多页 `.note`：Session 页列表逐页落库，不再合并为长画布。
- 旧数据：迁移将 `client_op.page_id` 绑定到既有页；缺页场景补默认页。
- 翻页：编辑器每次切页以 `targetPageId` 读取；缩略图按页读取。
- 构建门禁：Phase 413 记录 clean 与双 HAP 静态构建结果。模拟器/Hypium 属 Goal 明令禁止项，
  运行态验收保留到允许设备阶段的最终回归。
