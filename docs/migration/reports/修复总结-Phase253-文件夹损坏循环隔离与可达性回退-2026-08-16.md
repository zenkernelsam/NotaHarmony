# Phase 253 修复总结：文件夹损坏循环隔离与可达性回退

## 目标

承接 M2-U-05。既有实现已经具备 parent/siblingOrder、名称校验、自身子树防护、六层上限和事务门禁；本阶段不重复
实现这些功能，而是边修边审其损坏数据边界。

## 发现

`isFolderInSubtree()` 过去在 parent 链出现循环时直接返回 true。由于删除 folder 会用该 helper 枚举整棵子树，
一个与目标无关的损坏循环也会被误认成目标后代，导致无关 folder 的笔记被移到根目录，甚至随外键级联删除 folder。
同时 compact/regular 导航只 fallback 缺失 parent，循环组件完全不可达。

## 修复

- 无关循环现在返回“不是目标后代”；只有 parent 链真实到达 root 才进入删除集合。
- 移动校验仍调用 `folderDepth()`，循环 ancestry 会抛错，因此不会因删除隔离而放松自身子树/损坏父级防护。
- 导航新增 cyclic ancestry 检测，把循环组件作为损坏数据 fallback 暴露；合法折叠父级的子节点仍保持隐藏，不会重现
  Phase 251 修过的 orphan 重复显示 bug。
- `FolderRepository.test.ets` 新增正常 root、正常 child 与无关 A↔B 循环 fixture。

## 原版对照

原版 `e47` 保存 parent/siblingOrder，`beb.h()` 递归真实 children 求子树高度，`xdb` 在移动前做自身子树和六层上限
检查。原版正常写路径以合法树为前提；Harmony 的循环隔离是恢复/旧数据所需的 fail-safe，目标是避免扩大损坏范围，
不把它冒充成原版业务功能。
