# Phase 199 修复总结：WebDAV 配置资源规范化

## 发现

WebDAV 建目录使用宽松 `pathSegments()`，上传和 manifest 使用另一套 `backupUrl()`；配置页、事务、
legacy 迁移又各自 trim/default。重复分隔符、dot segment、反斜杠和编码 `/`、`\` 可能令同一配置
映射到不同远端资源。服务器 URL 也未统一拒绝非 HTTP(S)、缺 authority、user-info、query、fragment
和控制字符。

修复过程中继续发现：若把配置段的 `%25` 解码成字面 `%` 后直接持久化，下次加载会再次解码，
`%252F` 可能跨多次保存逐步变成 `/`；而严格升级校验若不区分 record envelope 与旧路径值，还会令
用户无法覆盖旧非法配置。

## 修改

- 新增共享 `normalizeWebDAVConfig()`，覆盖客户端、事务 load/save、legacy 迁移与设置页测试/保存
- 使用 Harmony `url.URL` 验证 HTTP(S)、authority、基础路径及无 credentials/query/fragment
- 服务器和备份路径按 segment 拒绝控制字符、反斜杠、空段、`.`、`..`、编码分隔符及非法百分号
- 备份路径以幂等规范编码持久化，所有 MKCOL/PUT/GET/manifest URL 共用同一解码 segment 列表
- 设置页以可读形式显示路径，同时保护字面 `%`，保证 UI 往返不改变资源身份
- HTTP 必须显式确认，HTTPS 自动清除无意义的 `allowInsecureHttp`
- Basic Auth 用户名拒绝 `:`；空服务器不得保留可查询的密码 alias
- 配置与存储记录在读密码前校验；非法配置在写 secret/record 前拒绝
- 允许 envelope/alias 可信但旧路径非法的记录被新配置安全替换并回收旧凭据
- 生成对象名新增层级分隔符和 dot segment 门禁
- 所有带 Basic Auth 的请求新增同源且位于配置基础路径下的最终门禁，防止凭据外送
- 新增英文/中文非法配置提示、ArkTS 单测和专项 replay
