# 修复总结 — Phase 443 照片 Picker 原始资产门禁修复

日期：2026-08-26

## 审计范围

复核交接优先项中的照片 caller。本地 DevEco SDK 的 `PhotoSelectResult` 除有序 `photoUris`
外还声明 `isOriginalPhoto`，且默认为 `false`；而 Phase 283 后的生产 caller 只读取 URI 列表。

## 缺陷

若系统 PhotoViewPicker 返回压缩、转换或非原始媒体，Harmony 会直接进入 Phase 282 的
original photo ingress，并在后续链路中继续把它当作 Android 原版意义上的原图处理。

## 修复

生产 caller 在每次选择成功后检查 `result.isOriginalPhoto === true`；非原始资产立即抛错，
不进入校验、URI 复制、规范化或持久化。500 张上限提取为
`ORIGINAL_PHOTO_PICKER_MAX_SELECTION`，既有空选择/取消语义不变。

## 变更证据

新增 ADR-0415、Harmony evidence、中文 Report 和专项 Replay
`d02-photo-picker-original-asset-bound.mjs`（9/9），同时锁定 SDK 声明、500 上限、
原始资产检查顺序和 ingress 边界。真实设备权限、provider URI、格式矩阵与性能仍开放。
