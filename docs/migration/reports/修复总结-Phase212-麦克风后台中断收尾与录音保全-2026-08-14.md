# Phase 212 修复总结：麦克风后台中断收尾与录音保全

## 发现

完成 Phase 211 后继续检查录音生产链，发现 `OriginalRecordingMicrophoneBackend` 的唯一空方法
`setInterruptionListener()` 不是无害占位：

- Harmony AVRecorder 可以由系统以 `StateChangeReason.BACKGROUND` 自动进入 `paused/stopped`；
- 后端只监听 error，不监听 stateChange，控制器和 UI 可能仍认为录音正在进行；
- 后端 stop 只接受 started/paused。若平台已经 stopped，后续停止会抛错并走 abort，删除本来可以持久化的
  有效 `.m4a`；
- 会话统一中断入口会先把 `focusActive=false`。该假设只适用于 focus gateway 自己发出的事件；backend 发出
  中断时会让仍活动的 AudioSession 被误判为已经释放。

这构成用户可感知的数据丢失：切后台、系统抢占或其他平台策略已经结束录音后，应用不仅不能自动收尾，还会
在用户再次按停止时删除已录内容。

## 原版对照

- 原版 `wr8.java` 在 AudioFocus 丢失且录音活跃时明确发出 interruption，沿录音拥有者的正常停止路径收尾。
- 原版 `tr8.java` 为 MediaRecorder 安装 info/error listener，不只依赖页面状态。
- Harmony SDK 明确区分 USER/BACKGROUND stateChange，并允许系统把 recorder 变成 paused/stopped。

因此本阶段复刻原版“中断必须通知拥有者并收尾保存”的行为，同时按 Harmony 平台状态机适配已经 stopped 的
情况；没有把原版不存在的 API 细节伪称为逐行移植。

## 修复

- `OriginalRecordingMicrophoneBackend`：
  - 实现 interruption listener 存储；
  - 在 prepare 前订阅 AVRecorder `stateChange`；
  - 只响应当前 recorder 的 BACKGROUND paused/stopped；
  - 每个 recorder 去重一次中断通知；
  - stop 接受已 stopped 状态，并跳过非法的第二次 `recorder.stop()`；
  - 仍然 release、校验普通非空文件、读取媒体时长并交给原有持久化；
  - release/dispose 注销 stateChange/error listener 并清空去重状态。
- `OriginalRecordingSessionController`：中断入口不再预先清除 `focusActive`，统一让串行 stop 的
  `deactivateFocus()` 执行幂等释放，从而同时覆盖 focus gateway 与 backend 两种来源。
- `OriginalRecordingSessionController.test.ets`：
  - 原有 focus 中断测试增加 focus-off 断言；
  - 新增麦克风 backend 中断后 stop、focus-off、persist 的完整顺序测试。
- 加强既有录音 capture replay，并新增 `d02-recording-background-interruption.mjs`，锁定原版 focus/listener
  证据、Harmony 事件分类、去重、已 stopped 收尾、listener 所有权、统一 stop/save 和运行时策略模型。
- 新增 ADR-0189。
