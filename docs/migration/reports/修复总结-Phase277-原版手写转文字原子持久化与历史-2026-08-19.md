## 2. 原版 1.0.3 证据结论

直读 `xsc.java`、`bt1.java`、`u5j.java`、`s5j.java`、`haa.java` 后确认：

1. 选区必须属于同一 page；union bounds 每轴不足 `8.0f` 时居中补齐。
2. Text 的 origin 是 selection top-left 减 page-frame origin，optional transform 省略时为 identity。
3. `bt1` 在同一个 `xq9` transaction 内严格执行：
   `DELETE_ENTITIES(type 25) → CREATE_BLOCK(TEXT, type 22) → INSERT_STRING(type 8)`。
4. `CREATE_BLOCK` 生成的 Text identity 是后续 `INSERT_STRING` 的精确目标，三步不能拆成独立提交。

## 3. 实现内容

### 3.1 原子 persistence path

新增 `StrokePersistence.commitOriginalHandwritingConversion()`：

- 先 flush 同页普通保存队列，再进入 `editorPersistenceMutex` 与单一 RDB transaction；
- 从 live page 重新读取完整 snapshot，逐条比较 source Ink 的持久化 payload 字节，并确认 original
  entity state 仍存在；stale source 直接 rollback；
- 按原版顺序分配并应用三条真实 original operation：

  ```text
  type 25 ORIGINAL_DELETE_ENTITIES
  type 22 ORIGINAL_CREATE_BLOCK(TEXT)
  type 8  ORIGINAL_INSERT_TEXT / INSERT_STRING
  ```

- 三个 reducer 共享同一个 `OriginalPageMutationBatch`，只在末尾 flush 一次；页面 revision 从 `N`
  只推进到 `N+1`；Ink 与 Text search index 分别失效；
- 重新读取 materialized Text，校验 identity、identity transform、Float32 origin/size、world bounds
  和完整 rich text；snapshot/search/history 任一失败均 rollback。

### 3.2 输入与数值门禁

`validateOriginalHandwritingConversionPersistencePlan()` 现在拒绝：

- 非 canonical original ID、重复 source、未完成 Ink、highlighter、partial eraser；
- 非有限或无法 Float32 round-trip 的 origin/width/height 及 `origin + size`；
- 小于原版最小尺寸的 block；
- 空字符串、非法 UTF-8 或超过生产 `INSERT_STRING` 1 MiB 限制的识别结果。

### 3.3 HWC1 durable history

新增 `OriginalHandwritingConversionMutationCodec.ets`：

- magic 为 `HWC1`；
- 保存完整 `PageMutationOpPayload`、source Ink IDs 和创建出的 Text ID；
- decoder 同时校验外层 kind/ID 与 persisted payload 内嵌 discriminator/identity，拒绝篡改、截断、
  尾随字节、重复 source 和 stale replay。

新增 `OpType.ORIGINAL_HANDWRITING_CONVERSION = 36` 与
`UndoableActionType.ORIGINAL_HANDWRITING_CONVERSION = 24`。`PersistentHistory` 将 HWC1 恢复为一个
dedicated action，不把三条原版 outbound row 错误拆成三个用户历史动作。

### 3.4 Undo/Redo

`applyOriginalHandwritingConversionHistory()` 在完整 page mutation replay 通过后：

- Undo 只写一条 type-25 visibility payload：隐藏 Text、恢复全部 source Ink；
- Redo 只写一条 type-25 visibility payload：隐藏全部 source Ink、恢复 Text；
- 每次共用一个 batch 并只推进一次 revision；移动后重新读取页面并验证目标 snapshot；
- HWC1 history companion 与 visibility operation 位于同一 transaction，失败整体 rollback。

`NoteCanvasView` 在调用持久层前执行当前 page/order/payload replay 门禁，成功后才移动 Undo/Redo 栈并刷新
画布/selection/search reservation。

## 4. 边修边补审发现与处理

- 原有 `OriginalDeleteEntitiesOperationApplier` 的 affected-page 收集只能保留一个 kind；混合 Ink/Text
  mutation 会漏掉一类 search invalidation。现改为按 page 收集多个 `StoredEntityTarget`，同一 page
  revision 合并失效 Ink/Text 两个索引。
- `OriginalPageMutationBatch` 原先只能记录 block 变化；现加入显式 `PageElementKind` 的 entity 记录，
  删除、创建、插字可以共享一个 revision contract。
- HWC1 不信任 page mutation 外层 kind/ID，改为重新解码 payload，避免错误 wrapper 把错误实体写入历史。
- 既有 Phase 276 文档中“混合 persistence 尚不存在”的表述是当时现场；已在 Phase 276 ADR/Report/evidence
  增加后续 Phase 277 更正，避免后续派工重复实现已闭环项。
