# 修复总结 — Phase 564：原版手掌检测设置

日期：2026-09-22

## 原版行为（硬证据）

`x22.java` case 2（Handwriting & drawing 小节）：

- `feature_settings__palm_detection` — "Palm detection"
- `feature_settings__palm_detection_lets_you_rest_your_palm_anywhere_while_writing`
  — "Palm Detection lets you rest your palm anywhere while writing."

`o59.c` 真值表：`palmDetectionEnabled` 缺省 **true**。底层屏蔽逻辑在
native 输入层（反编译不可见），可移植契约即说明语义：书写中手掌触摸
不得打断笔画。

移植前缺陷：Harmony 画布对任何第二个触点一律 `cancelActiveInteraction`
——书写中放手掌会取消进行中的笔画，与原版相反。

## Harmony 落地

- `EditorSettingsStore.ets`：`palmDetectionEnabled` 偏好键（沿用原版
  datastore 键名），共享布尔助手；`DEFAULT_PALM_DETECTION=true`。
- `EditorViewModel.ets`：`initialize` 同点加载 `palmDetectionEnabled`。
- `NoteCanvasView.ets`：`activeStrokeStylus` 记录活动指针是否为
  `SourceTool.Pen`；`palmRejectionActive()` = 开关开 + 触控笔笔画
  会话进行中。三处触摸路径守卫：
  - `onTouchDown`：笔画中到来的**非笔**触点被忽略（不取消、不进
    双指手势接管）。
  - `onTouchMove`：屏蔽激活时 `touches.length > 1` 不再取消，继续
    按 `activePointerId` 追踪笔。
  - `onTouchUp`：笔未抬时非笔抬手被忽略；笔抬手即使手掌仍按在屏上
    也正常提交笔画。
  - `resetPointerTracking` 复位标志。
- `SettingsPage.ets`：开关行（标题+原版说明）置于 shape_detection 与
  auto_deselect_eraser 之间，对齐 `x22` 条目顺序。

- 手掌先落的次序不覆盖：手指笔画进行中再落笔仍按双指接管取消
  （native 层的落笔夺权在现有事件面上不可移植，见 evidence）。
- 仅作用于触控笔笔画会话；手指笔画/橡皮/选区手势不受影响（说明
  语义即"书写时"）；第二个**笔**触点从不被当作手掌。
