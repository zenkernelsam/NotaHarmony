# Phase 301 修复总结：剪贴板探测与插入门禁分离

## 缺陷

Phase 300 为防止并发粘贴同步占用了 `photoImportBusy`，但可用性刷新的页面门禁也复用该标志。粘贴执行期间的
剪贴板 update 会触发刷新并立刻清空 `systemClipboardImageAvailable`；busy 结束后即使系统剪贴板仍是图片，
Paste 菜单也可能错误消失。

## 决策与实现

新增 `canProbeOriginalClipboardImage()`：保留 loaded、加载失败、historyBusy、persistence 和 pageId 检查，
但不把 `photoImportBusy` 当作剪贴板元数据失效。probe 初始判断和异步回写都改用该门禁；generation 守卫不变。
菜单显示和粘贴执行继续由 `canUseOriginalClipboardImage()` 要求非 busy，避免并发插入。

## 验证

- 剪贴板专项 Replay 从 23/23 扩展至 24/24，新增“probe 忽略 transient paste busy”断言；
- 双 HAP 与全量 Replay 结果见总进展验证补录；
- 未启动模拟器、虚拟机、真机或 Hypium。
