## 2. 原版结论

直读原版 1.0.3 `jc5/rn2/so5/wqh/pm8/bmb/fqa/s06` 后确认：

1. 选中实体先从当前 Note 实体表解析，缺失、隐藏、无 page frame 的实体不进入识别；文本识别还排除
   Highlighter；
2. 合法 Ink 按 unsigned operation timestamp、随后 unsigned 16-bit site ID 排序；
3. 每条 Ink 保持独立 pointer down/move/up 生命周期，不得把多条笔迹拼成一条折线；
4. 每个 center-path sample 保留 force，单笔解码失败时只 cancel 当前 pointer，再继续其他 Ink；
5. 原版 page-frame origin 会加到 Ink 局部采样。Harmony 当前页面模型已把该坐标折叠为 page-local
   `pathPoints + transform`，不能再凭空叠加第二个 frame offset。

完整 SHA-256、行号与行为片段见
`docs/migration/evidence/original-handwriting-selection-pointer-adapter-jadx-2026-08-18.md`。

## 3. 实现内容

新增 `OriginalHandwritingSelectionAdapter.ets`，提供
`adaptOriginalHandwritingSelection(selectedStrokeIds, pageStrokes)`：

- 只接收调用者已解析的当前可见页面 `StrokeElementData[]`；
- 逐笔拒绝 unfinished、partial eraser、highlighter、空 center path、奇异/非有限 affine 与非有限采样；
- 缺失 ID、重复 selection、页面内歧义 ID 均返回结构化 skip reason；
- 单笔失败不污染其他笔迹，输出同时包含 accepted IDs 与 skipped diagnostics；
- 对每个 sample 应用完整行主序 3×3 affine，并原样保留 `pressure`，包括无压感 sentinel `-1`；
- canonical `op:<timestamp>:<site>` 复用生产 `decodeOperationId()` / `compareOperationIdentity()`；
- `nb-*` 等导入 ID 不伪造原版 operation clock，而保留其输入槽位；canonical 候选只在自身槽位中排序。

## 4. 边修边补审发现

第一版候选方向若要求所有 ID 都可解码为原版 operation identity，会把 Notability 导入生成的 `nb-*`
笔迹整批判坏；若直接按 selection 数组顺序发送，又会丢失原版 `so5` 的确定顺序。最终采用“canonical
槽位稳定重排”：全 canonical 页面与原版一致，混合或全 imported 页面也不会猜造时钟或改变 imported 槽位。

同时明确了坐标职责：SelectionTool 只累计 `stroke.transform`，所以 OCR adapter 必须消费完整 affine；
使用 bounds、仅平移或单一 scale 都会让旋转、翻转和非均匀变换后的手写识别几何失真。
