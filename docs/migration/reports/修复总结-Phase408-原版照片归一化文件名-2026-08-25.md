# Phase 408 修复总结：原版照片归一化文件名

## 背景

补审发现照片选择入口总是把源 URI 扩展名拼接到 `photo-N` 后。当大图触发 Android 等价的 WebP lossy 85 规范化后，metadata 可能出现 `.jpg` 或 `.heic` 文件名配 `image/webp` MIME 的矛盾。原版 Android 实际使用 cache 目录下无扩展临时文件的名称，并不沿用 URI 扩展名。

## 修复

1. 规范化契约新增 `rewroteBytes`，明确区分未处理字节和重写后的 WebP 快照。
2. 照片入口在重写时使用无扩展的 `photo-N`；仅在未规范化时保留源扩展诊断名。
3. 入口结果同步透出 `rewroteBytes`，剪贴板 WebP 快照也显式声明为重写结果。
4. 选择顺序、读取上限、尺寸计划、临时清理和异常 fail-closed 行为保持不变。

## 证据与验证

- 新增 ADR-0385、Harmony evidence、中文 Report 和专项 Replay `d02-original-photo-normalized-name.mjs`（5/5）。
- 加强既有 `d02-original-photo-ingress.mjs`，锁定无扩展重写命名与未重写诊断命名并存。
- ArkTS fixture 覆盖 `.jpg`、`.heic` 到 WebP 的有序导入、MIME、重写标志和无扩展文件名。
- 全量 Desktop Replay：`REPLAY_FILES=365 PASSED=365 FAILED_FILES=0`。
