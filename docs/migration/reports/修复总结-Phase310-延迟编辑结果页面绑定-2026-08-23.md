# Phase 310 修复总结：延迟编辑结果页面绑定

日期：2026-08-23（Asia/Shanghai）

## 背景与缺口

Phase 301–309 已把剪贴板探测、权限续行、照片反馈和 Math 成功清除绑定到发起页。本轮补审继续追踪
`NoteCanvasView.ets` 中剩余异步路径，发现旧页迟到结果仍可影响新页：

1. 普通 `persist()` 只捕获 `pageId`，未捕获页面加载代数；flush 完成后可能误清或误报
   `saveFailed`。
2. 选区删除/剪切和普通 Paste 的 flush 回调只比较 `persistedPageId`，无法识别同 id 的重新加载。
3. Group/Ungroup promise 成功后无条件推进 undo、替换 `selectionGroups` 和元素顺序，并重建当前渲染；
   失败也全局提示新页。
4. 原版 Group Paste 的成功 UI 安装已有守卫，但 catch 中失败报告仍全局生效。

原版 1.0.3 将 `CREATE_GROUP` 定义为 op type 20，并在 reducer 中安装实体与成员变更；同时编辑器状态由
`currentPageIndex` 驱动。因此持久化事务可以跨页完成，但可见历史、数组、选区、渲染和用户反馈必须仍属于
发起页。

## 实现

- 统一在延迟边界捕获 `pageLoadGeneration` 与发起页 `pageId`；成功清除 `saveFailed`、失败调用
  `reportSaveFailure()` 都要求 generation/page/current page 与健康加载态匹配。
- 跨页迟到失败保留 hilog，不吞诊断，也不污染新页 toast 或状态。
- Group/Ungroup 的 SQLite 提交保持权威。若提交期间已切页，则记录“durable history remains available”，
  并跳过可见 undo push、组/顺序替换、同步、选择、层重建和渲染。
- 原 Group Paste 保留成功侧页面守卫，并把失败反馈收紧为同页上下文。
- `flushCurrentPage()` 在文本提交入队后、await flush 前捕获上下文，避免 await 穿越导航后影响新页。
