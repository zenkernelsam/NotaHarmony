# Phase 290 修复总结：多图照片部分失败成功前缀

日期：2026-08-23（Asia/Shanghai）
状态：已完成静态修复与验证；真实设备失败矩阵仍开放。

## 目标

接续 Phase 289 的开放缺口，审计多图照片导入在第 2 张及之后失败时的行为，消除“数据库已有成功前缀，
但当前会话不可见、不可 Undo，且重启后才出现”的状态分裂和双重错误反馈。

## 审计结论

原实现逐张提交 durable SQLite transaction；中途异常会中断循环，外层把整个批次当作保存失败。此时已入库
前序图片不会安装 UI、不进 runtime history，重启后重新出现。外层 save toast 后再抛给 photo caller，还会
形成双重反馈。原版列表校验本身是 all-or-nothing，但未提供单张持久化中途失败的补偿证据。

## 实现

- 保留每张图片独立事务和同一个 prepared history action；不做跨图 rollback。
- 首张失败保持整批失败：无成功 action、无 UI 安装，显示原 photo insert failed。
- 中途失败保留成功前缀：按输入顺序安装已 durable 图片、更新 element order、选中并重绘，推入一个
  `ADD_ELEMENTS` Undo action。
- 引入 `PhotoInsertOutcome` 区分完全成功与严格非空成功前缀；只有完全成功清 `saveFailed`，部分失败只
  显示一次明确 partial toast，失败细节写入 hilog。

## 验证

- Phase 289 及相邻 photo ingress/picker/persistence Replays 通过；
- ArkTS fixture 新增成功前缀契约并保持套件注册；

- 未启动模拟器、虚拟机、真机或 Hypium。
