# 修复总结：Phase434 录音推进所有权计数（2026-08-25）

## 问题

Phase 433 后边修边补审发现，录音自动连播使用布尔 `completionAdvanceInFlight` 表达在飞状态。
自动推进与用户 seek 都会调用播放控制器 `load()`，并共享同一个异步互斥队列。若用户 seek 后入队但使旧
自动任务先 settle，旧任务会提前清零布尔值；新 load 仍在飞行时，后续 COMPLETED 快照会被误判为无任务
在飞，自动时间线推进永久丢失。

## 修复

将布尔标志替换为权威计数 `completionAdvanceCount`。每次完成事件触发自动推进递增一次，对应 promise
通过自己的 `finally` 递减一次。销毁、无下一曲和失败路径不再由异步函数内部重复清理，统一被调用方
finally 覆盖。用户 seek 继续依赖控制器代际使旧请求失效，但不抢占其他任务的计数所有权。
