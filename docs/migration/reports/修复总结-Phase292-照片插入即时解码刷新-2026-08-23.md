# Phase 292 修复总结：照片插入即时解码刷新

日期：2026-08-23（Asia/Shanghai）
状态：已完成静态根因修复；真实设备大图性能仍开放。

## 目标

接手后继续审计 Phase 289～291 图片插入的运行态一致性，重点核对 durable 提交、UI 安装、共享 bitmap
缓存和首帧渲染之间是否存在断点。

## 审计结论与缺陷

durable 资产与 history 本身正确，但成功路径只把新 `ImageElement` concat 到 `imageBlocks` 后直接
`renderFrame()`；共享解码缓存没有新 asset entry，IMAGE renderer 只绘制 READY bitmap，因此首帧不可见。

`assetAvailabilityHub.publish()` 不能补救：它在 persistence 内部、caller 安装 `imageBlocks` 前触发。
当前 `onImageAssetAvailabilityChanged()` 遍历的是旧数组，找不到刚入库的 storageHash，于是丢弃这次
self arrival event。重启后的加载路径会调用 `refreshImageAssets()`，形成“重启后才显示”。

## Harmony 实现

在当前页代和页 ID 匹配后，安装 final images 时立即调用现有
`refreshImageAssets(generation, pageId)`。它会释放旧缓存、递增 generation 并对最终 blocks 发起异步
decode；完成后沿用既有 guard 写入缓存并强制重绘。持久化协议、history 顺序和 hub 外部到达语义不变。
