# Phase 407 修复总结：原版大图旋转缩放顺序

## 背景

原版 Android 在大图规范化时先用编码轴完成采样，再应用 EXIF 旋转。Harmony 旧适配器把 `rotate` 与 `desiredSize` 同时传入 `createPixelMap()`，但官方类型没有规定这两个选项的合成顺序。对 90°/270° 图像，平台若先按期望轴处理再旋转，可能造成轴交换失败或不必要 fail-closed。

## 修复

1. 解码时只保留原版等价的 `sampleSize`，并继续要求可编辑 PixelMap。
2. 解码后先调用 `PixelMap.rotate()` 应用 90°、180° 或 270° 旋转。
3. 随后用 Float32 边界计算缩放比，调用 `PixelMap.scale()` 到原版计划尺寸。
4. 继续校验最终输出轴，任何失败都抛出统一规范化错误并释放资源。
