# Phase 409 修复总结：资料库删除加载生命周期绑定

## 背景

资料库的权威列表读取期间，用户可以触发笔记删除。删除事务成功后，旧 `loadNotes()` 仍是活动读取代；它返回的陈旧快照会把刚删除的笔记重新放回 UI，并把 `isLoading` 错误复位为 false。

## 修复

1. `deleteNote()` 保持原有共享 mutation chain 和事务顺序，成功后继续立即移除可见卡片。
2. 若删除落地时权威读取仍在进行，则递增 `loadGeneration` 接管旧读取。
3. 用当前 folder 查询替换旧请求，并复用 stale read 与后续 mutation 的重试规则。
4. 替换读取失败不回滚已提交删除，只进入权威读取失败语义；最新有效结果才发布，loading 由 guarded finally 清理。

## 证据与验证

- 新增 ADR-0386、Harmony evidence、中文 Report 与专项 Replay `d02-library-delete-loading-bound.mjs`（5/5）。
- ArkTS fixture 增加 in-flight 权威读取中删除的场景，覆盖 loading 复位和幽灵卡片回归。
- 相邻资料库变更顺序 Replay 保持 8/8；相邻 mutation lifecycle Replay 保持 10/10。
