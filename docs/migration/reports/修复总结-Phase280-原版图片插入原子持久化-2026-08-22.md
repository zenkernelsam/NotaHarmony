## 2. 原版证据结论

直读 `bvh/bgj/vuh/w34` 及 `yr` debug extraction 后确认：

1. 显示几何同时受页面宽高各 `80%` 和 `320 / zoom` 限制；先以请求点为中心，再逐轴 clamp。
2. CREATE_BLOCK 保留 intrinsic 图片尺寸，fitted display size 通过 transform scale 表达。
3. URI 入口保持 item 顺序，最多复制 100 MiB；MIME 缯失回退 `image/*`。
4. 图片必须能读出尺寸；EXIF 90/270 度会交换对外宽高。
5. 任一轴超过 3000px 时，原版会实际缩放、应用 EXIF rotation，并以 WebP lossy 85 重写临时文件。

## 3. 实现内容

### 3.1 原版图片几何计划

新增 `OriginalImageInsertPlan.ets`：

- 所有原版 float 边界用 `Math.fround()` 重放；
- 页面 80% 与 `320 / zoom` 共同 fit，scale 不超过 1；
- 居中后逐轴 clamp；
- intrinsic width/height 写入 IMAGE metadata 与 block size；
- 显示宽高分别回算 `scaleX/scaleY`；
- 初始 crop/web URL/flip/lock/caption 等 register 使用原版默认值；
- 非有限/非正页面、zoom、anchor、坏 MIME/hash 或未规范化尺寸 fail closed。

### 3.2 图片字节与 AssetHash 门禁

- 入口复制 `Uint8Array`，最大 100 MiB。
- ImageKit 同时检查 encoded header、image MIME、EXIF orientation、实际 PixelMap decode 和尺寸一致性。
- intrinsic 尺寸必须是 `1..3000` 的安全整数；未实现的大图 adapter 不会伪装成功。
- SHA-512 digest 转为原版八个 little-endian uint64 word，并验证可重建 canonical 128 hex key。
- `sha512Digest()` 返回独立副本，避免 CryptoArchitectureKit 返回缓冲的所有权泄漏。
- 验证用 `ImageSource`/`PixelMap` 在 finally 中分别 release。

### 3.3 文件与 SQLite 原子边界

固定锁序：

```text
assetMutationMutex
→ decode/hash/file preparation
→ editorPersistenceMutex（databaseWriteMutex）
→ one SQLite transaction
```

文件先写 `assets/pending`，完整写入后 `fsync`，再原子 rename 到
`assets/final/<sha512>`。已有 final 必须 size 和内容完全相同才复用。

同一 transaction 内完成：

- reducer 前 canonical/legacy 历史资产 reconcile；
- IMAGE CREATE_BLOCK reducer；
- uploadable original operation；
- `note_asset` LOCAL/UPLOADED/DOWNLOADED 状态与 note references 合并；
- 单次 page revision、完整 snapshot/order 与 search state；
- PageMutation durable history companion。

任一步失败都 rollback；只补偿删除本调用新建的 final 文件，绝不删除复用文件。availability generation 只在
SQLite commit 返回后发布。

### 3.4 历史路径修复策略

- 应用私有目录内且逐字节同内容：数据库改指 canonical final，旧文件保留；
- 旧路径缺失：用已验证 canonical final 修复数据库；
- 私有旧路径内容冲突：拒绝并回滚；
- 应用目录外但仍可读：拒绝并回滚，不删除外部文件；
- 本阶段不清理任何历史旧路径，避免越权和误删。

## 6. 明确未完成边界

不得把本阶段描述成“任意图片已可直接插入”。以下仍开放：

- 超过 3000px 原图的缩放、EXIF rotation 应用、WebP lossy 85 重编码及 MIME/长度更新；
- URI/FD/Pasteboard/系统相册 caller、权限与产品 UI 入口；
- `ImageAssetLoader` 对小尺寸 EXIF 图片是否自动得到正确方向；当前没有显式 EXIF transform；
- 真实设备图片 decode、文件持久化、Undo/Redo、保存重启、导入导出/同步和视觉体验。

静态 Replay、ArkTS 编译和 HAP 打包不能代替上述设备与端到端验收。
