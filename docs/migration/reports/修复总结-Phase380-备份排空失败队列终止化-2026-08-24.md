# Phase 380 修复总结：备份排空失败队列终止化

日期：2026-08-24（Asia/Shanghai）

## 缺陷与修复

- 补审发现 `LatestWriteQueue` 失败后会保留 dirty 快照等待重试，而 `StrokePersistence.flushAll()` 使用无限循环反复
  flush 同一队列。
- 因此一个页面保存失败会让 WebDAV 整库备份在 `exportAllNotes()` 内永久阻塞，无法进入既有的本地错误分类提示。
- 现在 `flushAll()` 只做一轮 dirty 队列快照并顺序排空；任一失败立即抛给备份准备层。失败队列仍留给编辑器后续
  重试，成功队列注销逻辑不变。
