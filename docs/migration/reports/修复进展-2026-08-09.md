## 修复总纲1（第一份）：已完成修复

### ZIP 与格式链路

- F-01：`PreparedEntry` 保存 `rawSize`，Local Header 与 Central Directory 的 uncompressed size
  均写原始长度，不再重复写压缩长度。
- F-02：deflate/inflate 仅接受 `STREAM_END`；`OK` 视为缓冲不足并最多扩容重试三次，
  deflate 最终失败由 writer 回退 STORE。
- F-03：`ZipReader.parse` 改为 `{ entries, failed }`；Central Directory 损坏仍整体失败，
  单条 CRC、边界、压缩方法、加密或文件名编码问题则跳过该条并继续恢复。导入器按实际包类型
  判断 manifest/Session 是否关键，普通附件损坏返回 PARTIAL；Notability metadata 损坏时仍尝试
  从 Session 恢复。
- 新增 `ZipArchive.test.ets`：覆盖 STORE、DEFLATE、中文路径，逐字节断言 build/parse 往返一致；
  另破坏一个非关键 STORE 条目，断言其余条目仍可读取且 `failed` 精确记录损坏项。
- F-04：NSKeyedArchiver 的 UID(0) 明确解析为 nil；非标准 `$objects[0]` 记录 warning。
- F-05：自有格式恢复 `noteId/createdAt/updatedAt`，原 ID 冲突时新建带后缀副本并在结果中说明，
  不静默覆盖；Notability 导入同样恢复 UUID、时间戳与录音标志。新增“不创建默认页”的元数据
  建笔记路径，消除每次导入多出一张空白首页的问题；无冲突时自有格式页 ID 也保持不变。
- F-06：导入横向页面时交换 widthMm/heightMm。
- F-07：我方格式与 Notability 格式均按页保存；导出按页读取，不再把全部元素塞入 page_0。
- F-09：读取 Central Directory 通用标志；bit 0 条目进入失败清单并另记为 `encrypted`，
  关键条目给出“受密码保护”提示；bit 11 未置位时按完整 CP437 表解码文件名，bit 3 继续
  以 Central Directory 尺寸定位，兼容 data descriptor。
- F-10：每个 writer 条目携带合法 DOS 日期/时间，导出时使用笔记 `updatedAt`；新增
  `addDirectory`，自有格式显式写出 `pages/` 目录项及 DOS directory attribute `0x10`。
- F-17：导入读取和导出临时文件复制均循环读取到完整长度，短读抛出明确错误。
- D-17：manifest 仅拒绝比当前实现更新的版本，并用显式版本分支保留旧包兼容入口。
- D-18：`elements` 非数组时整页判损坏，不再静默改为空白页；导入器计数并显示 PARTIAL。
- F-11：binary plist 对象解析上界改为 offset table 起点，损坏对象偏移不能再越界读入偏移表。
- F-12：8 字节整数以高低 32 位组合；trailer 或对象整数超出 JavaScript 安全整数范围时明确拒绝，负数使用二补码高位计算，不再先产生已丢精度的浮点数再减 2^64。
- F-13：补齐 ordered set、URL/URL-with-base 与 UUID 标记；URL 引用和 UUID 载荷均执行对象区边界检查。
- F-14/F-16：被钳制到末页的曲线/形状使用同一个钳制后页号计算 y 偏移并记录 warning；形状 indices 非升序时按 zIndex、原始 index 稳定排序后再与曲线归并。
- F-15：发现非 `3k+1` 曲线立即停止消费锚点属性流，禁止后续 fractionalWidths/force 等数据整体错位。
- F-18：`ImportReport` 在所有返回路径提供 `missingAssets[]` 与 `warnings[]`；图片/附件、PDF、键入文本和损坏 ZIP 条目按项上报。PARTIAL 只由明确内容缺失或零笔画触发，普通诊断提示不再误降级。
- F-20/F-21/F-22/F-23：曲线 options 读取完整 u64 并对非零高位告警；扩展长度先检查 marker 边界；循环对象引用写入结构化 parser warning 并传播到导入报告；HandwritingIndex 页集合同时接受 DICT、ARRAY 与 SET。
- F-19 暂未修改：现有原版样本的 fractionalWidths/forces 全为 1 且 style 只有 3，尚无 Apple Pencil 压感样本可证明 style 到内部 InkStyle 的映射；继续维持原样比猜测映射更符合原版证据优先原则。

### 数据库与多页

- D-04：数据库版本升至 3，新增逐版本 `MIGRATIONS`，迁移在事务中执行，成功后写 `store.version`；
  初始化 Promise 去重，初始化/DDL/迁移失败不再静默形成半初始化状态。
- API 口径修正：当前 API 21 SDK 的 `relationalStore.StoreConfig` 没有 `version` 属性，编译器错误
  `Object literal may only specify known properties` 已证实。因此版本控制通过 `RdbStore.version` 实现，
  未照抄审计中会导致项目无法编译的 `StoreConfig.version` 验收项。
- D-01/R-14：`client_op` 增加 `page_id` 与复合索引；旧无页数据迁移时回填到笔记第一页，
  避免升级后历史笔迹因 pageId 不匹配而不可见。
- D-03：单页元素替换由事务包裹，使用 `batchInsert`，失败 rollback 并向上抛出。
- D-06：删除笔记改为事务，先删页/op/state 再删元数据；任一步失败均回滚并抛错。
- D-07：`PageInfo` 增加 `pageIndex`；addPage 使用 `MAX(page_index)`；重排、删页使用事务；
  删页同时删除该页元素并压缩后续页序。
- D-10：读取 `folder_id` 前用 `isColumnNull`，根目录笔记不再可能使整个列表退化为 `[]`。
- 普通 `createNote` 的元数据与默认页插入改为同一事务；`addPage` 不再吞写入异常。
- 自有格式/Notability 导入中途写入失败时删除已创建的元数据、页面和 op，避免半成品残留。
- 画布切页时先保存旧页，再加载新页、清空 Undo 与选区并重建完成层。
- 缩略图只加载首页元素。
- D-20/D-21：保留原版 `NoteAsset` 的“哈希主键 + noteIds 集合”模型；`saveAsset` 在事务内读取旧集合、按原顺序去重合并后再写，避免同一哈希被第二篇笔记引用时覆盖第一篇。查询不再对 JSON 做子串 `LIKE`，而是解析后精确匹配完整 noteId。
- 未采用审计建议的 `note_asset_ref` 新表：原版 1.0.3 的 `e47.java`、`a19.java`、`g19.java`/`f19.java` 均表明关联集合归属于单条 `NoteAsset` 记录。当前先修正该模型的原子性和精确性，避免无原版证据的结构偏移；如后续性能数据证明全表解析成为瓶颈，再以带迁移版本的索引表优化。
- D-22/D-23：`deleteAsset` 先在事务内读取可空 `local_path` 并删行，提交成功后才删除文件；文件不存在视为已清理，其他文件系统错误明确记录。`rowToAsset` 使用 `isColumnNull`，不再对 NULL 调用 `getString`，也不再把脏空串静默伪装成 NULL。
- 删除笔记现在在原有事务内精确解绑所有 `note_asset`：共享资源只移除当前 noteId，最后一个引用消失才删行；待数据库提交后再回收对应文件，杜绝悬空引用和误删共享文件。损坏的 `note_ids` 会中止并回滚删除，而不是把读取失败当作空集合继续破坏数据。
- D-08：Note/Page/Tool/Asset/Folder Repository 统一区分“正常无记录”与“数据库失败”。前者仍返回 null/空集合，后者抛出带方法上下文的错误；写操作不再只记日志后伪装成功，所有查询 ResultSet 均在 finally 中关闭。文件夹切换和标题保存补齐调用层错误处理，标题写库失败时恢复旧标题。

- D-12：远端路径逐段百分号编码；href 先做 XML/百分号解码，再规范为可下载的绝对 URL。

- D-16：密码改存 API 21 的系统 `AssetStoreKit`，设置为首次解锁后可访问、禁止同步；旧 preferences
  明文密码会一次性写入安全资产，确认成功后才删除旧键。HTTP URL 在设置页常驻警告，测试/保存
  时要求二次确认；确认结果随当前 URL 保存，URL 改动即失效，客户端层也拒绝未确认的 HTTP 请求。

  不虚构“照搬原版”的依据。

### M2-D-03 / M2-D-04：保存顺序与快速切页

- `StrokePersistence` 现在按 `(noteId,pageId)` 持有 `LatestWriteQueue`。每次保存先同步序列化为独立
  `Uint8Array` 载荷，再分配单调 revision；因此调用方随后修改 stroke/text 数组或元素对象，不会改变已入队快照。
- 单写者只执行一个事务；事务执行期间到达的多个未开始快照会合并为最新 revision。已开始的旧 revision 必须先完成，
  最新 revision 随后串行提交，旧快照不再可能晚到覆盖新快照。
- 写失败时队列把失败快照放回 pending 并保持 dirty；下一次 `flush()` 会重试。编辑器显示“笔记保存失败，请重试”，
  顶栏返回与系统返回均先等待 `flushCurrentPage()`，失败时不离开编辑页，不再伪装成已保存成功。
- 切页现在在进入异步流程时捕获 `fromPageId`、`targetPageId`、旧页深快照和 generation。旧页先 enqueue + flush，
  目标页加载完成后只有 generation 仍最新且父组件仍指向同一 target 才发布，A→B→C 时迟到的 B 结果不会覆盖 C。
- 原版数据模型证据仍以 `decompiled_1.0.3/sources/defpackage/e47.java:336-339` 为准：
  `ClientOp` 的身份属于 `(noteId,opId)`，不是脱离笔记的全局 op。当前全量页快照是 HarmonyOS 过渡实现，
  本修复只恢复原版写操作所要求的确定顺序和失败可见性，不把快照表述为完整原版 op-log。
- 新增 `LatestWriteQueue.test.ets`：延迟 revision 1 后连续入队 2/3，断言实际写入为 1、3；另注入首次失败，
  断言 dirty 保留且第二次 flush 重试同一快照。测试源已通过 `ohosTest` 编译，尚待明早设备测试流程实际执行。

### M2-D-01 / M2-D-02：复合主键与并发页号

  保留全部既有 payload/page/client_time。该定义严格对应 1.0.3 `e47.java:336-339`：
  ```sql
  CREATE TABLE IF NOT EXISTS `ClientOp` (... PRIMARY KEY(`noteId`, `opId`))
  ```

  因此同一元素 ID 出现在两个导入副本笔记时不再发生全局主键冲突。

### M2-F-04 / F-08：ZIP 安全预算、双头一致性与 Zip64
