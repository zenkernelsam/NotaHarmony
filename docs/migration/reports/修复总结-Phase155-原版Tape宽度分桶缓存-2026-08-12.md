# Phase 155 取证纠正：原版 Tape scale bucket 来自 zoom

## 原版证据

直读 `decompiled_1.0.3/sources/defpackage/qfe.java` 与 `mfe.java`：Tape pattern
缓存 key 包含 `scaleBucket = round(clamp(width, 1..8) * 2)`；bitmap 的创建尺寸按该
bucket 放大。只有 FLOWERS 的中心色额外使用 tapeColor，其他图案只使用 overlayColor。

## 结论

原先准备按 `brushWidth` 接入 scale bucket，随后继续阅读原版 `e16`/`c5g` 发现：
`qfe.a()` 的 bucket 参数是 viewport zoom。该方向已撤销，没有把错误的宽度语义留在生产代码中。
当前 Harmony renderer 契约没有 zoom，只能保留固定密度 tile；后续需先建立共享 viewport zoom
上下文，再实现原版 `round(clamp(zoom, 1..8) * 2)`。

## 验证

`d02-original-tape-pattern-scale-bucket.mjs`：`TOTAL=4 FAILED=0`。

本阶段未启动设备、模拟器、虚拟机或 Hypium；Tape zoom bucket 保留为后续真实修复项。

## 2026-08-16 后续收口（Phase 255）

Phase 255 已在可靠 viewport/page-output scale 建立后完成该 deferred 项：按原版 Float32 边界实现
`round(clamp(viewportZoom, 1..8) * 2)`，把 bucket 加入四字段缓存键，并贯穿主画布、AudioLinked、
partial eraser ordered redraw、完成层重建及缩略图。另经 `qfe.java:554` 更正：bucket 改变 cell bitmap
像素密度，不改变页面中的逻辑重复周期。详见 ADR-0233、专项 evidence/replay 与 Phase 255 Report。
