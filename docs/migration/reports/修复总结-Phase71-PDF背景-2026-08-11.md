# Phase 71 修复总结：原版 PDF Background 完整闭环

日期：2026-08-11

## 本阶段目标

严格依据 Notability 1.0.3 的 `sw9/wa0/xw9/ddg/wz9/v69/ya0`，恢复 PDF
背景的原始数据结构、页面 CRDT 语义、资产引用、同步回放、编辑器/缩略图渲染和
自有 `.note` 包往返。没有启动模拟器或真机。

## 已完成

1. 完整解码 PDFAsset：64-byte hash、文件名、MIME、uint32 fileSize、layout
   behavior、totalPageCount、pagesConsumed、pageOffset 和逐页 cropBoxes；保留原版
   默认值与范围校验，不猜测 enum 对渲染算法的额外含义。
2. PageBackground 升到 schema v2，旧 schema v1 仍可读取；IMAGE 与 PDF 共用
   AssetMetadata decoder，避免两套 hash/字符串/大小规则漂移。
3. 数据库从 v50 升到 v51，新增独立 `original_page_in_asset_winner`，并在 live
   page、远端删除归档、本地 delete checkpoint 中保存 `originalPageInAsset`。
   迁移只给原版 identity 回填 sequence index，本地 Harmony 页面保持 null。
4. CREATE_PAGE 按 `pdf.pageOffset + i` 初始化 PDF 页；非 PDF 原版页按 `i`
   初始化。MODIFY_PAGE 对目标 vector 的每一页独立写入 offset，背景与
   pageInAsset 分别进行 LWW；paper/null 背景不会清除 PDF 页码。
5. SET_METADATA 支持 note-level PDF；页面显式 null 继续解析 note fallback，且
   保留自己的 pageInAsset。NOTE_BUNDLE 使用同一套规则完成 fresh bootstrap、
   既有映射核对、winner 插入、物化和资产引用合并。
6. PDF 资产复用 IMAGE 已有 canonical/legacy key、PENDING/LOCAL、noteIds 合并和
   到达通知。metadata 或双本地路径冲突会让整个同步事务 deferred/rollback。
7. 新增 PDFKit loader，核对真实文档页数和目标页，转换 PixelMap/ImageBitmap；
   编辑器切页使用双 generation guard，退出/替换/迟到结果均释放资源。资产到达
   后主动刷新；失败时保留纸张 fallback，不阻塞笔记打开。
8. 主画布和缩略图均绘制 PDF，使用已证明的显式 margins 与 0/90/180/270 度
   rotation。layoutBehavior 只保存，不依据枚举名字臆造裁剪公式。
9. `.note` 导入导出统一收集 IMAGE/PDF 二进制资产；包页显式保存
   `originalPageInAsset`，旧包缺字段时从有效 PDF 背景兼容恢复。页结构历史升级
   NPG3，同时继续读取 NPG1/NPG2。
10. 修复审查中额外发现的持久化缺口：PersistentHistory、页面设置比较、revision
    signature、删除/恢复和 package 往返现在都把 pageInAsset 视为页面状态的一部分。

## 明早设备验收边界

需要用真实 PDF 覆盖：四个 rotation、非零 margins、不同 crop box、多页 offset、
页面级与 note-level fallback、PENDING 到达刷新、缺失/损坏 PDF、快速切页迟到结果、
缩略图刷新和反复打开退出后的内存释放。上述像素与生命周期结论不能由静态构建替代。

本阶段关闭“完整 PDF background 静态实现”批次，但不关闭总 Goal，也不把尚未证明的
layout enum 渲染差异、认证 transport 或服务端 note/site 流程宣称为完成。
