# Phase 288 修复总结：原版图片方向仿射中心

日期：2026-08-23（Asia/Shanghai）
状态：已完成静态 pivot 修复与验证；真实设备像素矩阵仍开放。

## 目标

继续补审 Phase 284～287 的方向渲染链，发现 baked orientation 的 Canvas2D transform 使用了交换后的
`orientedWidth/orientedHeight` 中心。原版 Matrix 明确使用 encoded bitmap 物理宽高中心；90/270 时这会引入
位置偏移。

## 原版证据

- `g3.java` case 6 以 `getWidth()/2.0f`、`getHeight()/2.0f` 作为 mirror 和 rotation pivot；
- EXIF mirror 先执行，rotation 后执行；
- 90/270 只创建交换物理尺寸的新 Bitmap，不改变 Matrix pivot。
完整记录见 ADR-0266 与 evidence 文件。

## Harmony 实现

- `ImageCanvasRenderer.renderImage()` 的 orientation transform 中心改为 `bitmap.width / 2` 与
  `bitmap.height / 2`；
- encoded crop clip → baked orientation → user flip → draw 的顺序不变；
- 编辑画布与缩略图继续共享同一 renderer。
