## 修复前真实缺陷

### Paste 几何错用 Duplicate 语义

`StrokeClipboard` 以 `20 * pasteSequence` 同轴平移，连续 Paste 到同一用户位置仍会逐次漂移。该规则没有原版
Paste 证据，且把 `cg2` Duplicate 的独立错开策略混进了普通 Paste。

### Cut 先改文档，再调用吞异常的 persist

Selection Cut 先删除数组、push history、重建 UI，再调用返回 `void` 的 `persist()`；`persist()` 内部捕获同步
`queueSaveElements()` 异常。因此 preparation 虽延后发布，queue/preflight 失败仍可能留下已删除 UI/history，
随后还发布新 clipboard。

### Paste preparation 只由 sequence 标识

普通 Paste 以前直接消费 sequence；第一轮 prepare/commit 改造后，commit 仍只核对 `pasteCount + 1`。如果异步
身份预留期间 clipboard 被新 Copy 替换，相同 sequence 不能证明 preparation 仍属于原 snapshot。

### Group admission 与 UI 可达性

Group Copy 会先验证整个 `selectionGroups`，无关空/损坏 Group 可让独立 Copy 失败。Paste 又以固定独立按钮呈现，
未统一到 selection native menu；页面加载与 history busy 状态也没有全部进入 live gate。

## 实际修改

### Copy preparation 与 clipboard revision

- 新增 `ClipboardCopyPreparation`、`prepareCopy()`、`commitPreparedCopy()` 与 `cancelPreparedCopy()`。
- preparation 深复制 Stroke/Shape/Text/Image/Math、element order、Group 图与 source page，但不会替换 published
  clipboard；只有当前 token 可 commit。
- clipboard 每次成功发布或 clear 都推进 revision；Paste result 保存该 revision，commit 同时核对 revision 与
  下一 sequence。
- `copy()` 保留为同步 prepare+commit 包装，既有调用方无需制造第二套语义。

### Cut/Delete future snapshot 事务边界

- Selection Delete/Cut 先收集实际存在的删除元素与原 indices，再生成 `removed*Ids`、future arrays 和
  `elementOrderAfter`；坏 selection ID 不再意外删除只有 order ref、没有实体的条目。
- 在任何 UI/history/clipboard 修改前构造 `UndoableAction` 与 `HistoryMetadata`，并用 future snapshot 调用
  `queueSaveElements(..., preserveActionBoundary=true, preparedHistory)`。
- 同步 prepare/enqueue 失败时取消 Cut preparation并返回，旧文档、选区、history 和 clipboard 全部保持。
- enqueue 成功后才发布 Cut clipboard、替换元素数组、清 selection、push prepared history、重建 layer并刷新。
- Group records 不随 leaf Delete/Cut 清除，保持原版 visibility/Undo 恢复 Group identity 的边界。

当前通用编辑器保存仍采用 optimistic serialized queue：enqueue 后的异步 RDB 失败由既有 dirty retry 与
`saveFailed` 路径处理。本阶段消除了同步 preflight/queue 失败时的假成功，但不把设备上的最终落盘与故障提示冒充
为已验证。

### 普通 Paste queue-before-apply

- `preparePaste()` 使用目标中心构造候选且不消费 sequence；严格 element-order validation 后准备单一
  `ADD_ELEMENTS` history。
- future page snapshot 先进入 persistence queue，成功后才 commit sequence/revision、应用 UI arrays 和 push
  history；queue 失败时文档/history/sequence 均不变。
- 移除显式 enqueue 后的第二次 `persist()`，避免同一 Paste 重复排队及 action boundary 被再次计算。
- 原版 Group Paste 继续走单 SQLite transaction 的 `commitOriginalClipboardPaste()`，preview 同样携带 revision。

### 用户锚点、边缘和 200ms 门

- 删除 `PASTE_STEP`；delta 改为 `targetCenter - sourceBoundsCenter`，再按页面 8 单位边距整体 clamp。
- 同一目标连续 Paste 只改变新 ID/sequence，不改变几何；边缘页面仍保持 selection 内部相对位置。
- Canvas touch down 保存 canvas-space anchor，Canvas 绑定 `ResponseType.LongPress` context menu；Selection menu Paste
  使用当前 selection bounds center。
- `canPasteClipboardNow()` 同时要求真实内容、loaded、无 loading/failure、无 history busy、loaded/current page
  identity 一致；Paste 请求增加原版 200ms concurrent suppression。
- `SelectionOverlay` 移除固定/独立 Paste 按钮，只在可用时向原生 selection menu 追加 Paste item。

### 可达 Group 子图

- Group map 允许保存 unrelated candidates，但递归到 selected root 时要求该 ID 恰有一个合法 Group。
- 可达空 Group、重复 ID、Group/leaf ID 冲突、缺成员、环、多父和非根 top Group 继续 fail closed。
- unrelated 空/损坏 Group 不再阻断独立叶或另一棵合法 Group Copy。

## 边修边审发现并修复

- 首次增量 `note@default` 暴露 ArkTS 禁止匿名对象类型与无显式类型对象字面量；新增
  `PendingClipboardCopy`/`PreparedClipboardState` 显式接口后通过。
- 普通 Paste 已显式 enqueue prepared history，却仍调用一次 `persist()`，会重复排队；本阶段删除该调用。
- 三份旧 replay 锁死 Cut 的“直接 splice 当前数组/直接从 this.elementOrder 删除”实现细节；future-snapshot
  重构后改为验证 next arrays、prepared queue 与 apply 顺序。
- 原版系统 clipboard 在内部 `mg2.a` 为空时还可读取受支持图片。Harmony 当前仅有内部元素 clipboard；该功能
  登记为后续 M2-R-08 缺口，不在没有平台/设备验收时伪造完成。
