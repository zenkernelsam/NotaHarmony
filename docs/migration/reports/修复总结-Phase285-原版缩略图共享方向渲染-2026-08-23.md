# Phase 285 修复总结：原版缩略图共享方向渲染

日期：2026-08-23（Asia/Shanghai）
状态：已完成静态接线与验证；真实设备图片矩阵仍开放。

## 目标

Phase 284 已让编辑画布使用 EXIF orientation/mirror 元数据，但补审发现 `ThumbnailRenderer` 的图片分支
没有传入这两项数据。库页缩略图会退回默认 `(0,false)`，造成页面显示正确而缩略图旋转/镜像错误。本阶段
修复该遗漏，并确认原版共享解码路径不会这样分裂行为。

## 原版证据

- `g3.java` case 6 对 JPEG/WebP/HEIC/HEIF 读取 EXIF Orientation；
- orientation `2/4/5/7` 水平镜像，rotation 来自 `w34.l()`，90/270 交换 bitmap 物理宽高；
- `nx0.java` 调用 `new g3(this, 6)`，说明异步加载工厂复用同一解码回调。
完整记录见 ADR-0263 与 evidence 文件。

## Harmony 实现

- `ThumbnailRenderer.renderThumbnail()` 继续通过 `ImageAssetLoader` 加载图片资产；
- 图片元素分支把 `asset.orientationDegrees` 与 `asset.mirroredHorizontally` 显式传给
  `ImageCanvasRenderer.renderImage()`；
- 编辑画布与库页缩略图共用同一 geometry/transform 实现；
- 不修改持久化 intrinsic dimensions、AssetHash、CREATE_BLOCK、cropRect 或资产文件。
