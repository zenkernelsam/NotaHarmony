# 修复总结 — Phase 562：原版笔记视图夜间模式

日期：2026-09-22

## 原版行为（硬证据）

`r22.java` 渲染笔记编辑器设置区；case 1 挂载开关行：

- `feature_settings__note_view_night_mode` — "Note view night mode"
- `feature_settings__note_view_night_mode_caption` — "View your notes
  (paper and ink) with a dark appearance"

说明文案明确语义：深色外观作用于**笔记视图内的纸张与墨迹**，而非全局
主题。运行时消费者在 native/混淆代码中（反编译不可见），可移植契约是
持久化开关 + 笔记视图内纸张墨迹深色渲染。

## Harmony 落地

- `EditorSettingsStore.ets`：新增 `noteViewNightMode` 偏好键
  （`noteEditorSettings` store），接口新增
  `getNoteViewNightMode`/`saveNoteViewNightMode`，复用共享
  `getBooleanPref`/`saveBooleanPref` 辅助（mutex + flush 失败回滚语义
  不变）。默认 `false`（原版默认无真值表证据，已登记差异）。
- `SettingsPage.ets`："Note editor" 区新增开关行，标题 + 原版说明文案
  同时渲染；沿用乐观更新 + 失败回滚 + lifecycle-generation 防过期
  （`setNoteViewNightModeEnabled`）。
- `NotePage.ets`：`@State noteViewNightMode`；`aboutToAppear` 经
  `applyNoteViewNightModeSetting()` 读取偏好（专用
  `nightModeGeneration` 在 `aboutToDisappear` 失效，防止过期异步写
  状态）。`resolveTokens()` 在开关开启时解析 `'dark'` —— 编辑器
  chrome 走 DarkTheme；该状态以 `nightMode` prop 传入画布。
- `NoteCanvasView.ets`：新增
  `@Prop @Watch('onNightModeChange') nightMode`；`resolveTokens()`
  同样按 `'dark'` 解析；纸张渲染路径本就经由 `resolveTokens()`，
  因此 `PaperRenderer` 自动消费
  `theme.paperBackground`/`theme.paperLineColor` 的深色值。
  watcher 触发 `renderFrame(true)` 全量重绘纸墨。

## 登记差异 / 限制

- 原版默认值无证据，按 opt-in（关）处理。
- 覆盖在 token 解析层生效（`'dark'` 替代存储主题模式），chrome /
  画布 / 纸张渲染统一变深；不动全局主题。
- 原版在 native 侧的具体实现不可见；本落地以"纸张与墨迹深色外观"
  的可移植语义为准，详见 ADR-0533。
