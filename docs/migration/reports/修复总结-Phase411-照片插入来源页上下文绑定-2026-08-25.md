# Phase 411 修复总结：照片插入来源页上下文绑定

## 问题

照片选择器和剪贴板图片导入都会经历较长的系统交互与解码等待。入口虽然保存了页代和页 ID，但真正的 `insertOriginalPhotos()` 在 await 后重新读取 `loadedPageId`、generation、纸张宽高、viewport zoom 和画布中心。若用户在等待期间切换页面或改变视口，图片可能写入新页，几何也会按迟到状态计算。

## 修复

现在新增不可变的 `OriginalPhotoInsertOrigin`，并在异步开始前统一捕获来源页身份与几何。照片路径在选择器返回后先执行 stale return；剪贴板路径在可用性探测、授权和导入前解析右键锚点或视口中心。持久化计划、pending draft、history action 与 durable commit 全部使用同一 origin。

当持久化已完成而页面再次过期时，保留数据库结果但记录错误并跳过 history push、内存投影和选区发布。失败 toast 依旧只在来源上下文有效时显示，`photoImportBusy` 保持 finally 清理。

## 验证

- ArkTS 检查无错误；既有警告不变。
- 专项来源绑定 Replay 12/12 通过。
- 加强后的照片 ingress disposal Replay 9/9 通过。
- 照片入口状态、picker caller、immediate decode 相邻 Replay 通过。
