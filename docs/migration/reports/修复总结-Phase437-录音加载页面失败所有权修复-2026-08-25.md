# 修复总结 — Phase 437 录音加载页面失败所有权修复

日期：2026-08-25

## 问题

Phase 436 让页面失败路径递增录音代际，阻止过期录音续体覆盖失败投影。但旧录音请求的 `finally`
也依赖同代检查清理 `recordingsLoading`；失效后清理被跳过，而页面失败路径没有接管该状态。若失效前
已有请求把 loading 置真，失败界面会留下永久加载指示。

## 修复

当前代页面失败在递增录音代际后立即显式清除 `recordingsLoading`，再重建页面和录音失败投影。旧续体因此
完全惰性；`loadRecordings()` 内部的同代 finally 清理语义保持不变，只有页面恢复后新启动的请求才能再次
置位。

## 验证

新增专项 Replay `d02-recording-loading-page-failure-ownership-bound.mjs`，锁定“递增代际 → 清理 loading →
失败投影”的顺序与同代 finally 边界，结果 3/3。既有页面失败代际 Replay 继续通过。其余全量验证见总进展
补录。未启动模拟器、虚拟机、真机或 Hypium。
