# Phase 201 修复总结：WebDAV 批次应用补偿回滚

## 发现

Phase 169/ADR-0174 已让远端校验失败对象被隔离，并允许其余已验证对象恢复，但应用阶段仍逐篇落库。若第 N 篇硬失败，前 N-1 篇会永久保留，恢复操作既非批次一致，也无法明确告诉用户是否已经清理。

继续边修边审还发现三项同源缺口：失败的单篇导入清理若未成功，`ImportReport` 会丢掉残留 note ID；仅标题 metadata-only PARTIAL 创建和公开补偿删除没有进入 `NoteImporter.importMutex`，可能与另一场导入交叠 RDB 事务；资产可用 hub 会永久保留已删除笔记的 generation 键。资产通知不是数据权威，但陈旧键会形成无界缓存残留。

## 修改

- 新增 `BackupBatchApplier`，将已验证对象作为一个应用级单元串行导入
- `SUCCESS`/`PARTIAL` 才可提交，且必须返回新、非空、未重复的本地 note ID
- 任一硬失败后逆序删除本次创建的所有可追踪笔记；一个删除失败不会阻止后续补偿
- 区分 `ROLLED_BACK` 与 `ROLLBACK_INCOMPLETE`，未知残留或删除失败绝不误报完整回滚
- `NoteImporter` 在自身清理失败时返回残留 note ID，并提供幂等 `removeImportedNote()`；删除报错后查询确认已不存在则视为成功
- metadata-only PARTIAL 创建和公开补偿删除统一进入导入 mutex；已持锁的单篇失败路径使用内部清理，避免非重入锁自锁
- `BackupPage` 使用显式 ArkTS nominal adapter 接入协调器，并新增中英文完整/不完整回滚提示
- 笔记删除成功后清除 `AssetAvailabilityHub` 的 note generation；资产引用仍在事务内解绑，最后引用文件在提交后且仍持有资产 mutex 时删除，封闭 hash 被并发复用后遭旧清理误删的窗口
- 新增 Hypium 测试、批次原子应用 replay，并加强恢复校验门、资产到达 replay
- 顺带修正 `d02-asset-cloud-persisted.mjs` 的历史版本漂移：数据库早已在提交 `1974343` 升至 v62，旧 replay 仍写死 v61
- 新增 ADR-0178

## 原版与平台边界

Android 原版 1.0.3 没有 Harmony WebDAV/Backup 批次恢复对应实现，因此本阶段不能伪称逐行移植。原版仍用于约束 `.note` 内容、身份和单篇导入行为；跨篇恢复一致性依据 Harmony 现有事务、资产文件和 UI 协议实现。

## 未闭环

应用级补偿无法提供进程崩溃时的 durable rollback journal；真实 WebDAV 服务端、磁盘满、文件删除失败和恢复中途杀进程仍需设备/故障注入。构建仍有大量既有 deprecated API 与“Function may throw exceptions” warning，后续继续按总纲和原版证据边修边审。Goal 保持 active。
