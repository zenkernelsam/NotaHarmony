# Phase 300 修复总结：图片粘贴入口串行化与复查

## 缺陷

Phase 299 的可用性复查在设置 `photoImportBusy` 前等待异步 promise。快速第二次点击可在复查窗口内通过同一
门禁，导致重复权限请求、读取和插入竞争。

## 决策与实现

入口先同步占用 `photoImportBusy`，再在 try 内执行当前 MIME probe。probe false 或异常时清除
`systemClipboardImageAvailable` 并返回；后续点击被统一门禁拒绝。只有复查通过才进入 READ_PASTEBOARD gateway、
Pasteboard 数据读取和 WebP lossy 85 规范化。finally 确保占用释放。

## 验证

- 剪贴板专项 Replay 保持 23/23，并将断言收紧为“busy 先于 probe、probe 先于 permission”；
- 双 HAP 与全量 Replay 结果见总进展验证补录；
- 未启动模拟器、虚拟机、真机或 Hypium。

## 开放项

真实快速点击矩阵、系统剪贴板高频变化和厂商兼容行为仍需设备验收；`T-042` 继续严格留到 Goal 最后一项。
