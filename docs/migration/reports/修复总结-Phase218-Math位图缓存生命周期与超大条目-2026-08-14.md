# Phase 218 修复总结：Math 位图缓存生命周期与超大条目

## 发现

Phase 217 恢复公式框适配后继续检查 `w18/v18/p18` 的位图所有权，确认 Phase 149 所称的“4 MiB LRU 和
PixelMap release”尚未完整接线：

- `MathCanvasRenderer.clear()` 没有任何生产生命周期调用者；
- 主编辑器离开时会 dispose layer/stroke/pencil 资源，却保留 Math cache；
- 缩略图 renderer 被 LibraryPage 退休时也不释放 Math cache；
- cache clear/eviction 只 release PixelMap，不 close ImageBitmap；
- 单张纹理若超过 4 MiB，会先进入 cache、被 LRU 自己淘汰释放，随后同一帧继续拿该 entry 绘制。

前四项造成跨页面 native 图形资源滞留；最后一项会直接导致超大公式空白、无效对象访问或平台绘图异常。

## 原版与 Harmony 适配依据

- 原版 `w18` 使用 4 MiB LRU，`v18` 按 RGBA 字节数计费。
- 原版 `p18` 在 native draw 失败时立即 recycle 临时 Bitmap。
- Harmony 纹理由 `ImageBitmap` 和 `PixelMap` 两层对象组成，必须显式结束两层所有权。
- `LibraryPage.retireThumbnailRenderer()` 已持有缩略图刷新 mutex 后再 dispose，不会与活动 render 并发清 cache。

## 修复

- 保持 4 MiB 原版缓存预算。
- 新纹理按字节数分流：
  - 不超过上限时加入 LRU 并正常淘汰旧条目；
  - 单张超过上限时不进入 cache，仅作为当前帧 transient texture。
- transient texture 在 `drawImage()` 完成后的 `finally` 中释放，避免先释放后绘制。
- transform/draw 改为 `try/finally`，绘制异常也会 restore Canvas 状态。
- 新增统一 `releaseTexture()`：
  - 尝试 `ImageBitmap.close()`；
  - 无论 close 是否异常都继续 `PixelMap.release()`；
  - LRU eviction、cache clear、transient release 共用同一路径。
- `NoteCanvasView.disposeRenderingResources()` 新增 `mathRenderer.clear()`。
- `ThumbnailRenderer.dispose()` 新增 `mathRenderer.clear()`。
- 新增 `d02-math-bitmap-cache-lifecycle.mjs`，锁定原版容量/字节证据、超预算分流、draw-before-release、双层
  资源释放、编辑器/缩略图生命周期接线和桌面 LRU 模型。
- 新增 `ADR-0195-math-bitmap-cache-lifecycle.md`。
