# Phase 122 修复总结：原版 Group 组合、解组、出站与持久历史

## 原版证据与纠错

- 复核原版 `dsc/ux9/dhb`：Group/Ungroup 分别是选择菜单命令 4/5。Group 只接受 drawn
  selection，将直接实体与已选 Group 分别作为 member unit，单位数至少为 2；Ungroup 只接受一个
  Group，不删除其叶子实体。
- 对照原版 payload 20/21：CREATE_GROUP 携带完整 member vector，Group 身份取 CREATE operation
  identity；MODIFY_GROUP 携带目标 Group 与完整替换 vector。当前本地组合使用 type 20，解组沿用既有
  type-25 Group visibility，Undo/Redo 在同一 Group identity 上 delete/undelete。
- 沿用 Phase 113 已完成的 Group 层序 authority：Group 的 zIndex 取 CREATE clientTime，顶层 Group
  作为整体排序，内部叶子保留自身 zIndex；解组后恢复各 member unit 的原有层序。

## 已完成修复

- 新增严格 type-20/type-21 FlatBuffer writer，拒绝空成员、重复成员、非法 operation identity 和超预算
  vector。新增 authoring resolver，从选择叶子中剔除已选 Group 的递归叶子，再把 Group ID 作为一个
  单独 member unit，支持嵌套 Group 与直接实体混合组合。
- `SelectionOverlay/NoteCanvasView` 新增条件化 Group/Ungroup 菜单、忙状态保护和选择保持。Group 成功后
  继续选中全部叶子并选中新 Group；Ungroup 后继续选中叶子但清除 Group metadata。
- `StrokePersistence` 新增 create/ungroup/history 三条公共事务路径。它们先 flush、校验原版 live page 与
  精确 before order，再经生产 reducer 写原版 operation、upload-immediate journal、Group state、页面层序
  与历史 companion；任一失败整体回滚。
- 新增 `NGM1` Group history codec、`GROUP_ELEMENTS` action 和 PersistentHistory materialization。
  PUSH/UNDO/REDO 跨重启保留 affected Group、完整 before/after order 和同一 actionId；损坏 zIndex、成员集合
  变化、stale Group state 或 CREATE member vector 不一致均拒绝执行。
- 边修边审补上 NGM1 的规范 zIndex 校验，避免编码器把损坏的持久历史静默正规化。
