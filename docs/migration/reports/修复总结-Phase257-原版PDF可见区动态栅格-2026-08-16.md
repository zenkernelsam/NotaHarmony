## 原版与平台证据

- `sba.java:162-190`：把请求 page rect 做并集，只按并集宽高乘输出倍率分配 ARGB bitmap；空请求返回 null。
- `sba.java:14`：原版共享 renderer 有 80 MiB 级 cache，但该总缓存值不能直接当成 Harmony 单张 PixelMap 上限。
- `iy9.java:391-405`：页面缩放与 consumer scale 共同进入 `PDFDraw.SetDPI()`；rotation 为 90 度档。
- `iy9.java:408-495`：cardinal inverse mapping、顶部坐标转 PDF 底部坐标、一个输出像素边缘扩张、clip 后 raster。
- `ba6.java:2225-2243`：0/90/180/270 四种矩形映射公式。
- Harmony PDFKit：`PdfMatrix.y` 从底边计量，矩形单位为 Points；`getAreaPixelMap()` 分别接收 clip matrix 和
  输出 bitmap 宽高。

详见 `docs/migration/evidence/original-pdf-visible-region-raster-jadx-sdk-2026-08-16.md`。

## 实际修改

### 栅格计划与预算

- 新增 `PdfRasterPlan.ets`：
  - page-space 可见区裁到页面，扩张 25% overscan 与一个输出像素；
  - inverse-map 四种背景 rotation，margins 形成 PDF content rect；
  - 独立计算 PDF Points matrix 和 Canvas local destination rect；
  - 顶部原点 y 转为 PDF 底部原点 y；
  - 输出尺寸使用原版正数 `Math.round`；单边 4096、总像素 8,388,608（RGBA 约 32 MiB）hard cap，
    round 后若仅因整数乘积略超预算则收敛到最大安全倍率。
- `CanvasViewport.visibleCanvasRect()` 成为 screen→page 可见区的共享入口。

### Loader、主画布与缩略图

- `PdfBackgroundLoader.load()` 接受可选 `PdfRasterRequest`，优先调用 `getAreaPixelMap()`；matrix rotation 固定 0，
  由既有 Canvas transform 独占背景旋转。
- 区域 API 抛错时回退默认整页 PixelMap；page/document 与 bitmap/pixelMap 所有权继续按 ADR-0234 释放。
- `PaperRenderer` 可把 cropped bitmap 画到其 page-space destination，不再假设每个 bitmap 都代表完整 content rect。
- `NoteCanvasView` 使用 `viewport.zoom × vp2px(1)`，120 ms debounce；手势结束、画布 ready/resize 立即复核。
  reraster 完成前保留旧图，generation guard 丢弃迟到结果，成功后交换并释放旧资源。
- `ThumbnailRenderer` 使用 300×400 fitted scale 请求 raster，不再加载默认整页后缩小。

## 边修边审发现并修复的新问题

第一轮 coverage 仅比较 `request.outputScale` 与历史 `requestedOutputScale`。当全页 8× 请求因 32 MiB 预算实际
只能生成约 2× raster 时，plan 仍记录“请求过 8×”；随后缩进到小区域，即使该区域已经能够在预算内达到 8×，
旧逻辑也会误判为无需更新，永久复用低清概览。

现改为计算“新 overscan 区域在同一 hard cap 下可达到的实际倍率”，再与旧 plan 的 `rasterScale` 比较：

- 小区域能获得更高倍率时重新 raster；
- 当前请求本身仍受预算封顶时，新 plan 会达到相同 bounded scale，不会形成 0 ms refresh loop。

ArkTS fixture 与 replay 均新增该回归门。

最终静态复核还发现背景模型允许 margins 恰好吃满 source width/height；这是合法的“无 PDF 可画区域”，
第一轮 planner 却以 `>=` 判为异常。现改为返回 null raster，保持普通纸张背景可用；同时 planner 独立拒绝
负数或非有限 margins，避免绕过模型入口的调用把畸形 geometry 传进 PDFKit。fixture 已覆盖两种边界。
