# Phase 128 修复总结：既有空 Text 与兼容文本编辑恢复

## 原版证据与新发现

- 原版 `awb.o()` 的 ReplaceRange 先对选区调用 `u5j.F` 删除字符，仅当替换字符串长度大于 0 时才
  调用 `s5j.i` 插入。因此把既有 Text 全部删空会生成 REMOVE_CHAR(S)，保留同一 Block identity，
  不走 type-25 删除 Block。
- Phase 127 已证明新建 Text 的空 INSERT 不合法，但“新建空草稿”和“既有 Block 清空”原本被同一个
  `text.length === 0` 分支错误合并。
- 边修边审还发现 Phase 125 回归：所有既有 Text 都强制进入 original CRDT preview。旧版 Harmony
  opaque-ID Text 没有 `original_block_state`，预览必然失败，导致这类历史内容无法再编辑。

## 已完成修复

- 空字符串取消条件收窄到 `editingOriginalTextBlock === null`，只影响尚未提交的新 Text。
- 既有 canonical Text 允许 after `""` 进入严格预览和既有 type 9/10 writer；所有 live 字符变 hidden，
  Block、层序、历史 identity 与后续 Undo/Redo 保留。
- 既有 opaque-ID Text 明确走 compatibility snapshot 编辑，恢复普通 `updateText`、REPLACE_ELEMENT
  Undo/Redo 与保存能力。
- canonical ID 但原版 page/Block/character/style state 不完整时仍拒绝提交，不以 compatibility fallback
  掩盖同步损坏。
- ADR-0104 增补 Phase 128 correction，避免其“空字符串取消”边界继续被误读为既有 Block 语义。
