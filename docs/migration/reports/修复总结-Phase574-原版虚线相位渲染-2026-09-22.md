# 修复总结 Phase 574 — 原版 DASH/DOTS 虚线相位渲染修正

- 日期：2026-09-22
- 类型：渲染保真修复（审计缺口清单 1.1，`Canvas2DStrokeRenderer.ets` 补审）
- ADR：ADR-0545
- 证据：`docs/migration/evidence/original-dash-phase-render-harmony-2026-09-22.md`
- Replay：`d02-original-dash-phase-zero.mjs`（16 断言）

## 背景

审计缺口清单把 `Canvas2DStrokeRenderer.ets`（462 行）列为最高优先未审
文件，挂起两条线索：高亮混合模式疑似近似、虚线参数未与原版比对。本 Phase
完成该文件与 decompiled_1.0.3 渲染层的系统对照。

## 原版证据

- `c5g.g`（实时笔画）与 `e16`/`p16.centralPathPaint`（持久笔画）两处
  DASH/DOTS 渲染均用 `DashPathEffect({2w,1w}`/`{0.001w,2w}`，**相位恒为
  字面量 `0.0f`**。
- `yyd` StyleMap 的 `backingDashPhase@12`/`backingDashPeriod@16` 全部
  读取点只流入 `rz1.H` → `l06.phaseOffsetPx`（RAINBOW/GLITTER 特效
  相位），从不进入 PathEffect。
- `ft1`/`uyd`/`o8j` 的切片相位推进只更新持久字段（特效连续性簿记）。
- `c5g` 构造器五画笔表：DASH=BUTT/ROUND、DOTS=ROUND/MITER、实线
  ROUND/ROUND，全部 SRC_OVER。
- `zx1.e(color, 107)`：高亮 = alpha **覆盖** 107，非 blend-mode。

## 修复内容

`Canvas2DStrokeRenderer.renderCenterPath`：移除
`setLineDashOffset(styleMap[0].backingDashPhase % period)`——该应用是
ADR-0012 时代的待验证假设，现证实原版渲染从不消费该字段。对
backingDashPhase ≠ 0 的切片/导入笔画，Harmony 之前会把虚线图案沿路径
偏移，与原版不一致；新建笔画（phase=0）无可见差异。

## 核对一致项（无需改动）

- 虚线/点间隔 `[2w,1w]`/`[0.001w,2w]`：逐项一致。
- cap/join：DASH→butt、DOTS→miter、其余 round：逐项一致。
- 高亮 alpha 覆盖 107（替换而非相乘）+ SRC_OVER：精确一致——审计
  「混合模式近似」疑点澄清为误报。
- `renderInkFill` 半透明填充排除 clip ≈ `e16.clipOutPath`；
  `renderCustomPath` DASH/DOTS clip→中心线 ≈ `e16:186-190`。
- `OriginalInkPartialEraser.remnantStyleMap` 切片相位推进式与 `ft1`
  完全同式（`(base+start) % period` 包绕，period=3w/2.001w）。
