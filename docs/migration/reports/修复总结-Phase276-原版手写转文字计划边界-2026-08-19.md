## 2. 原版 1.0.3 结论

直读 `xsc.java`、`bt1.java`、`jc5.java`、`u5j.java`、`bmb.java`、`fqa.java`、`qed.java` 后确认：

1. `xsc.v()` 要求选区实体全部属于同一 page；空选区或跨页会直接失败。
2. `xsc.j()` 合并选中实体的 world bounds；宽或高小于 `8.0f` 时在对应轴两侧居中扩展到 8；
   没有有效 bounds 或 page frame 时不产生转换目标。
3. page frame 的 origin 与 selection bounds 一起返回；`bt1` 创建 Text 时使用
   `selectionTopLeft - pageOrigin` 作为相对 origin，并传入 union size。
4. `bt1` case 2 在同一 `xq9` transaction 里严格执行：
   `u5j.l(DELETE_ENTITIES)` → `u5j.f(CREATE_BLOCK TEXT)` → `s5j.i(INSERT_STRING)`。
5. `u5j.f` 的 optional transform 通过 bitmask 省略，故原版该路径创建 identity-transform Text，
   而不是把 page origin 当成额外 transform。

## 3. 边修边补审：当前持久层不能安全承载混合 mutation

现有 `OriginalDeleteEntitiesOperationApplier`、`OriginalCreateBlockOperationApplier` 和
`OriginalInsertTextOperationApplier` 各自具备 transaction 内 reducer；`StrokePersistence` 的
`writeOriginalCreateText()` 也能处理“快照只新增一个 reserved Text（CREATE_BLOCK + INSERT_STRING）”。

但“删除多笔原版 Ink + 新增 Text + 写入识别字符串”不是当前 `singleReservedOriginalCreate()` 的
输入形状。generic snapshot fallback 也只会写当前快照和一条 page mutation，不能自动维护：

- 删除 Ink 的 type-25 visibility winner/archive；
- 新 Text 的 type-22 block state 与 type-8 insert identity；
- 三步共享 transaction 的 original history/Undo 语义。

因此本阶段没有把菜单或 provider 接入 `queueSaveElements()`，避免产生删除已落盘而 Text/operation
未完成的半原子状态。这是安全收缩，不是“转文字已经上线”。

## 4. 实现内容

新增 `note/src/main/ets/core/adaptation/OriginalHandwritingConversionPlanner.ets`：

- 要求选区非空、ID 唯一且无歧义、stroke 可见、bounds 有限且方向有效；所有 stroke 必须属于
  同一 page frame；每个失败都有结构化 `OriginalHandwritingConversionRejectReason`。
- 复现原版 union bounds 与每轴 8-unit 最小扩展，输出 page-relative `textOrigin`、width、height；
  记录 page origin、source IDs、page generation 和 source fingerprint。
- OCR Promise 回来时精确比较 page ID、generation、source fingerprint；页面切换、重载、选区变更、
  source revision 变化、空结果或超大结果均 fail closed。
- 只有 caller 已取得不与源 Ink 冲突的新 Text ID 且 OCR 结果仍新鲜时，才生成纯逻辑 mutation：
  `DELETE_ENTITIES → CREATE_BLOCK → INSERT_STRING`；文字（含前后空白）原样保存。
- 模块不修改 UI、SelectionTool、RDB、history 或 provider；不存在伪造 operation identity 的路径。
