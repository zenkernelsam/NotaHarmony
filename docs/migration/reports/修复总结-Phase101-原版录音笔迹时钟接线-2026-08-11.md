# Phase 101 修复总结：原版录音笔迹时钟接线

## 原版证据

- `kt1.d()` 在首个笔迹输入创建 transient CREATE_INK 时调用 `vcj.b(ckb, "ink.create")`，将返回值作为
  `wq9.audioTime`；后续 ADD_PATH 沿用同一时刻，而不是在抬笔时重新取时钟。
- `vcj.b()` 仅在 recorder active 且非 paused 时返回时钟。主 recorder 的值为 `wr8.j + wr8.e()`：
  `wr8.j` 是 start 成功后的 wall time，`wr8.e()` 用 monotonic uptime 计算并扣除暂停区间。
- CREATE_INK 虽有 nullable uint32 `audioDuration`，但实时 `kt1 -> u5j.g` 构造路径最后一参明确为
  `null`。因此不能因为播放 reducer 支持 duration，就自行给本地实时笔迹伪造时长。

## 已完成修复

- `OriginalRecordingCaptureController` 新增同步 `getCurrentAudioTime()`：按 wall start 加去暂停 monotonic
  elapsed 生成安全十进制时间；录制中、尚未完成的 pause/stop 过渡遵循原版 active flag，暂停、恢复过渡、
  idle/failed/released 返回 null。边修边审补上了 STOPPING 可从 PAUSED 进入的分支，避免暂停后点 Stop 的
  瞬间误关联新笔迹。
- session controller 只转发该时钟并在 release 后封闭；`NotePage -> NoteCanvasView` 使用同步回调，使画布在
  touch-down 当刻读取 controller，不使用约 100 ms 刷新的展示 snapshot，避免 audio-ink 固有偏移。
- `StrokeSession` 在 begin 时冻结 audio start，并贯穿实时 preview 与最终 `StrokeElementData`。页面 snapshot、
  undo/redo 和既有 JSON persistence 会自然保真该字段；加载时的原版 operation hydration 只补缺失字段，不会覆盖它。
- 本地实时笔迹不写 `audioDuration`，严格遵循已验证的原版 live CREATE_INK 路径。暂停期间或录音停止后的新笔迹
  不带 AudioLinked 元数据。
- 新增 capture、session、stroke ArkTS 覆盖、ADR-0078 与专项 replay。调查中用 JADX fallback 补读了普通
  反编译跳过的 transient 提交链，并据此纠正了最初“需要计算 duration”的假设。

## 验证

- 专项 replay：`recordingInkClock=touch-down-active-unpaused-no-fake-duration`。
- 全量桌面 replay：`TOTAL=87 FAILED=0`。
- 执行 `hvigor clean` 后，`note@ohosTest` 与 `note@default` assembleHap 均为 `BUILD SUCCESSFUL`；
  仅有项目既有 warning。
- 未启动模拟器、虚拟机或真机，未执行设备 Hypium；真实麦克风、codec、pause/stop 竞态和播放显隐像素仍待设备验收。

## 剩余边界

本阶段关闭本地 capture clock 到笔迹 snapshot 的静态生产闭环，但不虚报私有 CREATE_INK outbound writer、上传/ACK
或跨设备同步。真实录音时间与 AVPlayer callback 的对齐、录音中跨页面绘制和动画像素仍需集中设备测试。Goal 保持 active，
继续边修边补审。
