# 修复总结 — Phase 439 WebDAV 备份成功顺序修复

日期：2026-08-25

## 问题

WebDAV 备份成功后，`BackupPage.backupAll()` 先执行 `setLastBackup()`，再检查生命周期代际。若页面在该
await 期间销毁或新一代备份操作已接管，过期续体仍会把完成时间写入持久存储；并且它绕过 `return` 前的
正常收尾路径，导致 `backupOperationLease` 不释放，后续云备份/恢复永久提示占用。

## 修复

将目标绑定的 last-backup 写入移到成功续体的当前代门禁之后，再更新界面。所有失败、异常和过期分支都
统一落入 `finally`，重置忙碌状态并释放共享租约。批次发布、manifest 读回校验、恢复导入回滚和配置
快照语义不变。

## 验证

新增专项 Replay `d02-webdav-backup-success-order-bound.mjs`（3/3），锁定两个云操作的 finally 租约释放，
以及“发布 → 当前代门禁 → 持久化 → UI”的成功顺序。其余全量验证见总进展补录。
