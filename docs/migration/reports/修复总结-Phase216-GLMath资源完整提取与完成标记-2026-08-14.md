# Phase 216 修复总结：GLMath 资源完整提取与完成标记

## 发现

Phase 215 在枚举剩余单次 `fileIo.writeSync()` 路径时，定位到数学引擎 rawfile 提取仍偏离原版协议：

- 每次启动直接覆盖 `filesDir/glmath`，没有原版的 `v1` 版本目录；
- 没有 `.complete`，进程中断后无法区分完整资源与部分资源；
- 每个资源只写一次且忽略 `writeSync()` 返回值，正数短写会被当作成功；
- 写入后虽执行文件 `fsync`，但不校验最终长度和普通文件身份；
- 危险路径会被静默跳过，剩余文件仍可继续初始化；
- 提取失败不清理已经写出的文件，下一次会在未知混合状态上继续覆盖。

这会让 native GLMath 收到截断字体、缺失配置或跨版本混合资源，公式功能可能整体初始化失败，也可能只对特定
字符或版式产生隐蔽错误。

## 原版对照

`decompiled_1.0.3/sources/defpackage/s18.java` 明确实现：

- 资源目录为 `filesDir/glmath/v1`；
- 完成标记为 `v1/.complete`；
- 标记缺失时先清理未完成版本，再递归提取 asset `glmath`；
- 文件通过 `l96.i0(..., 8192)` 循环复制到 EOF；
- 所有资源成功后才创建 `.complete`；
- 只有完成版本目录才传给 `GLMathNative.nativeInit()`。

因此本阶段恢复的不是一个可选缓存细节，而是原版防止部分资源被使用的提交协议。

## 修复

- `OriginalMathEngine` 恢复 `glmath/v1 + .complete`：
  - marker 是普通文件时才复用版本目录；
  - marker 无效时清理 `glmath` 根，兼容迁移旧无版本布局；
  - 完整提取全部资源后才创建、同步并验证 `.complete`；
  - 只有完成目录才传给 `initializeNative(root)`。
- 每个资源采用 64 KiB 完整写入循环：
  - 按 `writeSync()` 实际返回值推进；
  - 拒绝零、负数或大于请求长度的进度；
  - 精确保留 `Uint8Array.byteOffset/byteLength`；
  - 完整写入后执行 `fsyncSync()`；
  - 关闭后验证普通文件身份与最终字节长度。
- 保留并加强资源预算：文件列表必须非空且不超过 128 项，总字节数必须是安全整数且不超过 16 MiB。
- 相对资源路径改为逐 segment 门禁；空路径、绝对路径、反斜杠、空 segment、`.` 或 `..` 会使整个提取失败，
  不再静默跳过后发布不完整集合。
- 提取任一步失败立即清理整个部分资源树，下一次初始化可从干净状态重试。
- 递归清理重新验证直接子路径，使用 `lstatSync()` 区分符号链接；链接只删除自身，不跟随到目录外。
- 更新 native 数学引擎 replay，并新增完整资源提取 replay，锁定原版协议、版本和 marker、短写循环、同步与
  长度门禁、路径检查、失败清理、符号链接边界及桌面故障模型。
- 新增 `ADR-0193-original-math-resource-complete-extraction.md`。

## 未闭环与真机待测

- 首次启动准备资源，在单文件正数短写、零写、磁盘满、`fsync` 失败、close 失败及 marker 创建失败处分别注入
  故障，确认 `glmath` 部分树被清理且下次启动可重试。
- 在资源提取中途和 `.complete` 创建前后分别杀进程，确认 native 永远不会接收没有有效 marker 的目录。
- 从旧版已存在的 `filesDir/glmath` 无版本目录升级，确认旧资源被清理并一次性迁移到 `glmath/v1`。
- 用原版公式样本覆盖普通文本、上下标、分式、根式、矩阵、希腊字母、长公式与异常 LaTeX，核对初始化、测量、
  baseline、位图尺寸和视觉输出。
- 后续若 rawfile 中的字体、配置或 parser 数据发生变化，必须提升 `RESOURCE_VERSION` 并验证旧版本迁移；不能
  依赖覆盖已有 `v1`。
