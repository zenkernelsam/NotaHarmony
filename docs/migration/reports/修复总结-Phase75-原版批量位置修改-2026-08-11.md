# Phase 75 修复总结：原版批量位置修改

日期：2026-08-11

## 问题

原版 payload type 24 `MODIFY_POSITIONS` 可以在一个 operation 中混合修改多种元素。此前 Harmony
没有该路由；若简单逐项调用既有 reducer，会让同页 revision 重复推进，并可能在后项缺失、状态分歧或异常时留下
前项半写。另一个边修边审发现的问题是 operation root 的 transient 标志此前被统一 reducer 忽略，交互预览有被
写入正式模型的风险。

## 原版证据

- `je8/ie8` 表明 payload field 0 是非空 modification vector；每项包含 required target、成对出现的
  page/origin、nullable rotation、nullable scale 和可选 uint64 zIndex。
- `v69/ba6/ddg` 表明同一 target 不可重复，全部 target 会先解析；同一 payload 可混合 Ink、Shape、Block、Group，
  四组位置 register 各自按 operation identity 做 LWW。
- operation root field 3 是 transient 标志，不能把交互过程状态当作正式同步结果持久化。

## 修复

- 新增 `OriginalModifyPositionsOperationApplier`，严格完整解码 vector、target、page/origin、nullable setter 和
  uint64 zIndex；空 vector、重复 target、未知字段、非有限几何及不成对 page/origin 均在写前 deferred。
- 全部目标先按真实持久化状态分类：Stroke 必须同时具备 `original_ink_state`，TEXT/IMAGE/MATH 必须具备
  `original_block_state`；缺失、kind/state 分歧及 Shape/Group 使整个 payload deferred，不部分应用。
- 在固定 SQLite savepoint 内逐项复用既有 Ink/Block reducer。任一子 reducer deferred 或抛错都会回滚此前所有项。
- 新增共享 `OriginalPageMutationBatch`：各子 reducer 先记录受影响页面，全部成功后每页只推进一次 revision，
  并合并 Ink/Text 搜索失效；standalone MODIFY_INK/MODIFY_BLOCK 未传 batch 时保持原行为。
- type 24 已接入统一 standalone 与 NOTE_BUNDLE 的 preflight/apply 路由；bundle 会收集所有显式 destination page，
  为被引用的最终归档页建立稳定绑定。
- 统一 standalone 路由、type 24 直接入口和 NOTE_BUNDLE 均拒绝 transient operation，避免预览态污染正式模型。

## 验证

- ArkTS fixture 覆盖两 target 解码、page/origin、nullable clear、uint64 最大值、重复 target、不成对字段，及
  同页 Ink+Text 只推进一次 revision。
- 新增 `d02-modify-positions.mjs`，覆盖混合 Ink/Block、层序、nullable clear、幂等、stale/tie LWW、缺失/Shape
  写前拒绝、第二子 reducer deferred 后全回滚、异常回滚、transient 零写及 NOTE_BUNDLE/归档页接线。
- 全量桌面 replay：`TOTAL=62 FAILED=0`。执行 `hvigor clean` 后，`note@ohosTest` 与
  `note@default` 均 `BUILD SUCCESSFUL`；构建仅保留仓库既有 warning。
- 按约束未启动模拟器/真机，未执行设备 Hypium。

## 尚未宣称完成

本阶段只关闭 Ink 与 TEXT/IMAGE/MATH Block 的 durable type 24 回放。Shape/Group 尚无经原版证据闭环的
Harmony 持久化 reducer，因此包含它们的整个 payload 仍安全 deferred；transient 还需要独立的非持久交互层。
其余 payload、私有 transport 和真机验收继续后续批次。
