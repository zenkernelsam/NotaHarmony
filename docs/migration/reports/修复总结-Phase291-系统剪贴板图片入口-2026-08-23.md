# Phase 291 修复总结：系统剪贴板图片入口

日期：2026-08-23（Asia/Shanghai）
状态：已完成静态修复与验证；真实设备权限和兼容性验收仍开放。

## 目标

接手后审计当前工作树中的系统剪贴板图片雏形，确认它是否对应原版能力，并闭环生产入口、锚点语义、
失败反馈和可验证边界。

## 审计结论与缺陷

原版 Android 通过 ClipboardManager 判断 `image/*`，在 Paste 菜单把内部元素与 `ClipboardImage` 分流，
并使用用户坐标调用专用 handler。Harmony 已有无调用者的 Pasteboard/WebP 雏形，但存在四个缺口：

1. 长按菜单没有生产 caller；
2. 计算出的 `target` 没传入插入计划；
3. 所有失败静默，只有日志；
4. 没有 ArkTS fixture、Replay、证据、Report 和总纲记录。

## Harmony 实现

- 新增 `OriginalClipboardImageIngress`：仅接受 `MIMETYPE_PIXELMAP`；尺寸非法拒绝；PixelMap 在 finally
  释放；输出 WebP lossy 85 并沿用 100 MiB 上限。
- 长按菜单在无内部元素内容时提供图片 Paste；有内部内容时保持既有语义优先。
- 插入路径显式传递 `clipboardPasteTarget`，复用单图 durable asset transaction 与 history。
- 失败显示现有“无法添加图片”toast，不再静默。

## 验证

- 新增专项 Replay：`d02-original-clipboard-image-ingress.mjs`；
- 新增 `OriginalClipboardImageIngress.test.ets`，覆盖空剪贴板、超大尺寸、资源释放和测试 reader 复位；
- ArkTS Check 对新增/触达文件无 Error；全量 Replay、clean 双 HAP 与静态检查见总进展补录；
- 未启动模拟器、虚拟机、真机或 Hypium。

## 明确未闭环

- `READ_PASTEBOARD` 权限提示、拒绝降级和跨应用剪贴板兼容性需要真实设备；
- 原版 handler 内部反编译失败，不声称逐行复刻其解码/缩放细节；
- 大图内存性能、色彩像素、Undo 后重绘与端到端体验仍开放。
