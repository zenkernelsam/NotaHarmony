# 修复总结 — Phase 444 原版 EXIF 水平镜像集合修复

日期：2026-08-26

## 审计范围

复核 Phase 284 引入的显示图像方向链，并对照 Android 原版共享解码器
`g3.java` 的 EXIF 方向矩阵。

## 缺陷

原版把 Orientation 数值 2、4、5、7 统一标记为水平镜像，并在旋转前应用
`postScale(-1, 1)`；Harmony loader 只识别 `'2'`，导致 4、5、7 图片显示时
丢镜像。SDK 还允许返回文本方向标签，旧内联比较没有统一归一化入口。

## 修复

新增共享纯函数 `originalExifMirrorsHorizontally()`，先 trim/lowercase 再
锁定 `'2' | '4' | '5' | '7'`；`ImageAssetLoader` 改用该函数生成
`mirroredHorizontally`。四分之一旋转映射、大图缩放、编码裁剪、用户翻转和
持久化字节不变；渲染仍按原版“先旋转后镜像”的组合矩阵进入用户变换。

## 变更证据

新增 ADR-0416、Harmony evidence、中文 Report 与专项 Replay
`d02-original-exif-mirror-set-bound.mjs`（10/10）。旧的方向渲染 Replay 已
从单方向断言升级为共享助手契约；ArkTS fixture 覆盖 2/4/5/7 正例和 1/3/6/8
负例。真实设备像素输出仍开放，不在本阶段冒充运行态结论。
