# Phase 217 修复总结：原版 Math 框内自适应与编辑几何保真

## 发现

Phase 216 恢复 GLMath 资源发布协议后，继续对照原版 `s18/p18/g18/w18` 审计公式运行时，确认真实 parser 已接入，
但公式尺寸语义仍没有移植完整：

- renderer 对所有 Math block 固定使用 20px 字号；
- 位图虽然与 block 等大，公式内容本身不会按框放大或缩小；
- 插入以 20px 测量，只向下压到 `240x120`，不会像原版一样把小公式放大到限制轴；
- 编辑新 LaTeX 后同时修改 `blockWidth/blockHeight/bounds`；
- 底层 latex-only classifier 明确只接受 LaTeX 字段变化，因此尺寸一旦变化，提交就会被拒绝。

最后一项不是纯视觉差异，而是会让用户输入合法公式、点击完成后仍收到失败状态的功能 bug。

## 原版对照

- `s18.d()`：`floor` 框宽高，以最大边作为初始字号测量，再按两轴最小比例适配；最终字号 `floor`、输出宽高
  `ceil`。
- `p18.invoke()`：按完整 block 创建位图，并把 `s18.d()` 返回的字号交给 `nativeDraw()`。
- `g18.j()`：插入固定以 `240x120` 为最大框，使用返回的 fitted width/height 创建并居中 Math block。
- `g18.i()`：编辑只提交 LaTeX setter，不重新测量或修改 block geometry。
- `w18`：缓存完整尺寸输入，测量与绘制分阶段执行。

## 修复

- `OriginalMathInsertPlan` 新增原版纯适配算法：
  - 框宽高先 `floor`；
  - 初始测量字号为最大边；
  - 适配比例取宽高两轴最小值；
  - fitted font 取 `floor`，宽高取 `ceil`；
  - 非有限、非正或零字号结果 fail closed。
- `OriginalMathEngine` 新增 `fit()`：先 native measure，再计算 fitted font/width/height。
- `render()` 改为内部执行两阶段适配，调用方不能再注入固定字号。
- `MathCanvasRenderer` 删除 20px 常量，主画布与缩略图都按 block 尺寸自适应。
- Math 插入改为直接对 `240x120` 调用引擎 fit，并用返回宽高创建 block。
- Math 编辑改为：
  - 用既有 block 宽高做 parse/fit 门禁；
  - durable 变更只写 `after.latex`；
  - 不再修改宽、高、bounds 或 transform；
  - 保持 latex-only classifier、type-23 field 10、事务和 Undo/Redo 契约。
- 更新 ArkTS fixture，覆盖初始字号、向下缩放、小公式放大、框尺寸取整和非法测量。
- 新增 `d02-original-math-box-fit.mjs`，锁定原版证据、Harmony 接线、latex-only 几何保真及运行时数值模型。
- 新增 `ADR-0194-original-math-box-fit-rendering.md`。
