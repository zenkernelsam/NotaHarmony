# 修复总结 — Phase 445 跨页历史失败租约释放修复

日期：2026-08-26

## 审计范围

复核 Phase 442 引入的页面操作三重门禁与 `NoteCanvasView.performHistory()` 的跨页
undo/redo 等待窗口，重点验证 `historyPending` 在所有切页终态下能否释放。

## 缺陷

`historyPending` 只在目标页成功加载并由 `resumePendingHistory()` 处理后释放。
如果切页过程中持久化或加载失败，catch 会恢复源页快照或进入加载失败态，但不会通知
父组件清除租约。此后 `runPageOperation()` 因 `historyPending === true` 永久拒绝
add/delete/move/background，页面管理被锁死。

## 修复

`resumePendingHistory()` 的异常退出分支现在在丢弃 pending 方向的同时调用
`onPageHistorySettled(false)`；`switchPageData()` 的 catch 路径也会清理残留的
`pendingHistoryDirection` 并发布 settled=false。成功路径继续自动执行挂起历史；
删除租约、标题飞行计数和页面结构互斥不变。

## 变更证据

新增 ADR-0417、Harmony evidence、中文 Report 与专项 Replay
`d02-cross-page-history-failure-release.mjs`（10/10），并新增
`CrossPageHistoryRelease.test.ets` 锁定失败释放模型。真实设备切页中断矩阵继续
开放，不在本阶段冒充运行态结论。
