# Phase 233 修复总结：有界完整文件 I/O 与短读比较

## 发现

接续 Phase 232 对生产 `readSync()` 做全仓复核。现有 8 个调用点均已使用返回值并循环推进，F-17 所述
“单次读取后忽略长度”已经修复；但进一步发现：

- Note 导入、Note 导出和图片资产读取仍按全部剩余长度创建临时缓冲；
- Note 导出在完整 `data` 尚存时，又从临时文件构造第二份完整 `bytes`；
- 图片已有文件比较会构造完整 `actual`，图片写入则反复 slice 全部剩余字节；
- 录音资产和系统 Backup 比较要求左右两次 `readSync()` 的单次返回长度相等，会把不同合法短读节奏误判为
  内容冲突。

这些路径在小文件上通常不显现，但大 `.note`、高分辨率图片、长录音或 picker/network-backed URI 会放大
内存峰值与短读差异。

## 原版依据

- `jv5.f()` 使用 8192-byte `BufferedOutputStream` 接收 URI。
- `fag.z()` 使用固定 `byte[8192]` 循环读取，并按实际 `i` 写出。
- 原版资产路径 `re0.g()` → `fag.y()` → `l96.i0(..., 65536)`，以固定 64 KiB 缓冲持续复制并同步计算
  SHA-512。
- 上述实现都不会按完整剩余文件重新分配缓冲，也不会把两条输入流的一次 read 分段视为内容身份。

## 修复

- `NoteImporter.readFileFully()`：
  - 增加长度合法性检查；
  - 每次最多读取 64 KiB；
  - 拒绝零、负数和超过请求长度的返回值。
- `NoteExporter.exportToFile()`：
  - 验证临时文件长度仍与导出 `data` 一致；
  - 临时文件同步落盘后立即清空完整 `data` 引用，不跨系统 picker 等待保留大数组；
  - 删除第二份完整归档读取；
  - 新增 `copyFileFully()`，从临时文件向 picker 目标有界流式复制；
  - 每个实际读取视图继续交给已有完整短写循环，随后 `fsync`。
- `ImageAssetPackageStore`：
  - 读取与写入均限制为 64 KiB 精确视图；
  - 写入校验异常超长进度；
  - 已有文件改为流式逐块比较，不再创建完整 `actual`；
  - 比较前后保留长度门禁。
- `OriginalRecordingPersistence` 与 `NoteBackupAbility`：
  - 新增逻辑块读满 helper；
  - 左右文件分别处理短读后再比较同一完整块；
  - 保留原有句柄关闭、冲突失败与快照发布门禁。
- 更新 Note 导出 replay，新增统一有界文件 I/O replay 与 ADR-0210。
