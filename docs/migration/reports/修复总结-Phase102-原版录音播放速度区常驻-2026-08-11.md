# Phase 102 修复总结：原版录音播放速度区常驻

## 原版证据

- 原版 `n05.a()` 在录音列表之后无条件显示 `Playback speed` 标题并调用 `n05.b(kpa.b, ...)`；该路径不依赖
  当前是否选中录音。
- `n05.b()` 遍历 `wna`，而 `wna` 只有 1x、1.5x、2x 三档。速度是播放器会话选择，可在下一次播放器
  prepared 前预设，不是选中某条录音后才存在的属性。

## 已完成修复

- 将 `RecordingPanel` 的累计 seek 时间轴与播放速度区拆开：时间轴仍只在存在选中录音时显示，播放速度标题和
  三档分段按钮则始终显示。
- 补齐中英文 `Playback speed / 播放速度` 资源；保持原版三档，不添加无证据速度。
- 面板固定高度同步增加常驻控制区所需空间，避免用录音列表原有可见空间来支付本次修复。
- 新增纯显隐判定测试、ADR-0079 和专项 replay。

## 边修边审发现

- Phase 101 留下的本地 CREATE_INK outbound 不能只靠追加 FlatBuffer 完成：原版笔迹实体 ID 等于 CREATE_INK
  操作 `(timestamp, siteId)`，而 Harmony 当前 `StrokeSession` 使用随机 ID；本地新页也尚无原版 page sequence
  identity。必须先统一 page/ink 的预分配身份，再写原版 payload，否则会在本地和同步端制造两个不同实体。
