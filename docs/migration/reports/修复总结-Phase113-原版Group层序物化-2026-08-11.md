## 已完成修复

- 数据库升至 v61，`original_group_state` 新增严格 uint64 TEXT `z_index`。新 Group 保存
  `operation.clientTime`；旧 v60 行仅从同 identity、payload 20 的
  `original_applied_operation_time.client_time` 精确回填，无 timing 的旧行保持 null 并保守拒绝排序。
- 新增 `OriginalGroupLayering` 统一层序模块：过滤 visibility tombstone；同一 member 多父 Group
  取 operation identity 最新者；递归到顶层；检测循环、损坏 identity、重复实体和缺失 Group zIndex；
  输出 Group 单元与连续叶子 ranks。
- CREATE Ink/Block/Shape、MODIFY Ink/Block/Shape、普通实体 delete/undelete 均改用同一 Group-aware
  排序。CREATE/MODIFY_GROUP 和 Group delete/undelete 会重排 live/archive 原版页面；只有实际顺序
  变化才推进 content revision，并同步使搜索索引失效。
- Create Ink/Block/Shape 在任何 reducer 写入前完成完整层序规划，避免 deferred 半应用；后续并发或
  覆盖差异抛错，由 inbox 外层事务整体回滚。
- `StrokePersistence` 的本地层序 writer 已从“Group 页面一律 fallback”升级为原版单元模型。
  `cfc case 8/9` 使用 Group zIndex 参与 uint64 运算，但历史和 type-24 payload 只包含可写实体；
  PUSH/UNDO/REDO 继续复用 v60 的精确 before/after 映射。
- NOTE_BUNDLE 的 Shape/Group 前后状态签名纳入 nullable Group zIndex，legacy 精确回填不会被误报为
  批次无变化。
- UI 递归解析 `selectedGroupIds` 的全部叶子。纯 Group 命令不创建伪历史；混合选择只移动未分组
  Stroke/Shape/Text/Image/Math，并把选中 Group ID 传给原版 writer，Group 叶子不再被错误拆开。
