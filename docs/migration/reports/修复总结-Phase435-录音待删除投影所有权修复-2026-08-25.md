# 修复总结 — Phase 435 录音待删除投影所有权修复

日期：2026-08-25

## 问题

录音删除提交续体在 await 删除与重载后仍执行 `this.pendingRecordingDeleteIds = []`。该赋值越过
`OriginalRecordingDeleteController` 的权威状态：若 A 提交期间用户请求删除 B，控制器已发布 `[B]`，
A 的后续续体会把 B 从页面投影中整体清空，导致撤销窗口显示错误。

## 修复

移除提交续体中的整表清空。待删除 UI 投影只由控制器监听器写入；控制器在自己的 finally 中按
“pending.delete → commits.splice → publish”的顺序清理本任务拥有的 ID 并发布权威快照。加载和监听器的
`editorDisposed` 守卫、失败提示路径均不变。

## 验证

新增专项 Replay `d02-recording-delete-pending-ownership-bound.mjs`，断言监听器唯一写入、提交续体不再
触碰 pending 投影、控制器清理顺序和 request 发布边界，结果 5/5。既有 followup 与 commit disposal
Replay 同步为新语义。其余全量验证见总进展补录。未启动模拟器、虚拟机、真机或 Hypium。
