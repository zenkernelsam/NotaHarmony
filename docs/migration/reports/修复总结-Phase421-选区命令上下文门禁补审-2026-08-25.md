# Phase 421：选区命令上下文门禁补审

## 结论

Phase 421 是审计型阶段：复核 Phase 420 之后剩余的选区命令入口，确认 Math 编辑、图片裁剪和 Ink 样式/颜色/
宽度命令不会消费空选区、非选区工具状态或工具栏显示值。未发现新的行为缺陷，因此不做生产代码修改。

## 审计范围

- `startMathEditing()` 与 `selectionCanEditMath`。
- `startImageCrop()`、`canCropImageSelection()` 与 crop session。
- `modifySelectedInkRegisters()` 的工具门禁与 SelectionTool 目标来源。
- 原版 `itc`、`dhb` Edit Math 分支、`v07` style popover 与 `zh9`/`wj9` 修改回调。

## 关键判定

Math 编辑的 capability 不是纯 UI 标志：它要求单一 canonical Math 且排除所有其他实体。入口还会重新查找 block
并验证 operation identity。图片裁剪入口同样重新调用完整 capability 函数并创建 session。Ink 命令的目标来自
SelectionTool，而不是 NotePage 用于回显的颜色/宽度/样式寄存器。

原版证据显示 Edit Math 从当前 Tap state 读取单个 Math block，style/color 操作也从当前 selection controller
状态过滤对象。Harmony 的实现方向一致。
