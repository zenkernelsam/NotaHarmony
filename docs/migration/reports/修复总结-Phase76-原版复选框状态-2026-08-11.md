# Phase 76 修复总结：原版复选框独立状态

日期：2026-08-11

## 问题

原版 payload type 28 `UPDATE_CHECKBOX` 此前没有进入 Harmony 的统一回放路由。现有渲染器还把
所有 checkbox decorator 固定画成空框，即使以后接收 checked 状态也无法显示。更重要的是，原版已废弃
paragraph style 内的旧 `isChecked` 字段；若把 checked 直接塞进普通样式操作，字符插入、删除、恢复或
样式重算后会丢失或串到错误段落。

## 原版证据

- `mqf/lti`：type 28 的字段是 required TextField、required stable location 和 bool isChecked；
  false 是 FlatBuffer 默认值，字段缺席仍表示一次明确的 false 更新。
- `e4c`：payload 转为 `bl2(operationId, location, Boolean)`，证明它是以稳定 location 为 key、
  operation identity 为 LWW winner 的 RichText 独立 map。
- `v69`：先解析 TextField target，再进入对应 RichText reducer；目标缺失应重试/deferred。
- `he8` 明确写着 `isChecked is deprecated, use UpdateCheckbox`；`lj3` 证明 checked 状态可在当前
  decorator 不是 checkbox 时继续存在，不能因暂时不可见而删除。

## 修复

- 数据库升至 v53，新增 `original_text_checkbox_state`。主键锁定 note、Block 与稳定字符 location，
  bool 和 winner timestamp/site 独立保存；note-scoped winner unique 约束阻止同一 operation identity
  被改用于另一 location。
- 新增 `OriginalUpdateCheckboxOperationApplier`。严格解析 inline TextField/location、默认 false、
  canonical bool 与未知字段；TextField 和 location 必须解析到同一个 live/archive/hidden Text Block。
- reducer 完整实现 stale no-op、site tiebreak、exact retry、同 identity 改 Block/location/value 冲突，
  并在快照分歧或目标缺失时零写入 deferred。
- RichText 物化增加 checkbox state 输入。只有当前 paragraph decorator=3 时才把 `isChecked` 写进
  快照；非 checkbox 样式下只推进 CRDT 状态，不推进 page revision。以后改回 checkbox 样式会恢复值。
- INSERT_STRING/INSERT_CHAR、REMOVE/REVIVE 和 MODIFY/CLEAR_STYLE 的 before/after 物化全部读取该状态，
  避免字符结构或样式变化把 checked 丢掉。隐藏字符与 hidden entity 继续保留独立寄存器。
- Canvas 测量和实际绘制统一消费 checked：false/缺省绘制 `☐`，true 绘制 `☑`。
- type 28 已接入 standalone 和 NOTE_BUNDLE 的 preflight/apply；外层现有 transient 拒绝和 bundle
  transaction 继续保证不把交互预览持久化，也不产生半包写入。
