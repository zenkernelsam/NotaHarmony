# Phase 109 修复总结：原版本地批量 Ink 样式修改

## 原版证据

- 原版 `zg9` 是 `OnBrushStyleClick`，`ti9` 将它交给 case 27；`zh9.u` 从当前选区分别筛选 Ink 与
  Shape，并明确排除 Pencil。
- 对全部选中 Ink，原版只调用一次
  `u5j.q(..., null, null, l2f.a(style), 28670)`。`u5j.q` 验证实体、求共同 page/origin 后调用
  `o0j.a`，写入 type 17 MODIFY_INK 的 target field 0 与 style field 5。
- style 存在时原版同时给 field 12 写空 style-map vector。`u5j.q` 的 color/width 参数分别对应
  fields 6/7，但这一条生产调用只传 style，因此本阶段没有把 color/width 选区编辑虚报为已接线。

## 已完成修复

- Selection 工具托盘新增 Mono/Taper/Dash/Dot 四种原版样式入口；命令只改当前选中 Ink，不污染下一笔
  的工具预设。Pencil 与 tool-5 partial eraser 不参与样式修改。
- 一次命令批量替换全部可用选中 Ink，清空旧 styleMap，并记录一条 `TRANSFORM_STROKES` before/after
  action；Undo/Redo 保持相同 entity IDs，持久历史继续由 page mutation companion 恢复。
- 新增严格 snapshot classifier：元素身份与顺序必须完全相同；变化项只能是 canonical、非 Pencil、非
  partial-eraser Ink；全部目标必须共用同一 style；把旧 payload 仅替换 `inkStyle` 并设
  `styleMap=[]` 后必须与新 payload 逐字节相等。任何路径、transform、mask、工具、颜色、宽度、effects、
  timing 或 metadata 混改都会回退并写 v59 guard。
- 新增 19-field MODIFY_INK encoder。整批目标只写一条 type 17 operation，经既有 LWW reducer 物化；
  upload-immediate outbound、snapshot reconciliation 与 Harmony history companion 在共享 mutex/单事务中
  提交，defer、revision/append/reconcile 故障全部回滚。
- 边修边审修复 stroke snapshot clone 丢失 `isPartialEraser`、`originalCreate`，以及把 optional
  `undefined` 强制改成 `null`/空数组的问题，避免历史或样式编辑夹带实体身份和 tool 语义变化。

- 专项 replay 输出：
  `localModifyInkStyle=original-batch-style-map-history-rollback`。
- 全量桌面 replay：`TOTAL=95 FAILED=0`。
- 第一次 clean 严格编译暴露 5 个被增量缓存遮蔽的既有 ArkTS 类型错误：
  `OriginalAddPathElementsOperation` 不再通过可选索引访问声明 cubic/splat 数组类型，改用明确的
  `CubicSegment[]`/`PencilSplatPoint[]`；`OriginalModifyInkOperation.StoredPageTarget` 显式继承
  `OriginalMutationPageTarget`。修复后重新执行完整门禁。
- `hvigor clean` 后严格串行构建 `note@ohosTest` 与 `note@default`，均为 `BUILD SUCCESSFUL`；两套 unsigned
  HAP 均已落盘。默认包只有项目既有 warning，没有 ArkTS error。
