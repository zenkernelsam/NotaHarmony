# Phase 115 修复总结：原版单步前移/后移层序出站

## 原版证据与边修边审更正

- 原版 `dhb` 把四个层序命令严格分开：case 6/7 调用 `py(..., 26)` 单步前移/后移，case 8/9
  才调用 `cfc(9/8)` 置于顶层/底层。
- 继续直读 `zh9/rsc/ssc/py/x0j/w0j` 后确认，`py case 26` 不是把整个选择簇平移一层，而是让每个
  未分组选中实体检查原始有序列表中的相邻 unit；相邻项也被选中便跳过。因此连续多选可能只移动边界实体。
- 相邻未分组实体交换精确 zIndex；相邻 Group 时只把选中实体写到 Group zIndex 的后一位或前一位，Group
  自身及内部叶子均不改。被选 Group 明确不可移动，并会阻止混合选择中的直接实体跨越它。
- 由此发现 Harmony 的实际可见错误：菜单文字已经是“前移一层/后移一层”，handler 却调用置顶/置底算法并发送
  `BRING_FRONT/SEND_BACK`，单击一次会直接跳到页面边缘。

## 已完成修复

- `OriginalGroupSelection` 新增严格层序 unit 解析：按最新父 Group 身份向上归并到顶层，拒绝循环、重复实体及
  非连续 Group 叶子，保留 Group 内部现有顺序。
- `PageElementOrder` 新增 `movePageElementRefsOneStep()`：以未修改的源 unit 列表判定每一条相邻边界，支持混合
  Stroke/Text/Shape/Image/Math，多组选中边界分别交换；跨 Group 时整体跨越，选中 Group 或 grouped leaf no-op。
- `NoteCanvasView.reorderSelected()` 改用单步算法，并发送新的 `BRING_FORWARD/SEND_BACKWARD` hint。到达前后边界、
  纯 Group 选择或无有效交换时不写 Undo、不触发保存。
- `StrokePersistence.createOriginalZOrderHistory()` 逐项复刻 `py case 26`：普通邻居双向交换精确 uint64 zIndex；
  Group 邻居只重写选中实体，向后在 0 饱和；目标原版排序必须与即时画布快照逐元素一致，否则保守拒绝。
- 继续复用 v60 `original_local_z_order_history`。PUSH 在同事务写精确 before/after vector；Undo/Redo 跨重启读取同一
  actionId，并先校验当前 source-state。type-24 reducer、upload-immediate journal、snapshot、history 与 companion
  任一失败均整体回滚。
- Phase 112 的置顶/置底实现没有删除；四种命令现在具有不同 enum 和 replay 边界，避免以后再次混淆。
