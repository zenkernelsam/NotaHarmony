# Phase 311 修复总结：异步历史应用页面绑定

日期：2026-08-23（Asia/Shanghai）

## 背景与缺口

Phase 310 已把普通 persist、选区、Paste 和 Group/Ungroup 的迟到结果绑定到发起页。本轮继续补审发现
Undo/Redo 自身的异步应用仍存在同类跨页风险：`historyBusy` 只阻止新的历史命令，不阻止页面切换。
`switchPageData()` 可在原版 Group、剪贴板粘贴、局部擦除、手写转文字或普通元素组等待持久化时推进
generation，随后旧页结果可能安装到新页。

具体风险包括替换数组/分组、取消选择、重建层并渲染、修改原笔迹资格、刷新图片资源，以及把新页置为
`saveFailed` 并弹出旧页失败反馈。

## 实现

- 在每条异步历史路径首次 await 前捕获 `pageLoadGeneration` 与动作的发起 `pageId`。
- 新增统一谓词 `isHistoryPageContextCurrent()`：要求生命周期活跃、generation 匹配、发起页等于
  `loadedPageId/currentPage.pageId`、页面已加载且没有加载中/失败状态。
- 持久化成功保持全局权威：已提交事务继续推进 Undo/Redo 并通知栈；若上下文已过期，记录
  “durable history remains available” 后直接返回，不再安装可见文档/渲染状态。
- 迟到失败保留 hilog 诊断，但只有同页健康上下文才调用 `reportSaveFailure()`，避免污染新页。
- 普通元素组在 `flush()` 前后和 `saveHistoryGroup()` 后复查；同页失败才回滚快照、刷新图片并报告，
  跨页失败不触碰新页数组或渲染。
