# Phase 103 修复总结：原版录音面板关闭生命周期

## 原版证据复核

- 重新追踪原版 `i5h.h` 的 Compose 回调后确认：`ujb.a` 位于 Record 控件的状态切换中；检测到
  `pjb` 活动录音时发送 stop，否则同一控件发送 `new tjb()` start。这不是工具箱 close 回调。
- 全局搜索原版 1.0.3 后，另一处 `ujb.a` 只存在于 `b49` 的同类 active/inactive Record toggle。
  原版可见源码中没有“隐藏 Recording toolbox 即 stop”的第三条路径。
- 原版编辑器 `u49` 还通过 `z39(xjb, 0)` 注册独立录音命令，而 `z39` 发送 `new tjb()`；这进一步
  证明 recorder 由编辑器/session 持有，不应绑定到某一个面板是否可见。

## 已完成修复

- `NotePage.closeRecordings()` 现只关闭 `showRecordings`，不再 stop/save 活动录音，也不会把尚在
  preparing 的 start 排队取消。用户可以继续书写并录音，重新打开面板后仍可 Pause/Resume/Stop。
- 离开编辑器的 `finishAndRelease()` 与 `aboutToDisappear` 幂等兜底保持不变，因此真正离开 note 时
  仍会停止、保存并释放有效 capture，不会丢失录音。
- 将 session 单测名称从“close-time stop”纠正为“explicit stop serialization”；mutex 的竞态保证
  本身仍保留，只是不再用错误的面板关闭语义解释它。
- 修正 ADR-0076 和 Phase 99 总结中的历史误判，新增 ADR-0080 与独立 replay，避免后续继续把 bug
  当成原版行为锁死。

## 剩余边界

本阶段纠正的是面板可见性与 recorder 生命周期的关系，不宣称已完成设备端麦克风、codec、系统音频
路由、权限 UI 或后台策略验收。录音音源选择仍需先核实原版 `DEVICE_ONLY` 后端和 Harmony 可实现性；
本地 CREATE_INK outbound 仍受 page/ink operation identity 前置约束。Goal 保持 active，继续边修边补审。
