# Phase 203 修复总结：WebDAV 整库导出快照最终复核

## 发现

M2-B-02 已有批次目录、对象校验和 manifest 最终发布，也会在每篇 `.note` 导出前后检查 revision；但这
仍不能保证整批来自同一资料库状态。笔记 A 完成导出后，在 B/C 仍生成期间发生变化，旧流程不会再次
检查 A，最终却可能把旧 A 与新 B/C 标成同一次完整备份。

继续边修边审还发现两个收尾问题：本地 `flushAll()`、数据库快照或摘要失败会被备份页误报为服务器不
可达；新加入的静态保存队列注册表若只在显式 flush 时清理，会长期强引用已经自动保存完毕的页面队列。

## 修改

- 备份前排空所有进程内页面保存队列，并以全局入队 generation 拦截导出期间的新编辑
- 用一条 note/page SQL 原子读取初始整库状态，保留每篇导出前后 revision 门禁
- 全部 ZIP 完成后再次原子读取整库，并比较笔记集合、可见元数据、结构 revision、页面状态、内容
  revision 与元素数量
- revision 改为固定长度 `v2:<SHA-256>`，避免多页状态直接撑大 manifest
- `structure_revision` 进入签名，使原版 note-level `SET_METADATA` 背景、标题及页面结构变化可被感知
- `LatestWriteQueue` 增加 idle 回调；成功排空立即从静态注册表注销，失败队列保留待重试
- 本地导出准备与 WebDAV 发布异常分层：快照变化、一般准备失败、网络/服务器错误各自提示
- 历史笔记 `createdAt == 0` 保持可导出，与原版元数据表及 Harmony `OpStoreImpl` 的时间边界一致
- 新增 `BackupSnapshotGuard` Hypium 测试、队列 idle 测试、双语资源和专项 replay
- 新增 ADR-0180，记录原版证据、Harmony 扩展设计和资产故障注入边界

## 原版与平台边界

Android 原版 1.0.3 没有 WebDAV 批次导出实现。本阶段严格参考原版 `RawLibraryStateDatabase_Impl.java`、
`defpackage/e47.java` 与 `defpackage/cha.java` 中独立保存的笔记 ID、标题及创建/更新时间语义，但最终整库
复核属于 Harmony WebDAV 扩展的可靠性协议，不能伪称直接移植原版备份代码。

资产写入在摘要校验后原子发布，正常应用路径不会原地覆盖既有 hash 文件。本阶段没有在整个 ZIP 构建
期间持有资产互斥锁，也没有把 `note_asset` 行或资产内容摘要直接加入最终 revision；外部同大小替换、
文件系统损坏和设备级删除竞态仍需故障注入验证。
