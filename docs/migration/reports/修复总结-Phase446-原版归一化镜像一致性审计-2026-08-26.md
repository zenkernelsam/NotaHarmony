# 修复总结 — Phase 446 原版归一化镜像一致性审计

日期：2026-08-26

## 审计范围

复核 Phase 444 显示镜像修复是否应同步进入 `normalizeOriginalImageBytes()`，
重点对照 Android 大图归一化 `vuh.b()`、EXIF 读取 `w34.l()` 和共享显示解码器
`g3.java`。

## 结论

原版只有在图片超过 3000px 时才重编码。该路径读取 `w34.l()` 后仅执行
`postRotate(90/180/270)`，从不执行水平镜像；重编码后的 WebP 不保留 EXIF，
因此后续显示也无法通过 `g3.java` 补回镜像。这是原版自身的视觉限制。

Phase 528 复审后，Harmony 现在完全一致：超大图重编码只旋转、不镜像；阈值内
即使有非零 EXIF 旋转也保留原始字节和 EXIF，由 Phase 444 的显示 loader 完整
处理 2/4/5/7。若在 normalization 中额外补镜像，反而会偏离原版语义。

## 变更证据

本阶段新增 ADR-0418、Harmony evidence 与专项 Replay；Phase 528 将 Replay 扩展
到 13/13，并修正小图 rotation-only 误重写，锁定“显示链补镜像、持久化归一化
不补镜像”的一致性边界。
