# Phase 202 修复总结：WebDAV 跨实例操作租约与备份目标身份

## 发现

`BackupPage.isBusy` 只能约束单个组件实例。页面重建、返回再进入或同时存在两个路由实例时，本地导入、
导出、云备份和云恢复仍可能并发。`WebDAVSettingsPage` 保存配置也不在同一互斥边界，能够在正在备份的
客户端背后改写目标。

继续边修边审发现两个同源缺陷：设置页原先要等“不安全 HTTP”确认框结束后才置 `isTesting`，确认期间
可以重复点击并弹出多个确认框；`webdav_last_backup` 只保存一个全局时间，改服务器、用户名或备份路径
后仍会把旧目标的成功时间显示给新目标。

## 修改

- 新增进程级、非排队 `BackupOperationLease`，覆盖备份页四个修改型操作和 WebDAV 配置保存
- 冲突操作立即显示统一提示，不暗中排队；release 幂等，旧 `finally` 不会解锁新 owner
- 连接测试与配置保存用 `isTesting`/`isSaving` 全流程互斥，门禁覆盖 HTTP 风险确认框
- 测试连接保持只读，不占用全局修改租约
- 云备份与云恢复冻结 `WebDAVConfig` 快照；客户端和成功时间写入使用同一目标
- 新增版本化目标身份：规范化 server URL、username、backup path，明确排除 password
- `getLastBackup()` 只返回当前目标匹配的时间；目标变化显示“从未备份”，密码轮换保留时间
- `setLastBackup()` 在同一次 preferences flush 写入目标和时间，并在提交失败时补偿旧二元组
- 旧版本只有全局时间、缺少目标身份时不猜测迁移，等待当前目标下一次真实成功备份
- 新增中英文冲突提示、Hypium 租约测试、目标身份测试与专项 replay
- 新增 ADR-0179，明确进程内与跨进程边界

## 原版与平台边界

Android 原版 1.0.3 没有 Harmony WebDAV/Backup 页面同构实现，因此本阶段不能描述为逐行移植。原版
继续约束笔记导入导出和用户可见语义；跨实例互斥、配置快照与目标身份是针对 Harmony 页面生命周期和
WebDAV 扩展能力的可靠性修补。

该租约不承诺覆盖未知进程归属的系统 `BackupExtensionAbility`，也不在进程终止后持久存在。旧无身份
时间戳故意不迁移，这是避免把不确定历史错误归属给当前服务器的保守选择。
