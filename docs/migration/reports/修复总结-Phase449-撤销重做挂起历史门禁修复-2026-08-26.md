# 修复总结 — Phase 449 撤销重做挂起历史门禁修复

## 问题

跨页 Undo/Redo 使用 `pendingHistoryDirection` 加父页 `historyPending` 表示一条尚未
resume 的历史命令。但父页工具栏回调只检查 `pageOperationBusy`，挂起期间第二次点击
仍会发送 undo/redo 信号；Canvas 的 `performHistory()` 也看不到父级挂起租约，可能
启动竞争性历史命令，破坏跨页命令的一次性串行化。

## 修复

工具栏 `onUndo` 与 `onRedo` 在发信号前新增 `!this.historyPending` 检查。挂起的
跨页历史命令在成功、失败或恢复异常路径释放后，才允许下一次撤销/重做。Canvas 内部
`historyBusy`、pending direction 和 stale-context 防御保持不变。

- 新增 ADR-0421、Harmony evidence 与中文 Report。
- 扩展 `d02-page-history-command-lease-bound.mjs` 锁定 undo/redo 门禁与守卫位置；
  当前 `TOTAL=9 FAILED=0`。
