# Phase 298 修复总结：剪贴板探测退订即时失效

## 缺陷

Phase 297 只防止“更新请求之间”的迟到结果覆盖。组件退订路径仍保留当前 probe 代数：如果退出前已有 probe
启动，其 promise 可能晚于 `aboutToDisappear()` 回来，存在销毁后回写窗口。

## 决策与实现

在 `stopSystemClipboardImageAvailabilityUpdates()` 的 finally 中递增
`systemClipboardImageProbeGeneration`，并同时移除 listener、清空 `systemClipboardImageAvailable`。这样所有
已启动 probe 在组件脱离时立即过期；重新挂载后由新订阅和新代数刷新。

## 验证

- 剪贴板专项 Replay 保持 22/22，并新增退订路径递增代数与清态断言；
- 双 HAP 与全量 Replay 结果见总进展验证补录；
- 未启动模拟器、虚拟机、真机或 Hypium。

## 开放项

真实组件重建、系统剪贴板事件时序和厂商兼容行为仍需设备验收；`T-042` 继续严格留到 Goal 最后一项。
