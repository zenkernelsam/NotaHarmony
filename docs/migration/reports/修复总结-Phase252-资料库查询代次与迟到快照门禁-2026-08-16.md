# Phase 252 修复总结：资料库查询代次与迟到快照门禁

## 目标

承接 M2-U-04/M2-U-08。Phase 204 已修复 mutation 提交边界和缩略图生命周期，但本轮补审发现页面层仍有
搜索、folder、初始化、索引回填和 mutation reload 之间的迟到发布竞态。本阶段在不改变仓储事务语义的前提下，
统一列表请求身份。

## 已完成

- `LibraryPage` 增加单调 `notesRequestGeneration`，并以 query/folder/ViewModel/pageActive 五元条件判断请求是否仍当前。
- 搜索输入在 debounce 排队时立即使旧查询失效；timer、成功和错误回调均拒绝旧文本/旧 generation。
- `onPageShow`、首次初始化和 search-index backfill 捕获同一 request tuple，旧初始化结果不能覆盖用户新查询。
- mutation 后权威 reload 在开始前确认仍属于当前 ViewModel，并捕获 query/folder/generation；迟到 reload 只丢弃，
  不覆盖提交后本地快照，也不显示过期错误。
- folder 选择只有在查询、列表与缩略图刷新均仍当前时才关闭 compact drawer；被新搜索取代或失败时保留上下文。
- 页面离开会递增 generation，跨生命周期 callback 不再发布列表。

## 原版对照

原版 `e47/sq1/vf6/d6c` 证明搜索是独立持久索引与异步数据库查询，不是 UI 内存标题过滤。原版由 Room/Compose
观察流消费最新状态；Harmony 没有同构 Flow，因此用显式 request generation 复刻“只有最新查询可见”的用户语义。
generation 是 Harmony 适配机制，不标成原版字段或常量。
