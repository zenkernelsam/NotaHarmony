# Phase 391：历史恢复入口状态绑定

日期：2026-08-25（Asia/Shanghai）

## 问题

历史恢复对话框的“重置撤销历史”回调直接调用重置函数。若对话框在编辑器销毁后或新历史命令启动后才响应，
迟到确认可绕过当时的生命周期/忙碌状态，进入持久化重置并清空共享 Undo/Redo 栈。

## 修复

- 新增 `requestPersistentHistoryReset()`，作为对话框唯一入口。
- 点击瞬间联合检查 `lifecycleActive`、恢复需求、两个忙碌标志和数据库可用性；不满足则静默返回。
- 既有 await 后销毁门禁、失败日志、durable reset 和 finally 清理保持不变。
