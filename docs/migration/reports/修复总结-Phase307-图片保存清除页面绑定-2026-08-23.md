# Phase 307 修复总结：图片保存清除页面绑定

## 缺陷

补审发现通用图片插入的成功路径在异步提交完成后无条件清除 `saveFailed`。若多图插入期间用户已切换页面，旧页的
完全成功结果可能清掉新页的真实保存失败状态，破坏 Phase 305 建立的失败反馈页面边界。

## 决策与实现

`insertOriginalPhotos()` 清除 `saveFailed` 前必须同时匹配发起 generation/pageId/currentPage，并且不存在部分失败。
跨页完全成功仍保留数据库结果、Undo history 和 outcome；新页的保存状态不再被旧操作改变。

## 验证

- 照片部分失败专项 Replay 从 8/8 扩展至 9/9；
- ArkTS 目标文件无新增错误；全量 Desktop Replay `277` 个文件全部通过，FAILED_FILES=0；
- `git diff --check` 通过；`note@ohosTest` 与 `note@default` 分别 `BUILD SUCCESSFUL in 7 s 871 ms`
  与 `11 s 345 ms`，只做静态打包且跳过签名；
- 未启动模拟器、虚拟机、真机或 Hypium。

## 开放项

多图跨张 rollback 仍需原版硬证据与独立补偿协议；真实设备失败注入继续开放；`T-042` 严格留到 Goal 最后一项。
