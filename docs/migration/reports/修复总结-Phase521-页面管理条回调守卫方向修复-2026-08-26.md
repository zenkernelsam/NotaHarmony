# 修复总结 — Phase 521 页面管理条回调守卫方向修复

日期：2026-08-26

## 问题

继续补审发现 Phase 519 的页面管理条直接回调条件方向相反：`if (!busy && !leaseActive) return;`
会在空闲时提前返回，在忙碌或共享照片导入租约活跃时反而执行原动作。紧凑新增、常规新增、删除、
前移、后移、导航和设置七类回调都受影响；响应式禁用掩盖了多数路径，但晚到触发只能依赖父级
`runPageOperation()` 异步兜底。

## 决策

七处直接点击回调统一改为 `if (this.busy || this.photoImportLeaseActive) return;`，先在组件层拒绝
忙碌与共享导入租约，再执行原动作。溢出菜单既有正向守卫、页序边界、父级串行化、设置弹层、背景
应用防御和正常语义保持不变。

  输出 `TOTAL=24 FAILED=0`。
