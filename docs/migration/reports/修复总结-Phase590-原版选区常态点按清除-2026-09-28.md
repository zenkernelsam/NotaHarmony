## Phase 589 误读纠正

Phase 589 把 `ftc.i` 当成"移动子集"，实现了元素粒度抓取拖拽。核对
`ftc.java` toString（`deselectMode=h, deselectedIds=i`）与
`dhb.java:18035`（菜单 cg2 case20 置位 deselectMode）后确认：

- `stc`/`ej9 case18` 是 **deselectMode 的点按移出选区**（`ys2.H` 从
  selectedIds 减去、`ys2.J` 并入 deselectedIds），不是拖拽抓取。
- 常态（`h=false`）下选区内按下走 `wtc → e39` 拖**整个**选区——正是
  Harmony 在 Phase 589 之前的行为，已恢复。

## 原版常态契约（dl1.java case2 else 分支）

| 按下位置 | 原版 | Harmony（本 Phase） |
|---|---|---|
| 选区覆盖层内 | `wtc` → `e39` 拖整体 | `pointInRect` → `selectionDrag` 拖全部（恢复） |
| 覆盖层外命中元素 | `vtc` → `uw2 case3` TapToSelect（`otc` 选元素 / `ntc` 组 → `gtc`） | `topmostPageElementIdAt` + `resolveOriginalGroupSelection` → `selectElementIds` |
| 覆盖层外未命中 | `rtc` → `ct0` ClearSelection | `clearSelectionWithRegisterReset()` |
| 无选区 | 套索/矩形手势 | `beginSelection`（不变） |

## 改动

- `NoteCanvasView.ets`：恢复 in-rect 整体拖拽；新增
  `topmostPageElementIdAt`/`allPageEntityIds`；选区外按下改
  TapToSelect（组展开）/ClearSelection。
- `SelectionTool.ets`：移除 `movingIds`/`grabElements`/`clearMoving`/
  `movingSubsetOf` 及 `applyTransform` 收窄——deselectMode 无入口，避免死代码。
- `ShapeGeometry.ets`：保留 `pointHitsShape`（topmost 命中复用）。

## 有界偏差

- 旋转选区 AABB 内、旋转矩形外：原版走 vtc/rtc，Harmony 走拖拽。
- `gtc` 组选择态成员点按的 `ttc → uw2 case4` 元素菜单未映射。
- deselectMode 无菜单入口，整体未移植。
