# Phase 123 修复总结：原版本地 Text 创建、出站与持久 Undo/Redo

## 原版证据与纠错

- 复核原版 `haa/zq9/baj/kci/f46/e4c`：Text 先用 type-22 `CREATE_BLOCK` 建空 RichText
  Block，再以独立 type-8 `INSERT_STRING` 将初始正文写到该 CREATE identity。
- `rl2` 保存 page/origin/size 与 common defaults；`f46` 要求非空 UTF-8 字符串并可显式指向
  Text Block；原版按 Unicode code point 分配字符 SeqId，而不是 UTF-16 code unit。
- 修正实现中途发现的 revision 错误：两条 reducer 各自推进会形成 `N→N+2`，违反
  `PageMutationOpCodec` 的单命令不变量。最终共享 `OriginalPageMutationBatch`，row 写最终
  `N+1`，页面只 flush 一次。

## 已完成修复

- 新增严格 type-22 Text CREATE_BLOCK 与 type-8 initial INSERT_STRING writer。采用 17pt
  黑色、原版 margins/common defaults；拒绝 shear、perspective、非有限几何、非法
  surrogate、空串、超预算正文和不可表示样式。
- 两个生产 applier 新增可选 batch 入口；普通入站保持各自 revision 语义，本地组合创建
  才共享一次 flush。
- 双击新建 Text 时消费 canonical reservation，Block ID 等于 type-22 identity，位置规范化为
  local origin `(0,0)` 加 translation。空草稿取消不落盘并重新预约；成功提交在保存后预约。
- `StrokePersistence` 在同一事务内执行两个 reducer、两条 immediate journal、revision batch、
  reducer-state 校验、snapshot/search reconcile 和 history companion，任一步失败整体回滚。
- 新增 `ORIGINAL_CREATE_BLOCK=71`、`ORIGINAL_INSERT_TEXT=72` 透明 companion；持久历史仍是
  一个 add-element action，Undo/Redo 沿 type-25 恢复同一 Block identity。
- 边修边审发现生产依赖图首次纳入 INSERT reducer 后，既有 RichText style state 使用了 ArkTS
  禁止的动态 `delete/in`、结构类型、解构与受限 `Object.assign`。现已改为命名 row/materialization
  接口、显式 Map 遍历和逐字段 style 重建；nullable clear 真正移除字段，不产生伪空 style run。
- 最终审阅补齐 `.note` 包的 Text `originalCreate` 严格边界：逐字段校验安全整数、uint16 siteId
  与整数 pencilSeed，损坏或伪造的预留 identity 不再进入导入和后续原版 writer。
