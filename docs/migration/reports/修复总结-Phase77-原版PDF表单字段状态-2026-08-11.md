# Phase 77 修复总结：原版 PDF 表单字段状态

日期：2026-08-11

## 问题

原版 payload type 27 `MODIFY_PDF_FIELD` 此前没有进入 Harmony 统一回放路由。PDF 背景虽然已能
按页渲染，但用户在原版 PDF 表单中填写的字符串、勾选状态会被当作 unsupported/deferred，无法落入
模型。若把这些值直接写入某一页或 `note_asset`，还会破坏原版同一 PDF 可被多页引用的 asset-level
语义，并错误要求本地文件必须先到达。

## 原版证据

- `ee8/p0j`：payload 为 required 64-byte assetHash、required key、STRING/BOOLEAN enum、
  nullable string/bool。BOOLEAN writer 会临时开启 FlatBuffers `forceDefaults`，所以 false 也显式写
  field 4；field 4 缺失代表 null，不能默认为 false。
- `q0j`：只把与 enum 匹配的值转为 typed string/bool；错类型或缺值不是有效操作。
- `v69/al2/bl2`：outer key 是 asset hash，inner key 是 PDF field key，operation identity 是 LWW
  winner；变化通知 `s09` 同样携带 `(assetHash,key)`，不是 page ID。
- 该 map 独立于资产引用/本地文件生命周期，允许事件先于 PDF metadata 或文件到达。

## 修复

- 数据库升至 v54，新增 `original_pdf_field_state`。主键为 note/hash/key，typed value 与 winner
  timestamp/site 独立保存；CHECK 保证 string/bool 恰有一个有效值，unique winner 防止同一 operation
  identity 被改用于另一字段。只 FK 到 `note_meta`，没有错误绑定 `note_asset`。
- 从 AssetCloudPersisted 抽出共享 canonical SHA-512 byte→hex helper，type 2/type 27 使用同一 128 hex
  storage hash，避免两套 hash 编码漂移。
- 新增 `OriginalModifyPdfFieldOperationApplier`。严格检查 required hash/key、UTF-8/大小预算、非空 key、
  enum、typed field presence、canonical bool 和未知字段；BOOLEAN false 必须显式 field presence。
- reducer 完整实现 stale/site tie、newer upsert、exact retry，以及同 identity 改 hash/key/type/value 的
  冲突。状态可以在 `note_asset` 不存在时先写入，笔记删除时级联清理。
- 导出 `readOriginalPdfFieldValue`，为后续 PDF form overlay/cache 提供明确读取边界；不错误推进单页
  content revision。type 27 已接入 standalone 与 NOTE_BUNDLE，沿用 transient 门禁和外层事务。
- 边修边审发现 NOTE_BUNDLE 的 `applied` 判定只观察元素、页 revision 和结构 revision，note-level PDF
  map 写入会被误报未变化。现增加按 hash/key 排序、长度前缀的完整状态签名，避免数值汇总碰撞。

## 验证

- 新增 `d02-modify-pdf-field.mjs`，覆盖 v53→v54、三种值、多 key/hash/note、stale/tie、幂等、
  三类 identity conflict、event-before-asset、NOTE_BUNDLE rollback、级联和迁移回滚。

- 执行 `hvigor clean` 后，`note@ohosTest` 与 `note@default` 均 `BUILD SUCCESSFUL`；仅保留仓库既有 warning。

## 剩余边界

本阶段完成的是原版 PDF field 模型、持久化和回放，不是视觉表单闭环。当前 `PdfBackgroundLoader`
只栅格化页面，尚无 AcroForm widget geometry、appearance stream、overlay、焦点/输入和 outbound writer；
因此不会把“值已保存”写成“用户已能看到并编辑”。这些需要后续有证据的 PDF form consumer 与真机验收。

统一生产路由现为 **21/31**，剩余 **10 类**：5、6、18、19、20、21、26、29、30、31，涉及
Recording、Shape/Group、临时协作、peer interaction 与 Comment。Goal 继续 active，下一阶段继续边修边补审。
