# 修复总结 — Phase 566：原版外观设置区

日期：2026-09-22

## 原版行为（硬证据）

- `r22.java` case 0：`feature_settings__match_system_appearance`
  （"Match system appearance"）
- `g8.java`：`feature_settings__dark_theme`（"Dark theme"）
- 两控件收敛为 `nve` 枚举 {MATCH_SYSTEM, LIGHT, DARK}：跟随系统时
  显式深浅色被覆盖。
- `s3d` 设置目录顺序：appearance 在 note_editor 之前。

Harmony 侧主题机制早已存在（ThemeStore 'system'/'light'/'dark' +
`library_prefs/theme_mode` 持久化 + LibraryPage.setThemeMode 写路径），
缺的是设置页里的外观区。

## Harmony 落地

`SettingsPage.ets` 新增 "Appearance" 区（置于 "Note editor" 之前，
对齐 s3d 目录顺序），两行开关：

- "Match system appearance"：开 → `theme_mode='system'`；关 → 取当前
  **已解析**外观落为显式模式（`systemDark ? 'dark' : 'light'`），
  关闭瞬间可见主题不跳变。
- "Dark theme"：写 `'dark'`/`'light'`；跟随系统开启时禁用并降透明度
  （枚举单值语义：match 覆盖显式选择）。

写路径复用 `ThemeStore.setMode` + `preferences` flush，带
lifecycle-generation/disposal 守护，与 LibraryPage 菜单同语义。
