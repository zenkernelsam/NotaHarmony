# Phase 209 修复总结：Replay 数据库版本下限契约

## 发现

Phase 208 结束后执行全部 195 个桌面 replay，169 个通过、26 个失败。逐文件检索确认失败脚本全部包含同一个过期断言：

```text
DB_VERSION: number = 61
```

生产数据库已在 Phase 207 升级为 v62，用于启动时清理孤儿 `note_asset` 引用；回退生产版本只为让旧测试通过会破坏真实迁移。继续执行修正后的脚本还发现
`d02-pdf-background.mjs` 仍要求旧的 `document.getPageCount() !== ...` 内联表达式，而生产实现已缓存 `pageCount` 并增加安全整数、正数、metadata 一致性和页索引范围校验。

## 修复

- 新增 `docs/migration/replays/support/database-version.mjs`：
  - 只接受唯一的行级 `export const DB_VERSION: number = <integer>;`。
  - 拒绝缺失、小数、注释伪声明、重复声明和非安全/非正整数。
  - `assertDatabaseVersionAtLeast()` 以数值方式检查最低版本，不使用无法扩展到三位数的正则枚举。
- 将 26 个 replay 的精确 v61 断言改为最低 v61 契约；各脚本原有迁移编号、DDL、触发器、FlatBuffer、LWW 与 reducer 断言全部保留。
- 新增 `d02-replay-database-version-contract.mjs`，覆盖 v60/v61/v62/v100 与非法声明边界。
- 更新 PDF 背景 replay，验证当前实现的 `pageCount` 缓存及完整边界，而不是旧表达式的字面拼写。

## 受影响范围

26 个脚本覆盖 Ink、Block、RichText、Math、PDF、Shape/Group、Checkbox、entity visibility、audioTime、local outbound 与 note background 等既有 D-02 功能。此次没有修改任何生产 ArkTS、数据库 DDL 或原版适配逻辑。

决策记录见 `ADR-0186-replay-database-version-floor.md`。
