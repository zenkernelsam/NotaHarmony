# Phase 816 — locale split 翻译覆盖矩阵

## 目的

Phase 795 登记了 1.4.2 的 17 个 locale split 存在性；本阶段解析各
split 的 `resources.arsc` 全局字符串池,量化每个语言的实际翻译
覆盖度 —— "声明支持"与"真实翻译"的深度差异。

## 取证路径

- `Notability_1.4.2/..._apkcombo.com.xapk` 内嵌 `config.*.apk`
  → `resources.arsc` RES_TABLE → 全局 string-pool(UTF-8)
- `decompiled_1.4.2` 基准 string 键数 ~1,400(共享 1396 + 新增)

## 关键发现

1. **15 个语言全量翻译**:ar/de/es/fr/hi/in/it/ja/ko/pt/ru/th/tr/vi/zh
   各 ~1,830-1,950 条 —— 与基准 string 面(1396 共享 + 新增)规模
   匹配,为真实全量本地化(含复数组合形式,如 zh 的
   "也将删除 %2$d 个文件夹和 %3$d 条笔记")。
2. **`config.my`(缅甸语)仅 93 条** —— 声明的 locale split 但
   近乎空壳,商店元数据级覆盖；登记为"挂名 locale"。
3. **zh split 双语态并存**:应用字符串为简体中文(笔记/文件夹/
   录音等简体形,369 命中 vs 84 繁体命中),而厂商串
   (Google Play 服务/Samsung IAP/导航 chrome)保留繁体
   (`服務`/`裝置`/`開啟`)—— 即应用文案 zh-Hans、厂商
   GMS/Samsung 文案随其自带的 zh-Hant 资源。

## Harmony 侧

Harmony 当前本地化 = `base`(en)+ `zh_CN` 两档,与应用内建表面
规模一致(约 1,600+ 键含 `import_files_count_*` 等对)。
原版 15 个全量语言 + 1 个桩级,在 Harmony 为**本地化广度
差距**(非行为缺陷):登记为未实现的本地化扩展面 ——
若未来扩展 zh_TW/ja/ko 等语言档,本矩阵给出原版的语言基线。

## 结论

locale 面闭合:16 个语言 split 中 15 个全量翻译、1 个(my)为
桩级;zh split 确认为 zh-Hans 应用文案 + 厂商 zh-Hant 并存。
