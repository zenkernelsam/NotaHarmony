| 域 | 报告文件 | 条数 | P0 | P1 | P2 | P3 |
|---|---|---:|---:|---:|---:|---:|
| 1 算法与适配层 | `域1-算法与适配层.md` | 32 | 0 | 16 | 11 | 5 |
| 2 数据层与 op 流 | `域2-数据层与op流.md` | 25 | 4 | 11 | 8 | 2 |

| 5 UI 与设置 | `域5-UI与设置.md` | 27 | 2 | 12 | 8 | 5 |
| **合计** | | **147** | **11** | **64** | **52** | **20** |

**必须先认清的判断**：问题不是"还差几个 bug"，而是**四处架构性缺失**，各自派生出一串表面症状。不先处理它们，逐个修表面 bug 会反复返工：

1. **存储层没有页维度**（D-01 / R-14 / F-07 / R-30）——`client_op` 无 `page_id`，`saveElements` 每次先 `DELETE WHERE note_id=?` 再全量重写。多页笔记所有页共用一份元素集合；导入侧靠"拍平成一个数组一次性写入"规避，页归属在导入那一刻永久丢失。撤销栈同样无页维度，页维度补上后会立刻暴露跨页撤销错乱。
2. **op-log 模型退化为整体快照**（D-02 / D-19）——`OpStore` 接口五个方法全仓零实现。undo 无法跨会话持久化、增量同步无从谈起、每次落笔全表删重插。
3. **渲染层坐标系不自洽**（R-01 / R-07 / R-18 / R-29 / R-35 / R-39）——已完成笔画层是**屏幕尺寸**位图却在视口变换内绘制，纸张原点随 zoom 漂移，脏矩形的两个入口用了两套坐标系。缩放后笔迹模糊、画布可视区外的笔迹永久丢失、清屏清不干净。
4. **铅笔的能力数据在入口就被丢弃**（A-25 → A-16 → A-13/A-14/A-15）——`new InkInputProviderImpl(true, false, false)` 把倾角与方位角支持**硬编码为 false**，导致 `angleDiff` 恒为 0，铅笔的散布半径、颗粒数、边缘淡出**全部塌缩为常量**。铅笔实际退化成"沿轨迹盖不透明度恒定的圆点"。

另有两条独立的致命/高危链路，与架构无关，可立刻单独修：

- **F-01**：`ZipArchive` 写 ZIP 头时把"未压缩长度"字段写成了压缩后长度 → **自己导出的 `.note` 100% 读不回来**，当前 WebDAV 备份产出的全部文件不可恢复。一行修复，收益最大。
- **A-30**：形状识别的触发时机错了。原版 resources 明文写着"画完后**继续按住**才自动识别"，移植侧是**每次抬笔都识别并替换**。用户随手画的横、勾、圈会被意外拉直，手写笔迹被破坏。

### FIX-A　存储页维度与写入事务【地基批次，必须第一个完成】

**根因**：`client_op` 表缺 `page_id`；`saveElements` 全量删重写且无事务；数据库无版本升级机制（导致加列本身就做不到）。

**覆盖条目**：D-01、D-03、D-04、D-07、R-14、R-30、R-31、F-07

**执行顺序不可颠倒**：
1. 先做 D-04（DB version + 迁移框架）。没有它，后面所有加列都不会生效，且失败会被静默吞掉。
2. 再做 D-01（`client_op` 加 `page_id` + 索引 + `saveElements/loadElements` 加页参数 + 更新全部调用点）。
3. 同步做 D-03（事务包裹 + `batchInsert`）。
4. 顺带 D-07（`PageInfo` 补 `pageIndex`、`addPage` 改 `MAX(page_index)`、`reorderPages`/`deletePage` 加事务）。
5. R-30（撤销栈补 `pageId`）与 R-31（补 `ADD_PAGE`/`DELETE_PAGE`/`REORDER_PAGES`/`PAGE_SETTINGS` 四种可撤销类型）。
   **⚠️ R-30 有两个方案（全局单栈带 pageId vs 每页独立栈），需指挥官定夺，工人不得自选。**
   **⚠️ R-31 顺带纠正一项验收错误：`reports/T-035-完成.md` 标记「Undo 全覆盖」完成，实际页级与文档级操作从未纳入。删页目前完全不可撤销。**
6. 最后 F-07 是调用侧收尾：`NoteImporter` 改按页写入并删掉"必须一次性写入"的规避注释、`NoteExporter` 改按页读取。

**验收**（静态，逐项可 grep）：
- `DatabaseManager.ets` import 含 `DB_VERSION`，`StoreConfig` 含 `version:`，存在 `store.version` 的读与写与按版本分支的迁移数组
- `DatabaseHelper.ets` 的 `DDL_CLIENT_OP` 块内命中 `page_id`
- `grep -rn "saveElements(" note/src` 所有调用点参数 ≥ 4 个
- `StrokePersistence.ets` 删除谓词同时含 `equalTo('note_id'` 与 `equalTo('page_id'`，且出现 `beginTransaction()` 与 `rollBack()`
- `NoteImporter.ets` 中不再存在"必须一次性写入"注释
- `PageRepositoryImpl.ets` 的 `rowToPage` 含 `page_index`；`addPage` 不再出现 `while (countSet.goToNextRow())`
- `UndoableAction` 含 `pageId`；`UndoableActionType` 枚举成员数 ≥ 11

### FIX-J　铅笔能力数据链【四条必须一次做完，否则改一半没有任何可见效果】

**根因**：倾角/方位角数据在输入层被硬编码丢弃，导致下游全链路塌缩。

**覆盖条目**：A-25、A-16、A-15、A-26、A-14、A-13、A-18

**执行顺序**：
1. **A-25**：`NoteCanvasView.ets:52` 与 `NoteCanvasPage.ets:28` 的 `new InkInputProviderImpl(true, false, false)` 改为按设备能力探测；两处重复构造抽成统一工厂。
2. **A-16**：打通 `InputPoint.tiltRadians → StrokePathPoint → SplatAttributes` 的传递（数据在输入层本来就有，只是断链了）；删除 `interpolateAttributes` 里 `tilt: Math.PI/4` / `orientation: Math.PI/5` 两个硬编码常量。**无倾角数据时的 fallback 不能取 π/4 或 π/5——这两个值都会让 angleDiff 归零。**
3. **A-15 + A-26**：`angleDiff` 改用与尺寸因子第二参同源的字段（倾角），不再用规约到 `[0,2π)` 的方位角标量。
4. **A-14**：`scaleBase` 的输入从 `width` 改为 `pressure`（原版两处同用 `fc0.d()`）。
5. **A-13**：`:156` 的 `len` 补上漏掉的 `* r` 因子（`Math.sin(theta) * r`），恢复均匀圆盘采样。
6. **A-18**：前五步落地后，删除 `ellipseR` 上 `Math.min(..., spacing*1.5)` 的钳制——那是 T-033 为掩盖 A-16 症状加的补丁，保留会把散布范围截断到五分之一。

**⚠️ 派工前必须交代**：最近一次提交 `3b4f171` 声称修复了"铅笔颗粒纹理"。该修复**不可能通过本路径生效**（只要 tilt/orientation 仍是常量，塌缩必然发生）。工人第一步应核对 `3b4f171` 究竟改了什么、是否绕开 `PencilSplatGenerator` 另做了一套纹理；若存在两套并行实现必须合并。

**验收（静态）**：全仓 `new InkInputProviderImpl(` 实参不含连续两个字面 `false`；`interpolateAttributes` 中 `tilt` 来源为 `StrokePathPoint` 字段而非字面常量；`scaleBase` 表达式不含 `width`；`:156` 的 `Math.sin(theta)` 后跟 `* r`；`ellipseR` 计算不含 `Math.min(..., spacing * 1.5)`。

### FIX-M　形状识别行为对齐

**覆盖条目**：A-30、A-31、R-28

**要点**：原版 resources 明文定义了交互——"画出形状后**继续按住不抬笔**才自动识别"，且设置页有可关闭的「Shapes detection」开关。移植侧是抬笔即识别且无法关闭，叠加 `confidenceThreshold` 只有 0.5 与 R-28 的"点数不同即算识别成功"，误替换率会很高，用户的手写笔迹会被无声破坏。

**验收（静态）**：识别调用不在 touchUp 路径上，而在按住计时器回调中；设置页存在开关且被识别调用点读取。

### FIX-N　算法保真（其余）

**覆盖条目**：A-01 ~ A-08（CubicFitter）、A-09 ~ A-12（ForceSmoother）、A-22 ~ A-24（WidthOutlineBuilder）、A-27 ~ A-29（适配层）

**其中三项要特别交代**：

- **A-09（P1）力平滑只实现了一半**。原版是「时间加权 lerp + 增量钳制」两步：`t = clamp(dt/window,0,1)`，`blended = last*(1-t) + raw*t`，再钳制增量。移植侧**恒等于 t=1**，`p.elapsedTimeMillis` 与 `smoothingWindowMs` 从未参与运算。120Hz 下两者接近（所以测不出来），240Hz 手写笔下压力曲线明显更抖。**注意：三个默认值（enabled/8ms/0.15）移植得完全正确，问题在算法结构不在参数，不要去调参。**
- **A-22（P1）轮廓端点半圆帽的角度整体偏了 90°**，纯几何推演可证，导致封闭轮廓在两端不闭合、笔画端部出现"耳朵"或缺角。修复后应补单测断言帽的首末点与 `upper[0]`/`lower[0]` 重合。
- **A-21 需指挥官决策，不得让工人自行动手**：原版 `WidthOutlineBuilder` 基于 bezierkit 做**贝塞尔曲线偏移**（带内圆弧判定与等宽快速路径），移植侧退化为**折线偏移**。这是方法论差异，三个选项（加密自适应采样+圆弧接头 / 引入曲线偏移 / 接受差距并登记）需先定方案。**在决策前禁止改这个文件的结构。**
- **A-27**：仓内存在两套并行画布实现（`NoteCanvasView` 1131 行 与 `NoteCanvasPage` 248 行），各持一份 provider 与 session。**哪一个是活的本轮未确认**——工人修改画布缺陷前必须先定性，否则可能在死代码里改 bug。
