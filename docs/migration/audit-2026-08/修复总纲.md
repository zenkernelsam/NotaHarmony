**必须先认清的判断**：问题不是"还差几个 bug"，而是**四处架构性缺失**，各自派生出一串表面症状。不先处理它们，逐个修表面 bug 会反复返工：

1. **存储层没有页维度**（D-01 / R-14 / F-07 / R-30）——`client_op` 无 `page_id`，`saveElements` 每次先 `DELETE WHERE note_id=?` 再全量重写。多页笔记所有页共用一份元素集合；导入侧靠"拍平成一个数组一次性写入"规避，页归属在导入那一刻永久丢失。撤销栈同样无页维度，页维度补上后会立刻暴露跨页撤销错乱。
2. **op-log 模型退化为整体快照**（D-02 / D-19）——`OpStore` 接口五个方法全仓零实现。undo 无法跨会话持久化、增量同步无从谈起、每次落笔全表删重插。
3. **渲染层坐标系不自洽**（R-01 / R-07 / R-18 / R-29 / R-35 / R-39）——已完成笔画层是**屏幕尺寸**位图却在视口变换内绘制，纸张原点随 zoom 漂移，脏矩形的两个入口用了两套坐标系。缩放后笔迹模糊、画布可视区外的笔迹永久丢失、清屏清不干净。
4. **铅笔的能力数据在入口就被丢弃**（A-25 → A-16 → A-13/A-14/A-15）——`new InkInputProviderImpl(true, false, false)` 把倾角与方位角支持**硬编码为 false**，导致 `angleDiff` 恒为 0，铅笔的散布半径、颗粒数、边缘淡出**全部塌缩为常量**。铅笔实际退化成"沿轨迹盖不透明度恒定的圆点"。

另有两条独立的致命/高危链路，与架构无关，可立刻单独修：

- **F-01**：`ZipArchive` 写 ZIP 头时把"未压缩长度"字段写成了压缩后长度 → **自己导出的 `.note` 100% 读不回来**，当前 WebDAV 备份产出的全部文件不可恢复。一行修复，收益最大。
- **A-30**：形状识别的触发时机错了。原版 resources 明文写着"画完后**继续按住**才自动识别"，移植侧是**每次抬笔都识别并替换**。用户随手画的横、勾、圈会被意外拉直，手写笔迹被破坏。
