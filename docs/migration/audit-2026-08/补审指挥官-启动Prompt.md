### 任务 1【最高】原版 Room schema 逐表比对

**为什么最优先**：域2 有三条 P0/P1（D-01 无页维度、D-02 op-log 退化、D-05 缺外键）的基准证据目前全是 🟡 结构性推断，依据只是包路径命名和异常类名。而原版 Room 生成的 `*Database_Impl.java` 里就有**完整的建表 SQL、列名、索引、外键、迁移版本**——这是整个项目最硬、最容易拿到的基准证据，却一直没用。

**做什么**：在 `decompiled_1.0.3/sources/com/gingerlabs/notability/` 下找出这些 Room 库的 `_Impl` 类，提取 `createAllTables` / `onCreate` 中的 DDL：
`NoteStateDatabase` / `NoteAssetDatabase` / `NoteBundleMetadataDatabase` / `RawLibraryStateDatabase` / `ToolboxDatabase` / `SettingsDatabase`（另有 LearnDatabase / SearchDatabase / TranscriptionDatabase，属未移植功能，可略）

- 一张**列级对照表**（原版列名/类型/约束 ↔ 移植侧对应物 ↔ 差异）

- 原版**op 表的真实结构**——这决定了 D-02（op-log 退化为快照）该怎么修，是本任务的核心产出

**写入**：`docs/migration/audit-2026-08/域2-数据层与op流.md` 末尾新增一节「原版 Room schema 逐表比对」，新缺陷编号从 **D-26** 起。同时回到 D-01/D-02/D-05 三条，在原文下方追加「指挥官复核」小节更新证据等级，**不要删改原文**。

### 任务 5【中，工作量最大】域4 与 androidx.ink 的系统性行为对照

**为什么重要**：域4 是缺陷最密集的域（40 条，占总量 27%），但它的覆盖度声明里明说了——几乎全部是**移植侧自洽性推演**，没有与原版做过对照。也就是说我们发现的都是"移植代码自己前后矛盾"，而「原版橡皮擦是什么语义」「原版选区变换后笔宽怎么处理」「原版视口缩放的锚点在哪」这类**只能靠对照才能回答的问题，一个都没回答**。这是"离完美移植还远"的真正所在。
