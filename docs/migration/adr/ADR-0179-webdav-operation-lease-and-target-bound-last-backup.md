# ADR-0179：WebDAV 页面操作租约与目标绑定的上次备份时间

## 决策

备份页的本地导出、本地导入、WebDAV 备份、WebDAV 恢复，以及 WebDAV 设置保存，共享一个应用进程内、
非排队的 `BackupOperationLease`。页面重建或重复导航产生第二个页面实例时，若已有修改型操作进行中，
新操作立即拒绝并提示用户，不在后台排队执行一个用户可能已经看不到的任务。release 必须幂等，使旧
`finally` 再次执行时不能释放后来取得的租约。

连接测试不持有全局租约，因为它不修改数据库、备份对象或持久化配置；但设置页以 `isTesting` 与
`isSaving` 覆盖包括 HTTP 风险确认框在内的完整流程，禁止重复确认、测试与保存互相穿插。WebDAV 备份
和恢复在取得租约后冻结配置快照，网络客户端及成功时间写入必须使用同一快照。

“上次备份时间”不再是无归属的全局时间戳。持久化同时保存版本化目标身份和时间；目标身份由规范化的
服务器 URL、用户名与备份路径组成，不含密码。更换服务器、用户或路径后显示“从未备份”；仅轮换密码
仍属于同一个远端目标。目标身份与时间在同一次 preferences flush 中提交，失败时恢复此前的二元组。

升级前只有时间戳而没有目标身份的记录不进行推测迁移。首次升级会对当前目标显示“从未备份”，直到该
目标下一次成功发布并校验完整批次。错误地把旧时间绑定到一个不确定的服务器，比丢失一次历史展示更具
误导性。

## 原因

原有 `isBusy`、`isTesting` 都是组件实例字段。页面被重建或存在两个路由实例时，每个实例都可能认为
自己空闲，于是导入、恢复、导出、备份或配置保存可并发进入同一数据库、文件与远端命名空间。设置页还
会在确认不安全 HTTP 期间保持可点击，形成重复确认框和并发提交。

旧 `webdav_last_backup` 又没有绑定服务器、用户或路径。用户修改配置后，页面会把旧目标的成功时间展示
为新目标的备份状态；若备份过程中配置被另一页面改写，客户端与成功时间甚至可能指向不同目标。

非排队租约符合这些页面操作的交互语义：用户点击的是当前可见任务，冲突时应立即得知，而非几分钟后
悄悄启动。目标身份排除密码，可避免正常凭据轮换抹掉同一远端资源的历史状态。

## 原版与平台边界

Android 原版 Notability 1.0.3 没有 Harmony WebDAV 页面、系统 BackupExtensionAbility 或对应的
“上次 WebDAV 备份”存储可逐行移植。本决策不伪称原版同构实现；原版仍用于约束笔记内容与导入导出
体验，而 WebDAV 并发及目标身份依据 Harmony 当前页面生命周期、持久化和网络协议补齐。

`BackupOperationLease` 只保证同一应用进程中的备份页工作流与 WebDAV 配置保存。系统
`BackupExtensionAbility` 是否与 UI 处于同一进程不由本模块保证，因此不得声称该租约覆盖跨进程系统
备份。进程被终止时租约也不持久化；真正的跨进程互斥或崩溃恢复需要系统级锁或 durable journal。

## 验收边界

单测与 replay 覆盖跨页面实例拒绝、幂等 release、所有修改型入口、确认框全流程门禁、配置快照、目标
身份规范化及密码轮换。真实页面重建、应用进程终止、系统 Ability 并发、WebDAV 服务端中断仍需后续
设备和故障注入验证。
