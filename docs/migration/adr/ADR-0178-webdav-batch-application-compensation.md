# ADR-0178：WebDAV 批次恢复的应用级补偿回滚

## 决策

WebDAV 恢复继续保留 ADR-0174 的“远端对象独立校验”语义：校验失败的对象被隔离，其余已验证对象仍可进入恢复。对这组已验证对象，新增 `BackupBatchApplier` 作为应用阶段协调器：

- 仅 `SUCCESS` 与 `PARTIAL` 视为已创建笔记；`PARTIAL` 同时计入 degraded。
- 每篇导入必须返回新且非空的本地 note ID，协调器据此登记本次创建集。
- 任一硬失败后按创建顺序逆序删除本批次已创建笔记；单篇导入自身清理失败时暴露残留 note ID，批次协调器继续补偿。
- 所有可追踪笔记均删除成功时返回 `ROLLED_BACK`；删除失败、异常抛出后无法确认残留身份，或已提交结果没有可追踪身份时返回 `ROLLBACK_INCOMPLETE`，不得误报完整回滚。
- 完整回滚和不完整回滚使用不同的用户提示；验证失败计数不与应用回滚状态混淆。

这是一项应用级原子应用协议，不宣称是真正的跨篇数据库事务。

## 原因

每篇 `.note` 导入内部会经过 `NoteRepositoryImpl`、`PageRepositoryImpl`、`StrokePersistence` 与资产存储，各层已有自己的事务和互斥边界。若在外层强行包裹一个跨篇 RDB 事务，内层再次开始事务或等待资产/编辑持久化锁时容易形成不受支持的嵌套事务与锁顺序问题。

原恢复页逐篇调用 `importFromData()`，后篇失败时会永久留下前篇成功结果，却仍只能给出聚合失败提示。逆序补偿能在不破坏现有单篇事务所有权的前提下，使一次已验证批次通常表现为“全部应用或全部撤销”；无法证明撤销完整时必须诚实升级为人工检查状态。

## 导入与删除并发边界

`NoteImporter.importMutex` 覆盖自有格式、Notability 格式、仅标题 metadata-only PARTIAL 创建，以及公开的补偿删除。单篇写入失败时已经持有该锁，因此调用不再加锁的内部清理函数，避免递归获取同一非重入锁。这样批次补偿不会和另一场导入在同一个 RDB store 上交叠事务。

## 资产与通知边界

`deleteNote()` 在资产互斥与数据库事务内解绑 `note_asset` 引用；最后引用消失时，事务提交后、但仍持有同一资产互斥锁时回收独占文件，防止另一条写入在 commit 与 unlink 之间复用同一 hash 后被旧清理误删。`AssetAvailabilityHub` 只是刷新提示，编辑器、录音列表和缩略图仍以数据库及文件为 authority，不会因先前的“可用”通知保留已删除资产。删除成功后同时忘记该 note 的 generation，避免批次回滚长期留下陈旧缓存键。

## 原版与平台边界

Android 原版 Notability 1.0.3 没有 Harmony WebDAV/Backup 批次恢复实现可逐行移植。本决策不改变原版 `.note` 内容解析或单篇落库语义，而是依据现有 Harmony 恢复协议、RDB 事务所有权和文件生命周期补齐批次一致性；不得将其描述为原版代码的直接复刻。

## 验收边界

ArkTS 单测和 replay 覆盖成功/PARTIAL、逆序补偿、残留 note ID、删除失败继续补偿、不可追踪提交、异常抛出、互斥锁归属及资产 generation 清理。真实 WebDAV 传输、磁盘满、进程被杀和删除文件失败仍需后续设备/故障注入测试。
