# ADR-0193：原版数学资源必须以版本目录和完成标记发布

## 状态

Accepted，2026-08-14。

## 问题

`OriginalMathEngine.prepare()` 旧实现每次初始化都直接把 rawfile 中的 `glmath` 资源覆盖到
`filesDir/glmath`，随后立即把该目录传给 native 初始化。它存在四类完成性缺口：

- 资源目录没有版本，也没有“整套资源已经提取完成”的提交标记；
- 每个文件只调用一次 `fileIo.writeSync()`，忽略实际返回字节数，正数短写会被误判成功；
- 进程在多个文件之间或单个文件写入中被终止时，会留下新旧文件混合或部分文件；
- 路径检查仅按字符串粗略跳过部分危险项，失败后也不回收已经发布到目标目录的部分资源。

下一次启动会继续在这棵未知状态的目录上覆盖，并可能把不完整资源交给 native parser。结果可能表现为公式初始化失败、
特定字体或符号缺失，甚至只在部分公式上出现不可复现的渲染错误。

## 原版证据

`decompiled_1.0.3/sources/defpackage/s18.java` 明确给出 GLMath 的资源发布协议：

- `c()` 使用 `filesDir/glmath/v1`，完成标记为该目录下的 `.complete`；
- `.complete` 不存在时先通过 `tf4.u0(file)` 清理未完成的 `v1`，再从 asset 根 `glmath` 递归提取；
- `a(file, "glmath")` 对目录递归，对文件使用 `l96.i0(..., 8192)` 完整流复制；
- 全部递归提取成功后才调用 `file2.createNewFile()` 创建 `.complete`；
- `b()` 只把 `c()` 返回的完成版本目录传给 `GLMathNative.nativeInit()`。

这不是普通缓存优化，而是“目录内容完成后才提交”的资源一致性协议。Harmony 移植应保留该协议，同时补齐平台
`writeSync()`、路径和符号链接语义造成的新风险。

## 决策

1. 资源根改为 `filesDir/glmath/v1`，以 `filesDir/glmath/v1/.complete` 作为唯一完成标记。
2. 标记已经是普通文件时复用完成目录；标记缺失、是目录或符号链接时，不把现有目录交给 native 初始化。
3. 缺少有效标记时先清理 `glmath` 根，再创建全新的 `v1`。原版会清理未完成 `v1`；移植额外清理旧的
   无版本 `filesDir/glmath` 布局，以完成一次性迁移并避免旧资源混入版本目录。
4. rawfile 列表必须非空且不超过文件数预算；总字节数必须保持安全整数并不超过既有资源预算。
5. 每个相对路径按 segment 校验：拒绝空路径、绝对路径、反斜杠、空 segment、`.` 与 `..`。任何危险路径使
   整次提取失败，不能静默跳过后仍发布 `.complete`。
6. 每个资源按 64 KiB 分块写入，并按 `writeSync()` 的实际返回值推进；返回值小于等于 0 或大于本轮请求长度
   均视为非法进度。每次切片严格保留原 `Uint8Array.byteOffset/byteLength` 边界。
7. 文件完整写出后执行 `fsyncSync()`，关闭后验证路径是普通文件且最终长度严格等于资源字节数。
8. 只有全部资源验证完成后才创建空 `.complete`，同步 marker，并验证其普通文件身份和零长度。
9. 提取、写入、同步、关闭、校验或 marker 创建任一步失败，都递归删除整个部分资源树，让下一次初始化从
   干净状态重试。
10. 递归清理重新验证每个枚举项确为目标目录的直接子项，并使用 `lstatSync()`；符号链接只删除链接自身，
    不跟随到资源根之外。
11. 只有有效 `.complete` 对应的 `v1` 目录才传给 `initializeNative(root)`；native 初始化返回值继续决定引擎
    是否 ready。

## 结果

- 杀进程或短写不能再把部分资源伪装成可初始化的完整集合。
- 旧无版本目录会在首次准备时被清除并迁移到原版 `glmath/v1` 协议。
- 危险 rawfile 路径、异常文件身份和符号链接不会越过资源根边界。
- 成功初始化后的后续启动可通过 `.complete` 直接复用资源，避免无条件重写。
- 提取失败会留下“没有完成目录”的明确状态，下一次可以干净重试。

## 边界

- `.complete` 证明本应用曾完成文件写入与文件级 `fsync`，不等同于父目录 rename 或任意掉电窗口下的完整
  文件系统事务；Harmony 当前 API 未提供可证明的通用目录同步方案。
- marker 存在后不会逐次重新散列全部资源，这与原版版本目录语义一致；资源内容变化必须提升
  `RESOURCE_VERSION`，不能继续复用 `v1`。
- 桌面 replay 能覆盖协议结构、短写、路径门禁和清理模型；真实磁盘满、I/O 中断、文件系统损坏、系统杀进程
  与 native 对实际字体/符号资源的加载仍需设备故障注入和公式样本测试。
