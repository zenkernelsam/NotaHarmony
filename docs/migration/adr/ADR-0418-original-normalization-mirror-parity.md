# ADR-0418: 原版大图归一化镜像一致性裁决

日期：2026-08-26

## 状态

Accepted

## 背景

Phase 444 修复显示链后，需要复核持久化大图归一化是否会丢失 EXIF 水平镜像。
Android 原版 `vuh.b()` 只在超过 3000px 时解码、降采样并重编码；其矩阵只调用
`postRotate(w34.l())`。原版 EXIF 助手 `w34.l()` 返回旋转度数，不返回镜像位。
共享显示解码器 `g3.java` 虽然识别 Orientation 2/4/5/7，但重编码 WebP 不保留
EXIF，后续显示无法再恢复该镜像。

Harmony `OriginalImageNormalizer` 当前同样只在需要降采样或四分之一旋转时重写
字节，使用同一旋转集合，不做水平镜像；未超过阈值时保留原始字节和 EXIF，由
显示 loader 应用完整方向集。

## 决策

1. 大图重编码路径保持与 Android `vuh.b()` 相同的 rotate-only 语义，不额外
   插入 `scale(-1, 1)`。
2. 小图路径继续保留原始字节；Orientation 2/4/5/7 的镜像由 Phase 444 显示链
   在运行时应用。
3. 该行为是移植一致性裁决：Android 原版对超阈值镜像图存在同源视觉限制；
   Harmony 不在本阶段擅自改变产品语义或伪造更高兼容性。
   该限制是原版同源限制，不是 Phase 444 的回归。

## 结果

鸿蒙与原版在两条路径上保持一致：小图保留 EXIF 并完整显示方向；超大图重编码
后都只固化旋转、丢失镜像。生产代码无需变更；新增静态 Replay 锁定该边界，
防止后续把显示修复误推广到持久化 normalization。
